# vica 개발일지: 내장 도구 정비와 0.1.12 준비

2026년 11월 11일의 vica 작업은 내장 도구의 실행 방식과 개발·검증 환경을 정비하는 데 집중했습니다. 여러 이미지를 첨부했을 때의 표시 방식도 시안으로 남겼고, 0.1.12 릴리스를 준비했습니다. 이번 일지에서는 최근 커밋 7개를 도구 실행, 개발 환경, 작업 규칙, 화면 설계로 묶어 정리해 보겠습니다. 커밋 메시지에서 확인할 수 있는 변경과 아직 확인하기 어려운 결과는 구분해서 적었습니다.

## 내장 도구의 실행 의존성 줄이기

채팅 영역에서는 내장 도구가 바깥 프로그램 없이 동작하도록 바꾸고, 도구가 다루는 범위를 넓혔습니다. 이번 작업에서 사용자 기능과 직접 맞닿아 있는 변화입니다. 외부 프로그램을 호출해야 했던 실행 방식에 손을 댔다는 점이 핵심입니다.

다만 어떤 도구가 추가됐는지, 기존 도구의 지원 범위가 어디까지 늘어났는지는 커밋 메시지만으로 알기 어렵습니다. 그래서 모든 실행 환경의 의존성이 사라졌다거나 특정 작업을 새로 지원한다고까지 설명하지는 않겠습니다. 현재 확인할 수 있는 변화는 **내장 도구의 자체 실행과 범위 확장**입니다. 실제 사용에서 달라지는 부분을 더 구체적으로 소개하려면 도구별 변경 내용을 함께 확인해야 합니다.

## 도구만 따로 컴파일하고 테스트하기

개발 환경에는 도구 파일만 따로 컴파일해 테스트하는 스크립트와 스킬을 마련했습니다. 도구를 수정했을 때 해당 파일을 대상으로 검증할 수 있도록 별도의 경로를 둔 셈입니다. 내장 도구의 기능 변경과 이를 확인하는 개발 작업이 같은 날 함께 이뤄졌습니다.

이 부분은 검증에 걸리는 시간보다 검증 대상을 분리했다는 점에 초점을 맞추고 싶습니다. 실행 시간이나 테스트 결과가 제공되지는 않았으므로, 빌드가 얼마나 빨라졌는지 또는 검증을 모두 통과했는지는 이번 기록에서 말하기 어렵습니다. 확인 가능한 성과는 도구 파일로 범위를 좁혀 컴파일하고 테스트할 수 있는 스크립트와 스킬이 생겼다는 것입니다.

## 탐색 규칙과 코드 지도 정리

저장소를 살펴보는 작업에는 “없다고 말하기 전에 전체를 찾는다”는 규칙을 문서로 남겼습니다. 일부 파일이나 익숙한 경로에서 찾지 못했다는 이유만으로 기능이나 구현이 없다고 판단하지 않도록, 부재를 말하기 전에 거쳐야 할 탐색 범위를 명시한 것입니다.

같은 날 코드 지도 캐시를 갱신했고, 내장 도구 기록도 정비했습니다. 이 변경들은 새 기능을 추가하는 작업과 구분할 필요가 있습니다. 저장소를 탐색할 때 참고하는 정보와 도구 관련 기록을 갱신한 유지보수 작업입니다. 탐색 규칙을 문서에 두는 일과 참고 자료를 손보는 일이 함께 진행됐다는 점에서 한 영역으로 묶었습니다.

## 여러 이미지 첨부의 표시 방식 검토

화면 설계에서는 여러 이미지 첨부를 겹친 묶음으로 보여 주는 시안을 추가했습니다. 여러 장을 첨부했을 때 이를 어떻게 표현할지 검토하는 디자인 작업입니다.

여기서 구분할 점은 **시안 추가가 곧 화면 구현 완료를 뜻하지는 않는다**는 것입니다. 이번 커밋으로 확인되는 범위는 디자인 문서에 표현 방안을 추가한 데까지입니다. 묶음을 누르면 어떻게 열리는지, 이미지 순서는 어떻게 표시하는지 같은 세부 동작은 주어진 기록에 없어 설명에서 제외했습니다.

## 0.1.12 릴리스 준비

마지막으로 0.1.12를 위한 릴리스 준비 작업이 있었습니다. 배포 완료 여부는 확인되지 않으므로 이번 일지에서도 준비 단계로 적어 둡니다.

이번 변경을 돌아보면 내장 도구의 실행 방식을 손보면서, 도구를 따로 검증할 수단과 저장소 탐색 규칙도 함께 마련했습니다. 이미지 첨부 화면은 시안 단계로, 버전 작업은 릴리스 준비 단계로 남아 있습니다. 기능 변경과 검증 환경 정비, 설계 검토가 각각 어디까지 진행됐는지 구분해 두는 것으로 이번 작업 기록을 마칩니다.
