# vica 개발일지: 앱·웹 조작과 시작 직후 요청 처리 보완

2026년 11월 16일의 최근 커밋 세 개는 컴퓨터 조작이 중간에 멈추거나, 시작 시점에 요청을 놓치는 문제를 다뤘습니다. 뒤에 있는 앱에 새 문서를 만드는 동작부터 웹 목록 탐색, 채팅을 켠 직후의 조작 요청까지 손봤습니다. 이번 기록은 커밋 메시지에서 확인할 수 있는 변경 범위를 바탕으로, 앱 조작·웹 탐색·요청 처리와 테스트로 나눠 정리했습니다.

## 앱 조작: 뒤에 있는 앱과 열린 메뉴 다루기

앱 조작에서는 대상 앱이 뒤에 있을 때 새 문서를 만드는 동작을 수정했습니다. 컴퓨터를 조작하다 보면 요청을 수행할 앱이 항상 맨 앞에 있지는 않습니다. 이번 변경은 그런 상태에서도 해당 앱에 새 문서를 만들도록 다듬은 작업입니다.

메뉴를 열어 둔 채 조작이 굳는 문제도 함께 다뤘습니다. 메뉴를 여는 것까지 성공했더라도 그 상태에서 멈추면 다음 작업으로 이어갈 수 없습니다. 그래서 이번 수정에서는 새 문서를 생성하는 동작과 함께, 메뉴가 열린 상태에서 진행이 막히는 부분을 보완했습니다.

두 변경을 묶는 기준은 앱의 현재 상태입니다. 대상 앱이 뒤에 있거나 메뉴가 이미 열려 있는 상황을 조작 과정에서 다룬 셈입니다. 다만 커밋 메시지만으로는 어떤 앱에서 문제가 발생했는지, 내부적으로 어떤 방식으로 수정했는지까지 확인할 수 없습니다. 모든 앱과 메뉴에서 같은 문제가 해결됐다고 범위를 넓혀 말하지는 않겠습니다.

## 웹 탐색: 목록 끝까지 읽기와 쪽 겹침 맞추기

웹에서는 목록을 키로 넘기면서 기간을 끝까지 읽도록 수정했습니다. 목록에 표시된 정보를 읽는 작업에는 현재 보이는 부분을 확인하는 과정뿐 아니라, 다음 부분으로 이동해 남은 내용을 확인하는 과정도 필요합니다. 이번 변경은 그 이동과 읽기를 이어 주는 부분에 해당합니다.

함께 다룬 내용은 쪽 사이의 겹침을 메시지로 맞추는 작업입니다. 목록을 넘겨 읽는 흐름에서는 어디까지 읽었고 다음 쪽이 어디서 이어지는지를 맞추는 일도 중요합니다. 커밋에 적힌 변경 범위는 이 겹침을 메시지로 맞췄다는 데까지이며, 메시지의 구체적인 형식이나 처리 규칙은 확인되지 않습니다.

웹 탐색 수정은 이렇게 두 부분으로 볼 수 있습니다. 키 입력으로 목록을 더 탐색해 기간을 끝까지 읽고, 쪽을 넘기는 과정에서 생기는 겹침을 맞췄습니다. 이를 웹 목록 전반의 누락이나 중복이 모두 사라졌다는 뜻으로 받아들이기보다는, 이번에 손본 읽기 흐름의 범위로 보는 편이 정확합니다.

## 요청 처리와 테스트: 켠 직후의 요청 놓치지 않기

채팅 쪽에서는 켠 직후 들어오는 컴퓨터 조작 요청을 버리지 않도록 수정했습니다. 앱이나 웹에서 실제 조작을 수행하기에 앞서, 요청 자체가 처리 흐름에 남아 있어야 합니다. 이번 변경은 특히 시작 직후라는 시점에 발생하던 요청 처리 문제를 다뤘습니다.

다만 요청을 보관했다가 실행하는지, 준비 상태를 기다리도록 바꿨는지는 커밋 메시지에 드러나지 않습니다. 확인할 수 있는 핵심은 켠 직후의 컴퓨터 조작 요청을 더 이상 버리지 않도록 했다는 점입니다. 구체적인 구현 방식까지 추측해 덧붙이지는 않겠습니다.

같은 영역에서 흔들리던 테스트를 고정하는 작업도 진행했습니다. 기능 수정과 함께 테스트의 불안정성을 다뤘다는 점을 이번 기록에 남깁니다. 어떤 조건에서 테스트가 흔들렸는지, 수정 후 얼마나 반복 검증했는지에 관한 정보는 없어 안정화 수준을 수치로 설명하기는 어렵습니다.

이번 세 커밋은 새 기능을 추가하기보다 기존 조작 흐름에서 막히던 지점을 손본 작업입니다. 앱의 위치와 메뉴 상태, 웹 목록의 이동과 겹침, 시작 직후의 요청 시점처럼 각각 다른 조건을 다뤘습니다. 현재 기록으로 확인되는 개선은 여기까지이며, 실제 사용 범위나 검증 결과는 추가 근거가 있을 때 구분해서 정리하겠습니다.
