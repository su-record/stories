# vica 개발일지: 실행 엔진 업데이트 상태와 vicad 교체 흐름 정리

2026년 11월 6일에는 vica의 실행 엔진 업데이트와 vicad 점검 흐름을 다듬었습니다. 설정 화면에서는 업데이트 확인 상태와 결과, 현재 버전을 볼 수 있도록 했고, 데몬 쪽에서는 업데이트 뒤 남아 있는 예전 vicad를 유휴 시간에 새것으로 교체하도록 손봤습니다. 요청을 보내 응답을 확인하는 스크립트와 교체 규칙을 설명하는 문서도 함께 추가했습니다.

## 설정 화면에서 업데이트 상태 확인하기

실행 엔진 업데이트 버튼에 ‘확인 중’ 표시와 결과 알림을 더하고, 현재 버전도 보여 주도록 했습니다. 버튼을 누른 뒤 어떤 단계에 있는지, 확인 결과가 무엇인지, 현재 버전은 무엇인지를 설정 화면에서 살펴볼 수 있게 한 작업입니다.

업데이트 기능에서는 실행 요청만큼이나 상태를 전달하는 방식도 중요합니다. 확인 중이라는 표시와 결과 알림은 서로 다른 시점의 정보를 맡습니다. 전자는 작업을 진행하고 있다는 사실을 알려 주고, 후자는 확인이 끝난 뒤 결과를 전달합니다. 현재 버전 표시는 그 결과를 살펴볼 때 기준이 됩니다.

다만 이번 변경만으로 모든 업데이트 상황을 화면에서 설명한다고 말하기는 어렵습니다. 이번에 추가한 범위는 업데이트 버튼의 확인 상태, 결과 알림, 현재 버전 표시입니다. 사용자에게 보이는 정보가 구체적으로 늘어났다는 점에 초점을 맞췄습니다.

## 업데이트 뒤 남은 vicad 교체하기

데몬 영역에서는 업데이트 이후에도 남아 있는 예전 vicad를 쉬는 동안 새것으로 바꾸도록 수정했습니다. 새 버전을 받아 두는 단계와 남아 있는 예전 vicad를 교체하는 단계 사이를 다룬 변경입니다. 교체 시점은 유휴 시간으로 잡았습니다.

여기서는 ‘업데이트했다’는 말만으로는 드러나지 않는 교체 조건이 핵심입니다. 설정 화면에 버전과 결과를 보여 주는 일과 별개로, 데몬 쪽에서도 예전 vicad가 남은 경우를 처리해야 합니다. 이번 수정은 그 경우에 새것으로 바꾸는 동작을 보완합니다. 구체적인 교체 조건과 점검 방법은 문서에도 남겨, 이후 동작을 확인할 때 참고할 수 있도록 했습니다.

vicad가 모르는 요청을 받았을 때도 응답하도록 고쳤습니다. 지원하지 않는 요청을 정상 처리한다는 뜻은 아닙니다. 알 수 없는 요청에도 답을 보내도록 응답 동작을 보완한 것입니다. 교체 처리와 함께 요청에 대한 응답 여부도 이번 데몬 작업의 범위에 포함했습니다.

## 요청 한 번으로 확인하는 도구와 문서

점검용으로는 vicad에 요청 하나를 보내고 답을 확인하는 스크립트를 추가했습니다. 실행 중인 vicad와 요청·응답을 주고받을 수 있는지 살펴보는 도구입니다. 복잡한 사용 흐름을 따라가기 전에, 요청에 답이 오는지 직접 확인할 수 있는 수단을 마련했습니다.

이 스크립트 하나로 업데이트와 교체 과정 전체를 검증한다고 보기는 어렵습니다. 역할은 요청 하나와 그 응답을 확인하는 데 있습니다. 교체 규칙과 점검 방법을 정리한 문서는 그보다 넓은 동작 맥락을 참고하는 자료로 두었습니다. 직접 실행해 보는 도구와 조건을 읽어 볼 수 있는 문서를 함께 갖춘 셈입니다.

이번 네 커밋은 설정 화면, 데몬, 점검 도구와 문서에 걸쳐 있습니다. 화면에서는 업데이트 상태를 확인하고, 데몬은 남아 있는 예전 vicad를 유휴 시간에 교체하며, 개발할 때는 스크립트와 문서로 동작을 살펴볼 수 있도록 정리했습니다. 실제 실행 결과나 테스트 수치는 주어진 커밋 정보에 없어 덧붙이지 않았습니다. 이번 기록은 구현하고 남긴 범위까지 담았습니다.
