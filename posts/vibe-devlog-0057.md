# vibe 개발일지 #57 - AI 교차 감사 기반 P1 수습 및 Wave A~D 품질 개선 (11개 커밋)

**작업 기간**: 2026-07-28 ~ 2026-07-29

안녕하세요, vibe 프로젝트를 개발하고 있는 Su입니다.

vibe는 **"Easy vibe coding + Minimum quality guaranteed"**라는 슬로건으로 만든 AI 코딩 하네스 도구입니다. 에이전트의 성능은 `Agent = Model + Harness` 공식에 의해 결정된다고 믿기에, 모델이 최선의 코드를 짤 수 있도록 하네스(안전망)를 만드는 데 집중하고 있습니다.

이번 이틀 동안은 AI 교차 감사를 도입해 코드베이스 전체를 훑고, 발견된 치명적 결함(P1)을 수습한 뒤 Wave A부터 Wave D까지 이어지는 체계적인 품질 개선 작업을 완수했습니다.

## 💡 작업 하이라이트

### "AI 교차 감사(Cross-Verification)가 찾아낸 맹점"

이번 작업에서 가장 인상 깊었던 순간은 **Claude와 Codex에게 서로 다른 각도에서 프로젝트 감사를 맡겼을 때**였습니다.

개발자가 혼자 코드를 보다 보면 "당연히 잘 돌아가겠지" 하고 넘어가기 쉬운 맹점들이 있습니다. Claude와 Codex 독립 감사 결과, 저희 파이프라인에 P1 수준의 긴급 결함 3가지가 숨어있음을 확인했습니다.

```
[기존 하네스]
AI 모델 -> 실행 -> (성공한 것 같지만 병렬 실행 race condition & engines 거짓 선언) -> 미세한 누수 발생

[개선된 교차 감사 하네스]
Claude 감사 ──┐
             ├─> 교차 검증(Cross Check) ──> P1 3건 적발 ──> Wave A~D 파이프라인 자동 태스크 전환
Codex 감사  ──┘
```

특히 **Stop 시퀀스가 병렬로 실행되면서 상태가 꼬이던 문제**와 **`engines` 명세가 실제 런타임 환경과 달랐던 문제**는 사용자 환경에서 불규칙한 에러를 야기할 수 있는 시한폭탄이었습니다.

이를 확인하자마자 P1 이슈를 즉시 수습하고, 재발 방지를 위해 **Wave A(배포계약) -> Wave B(타입/훅) -> Wave C(테스트 86건) -> Wave D(의존성 계획)**로 이어지는 구조적 개편 체계를 밟았습니다.

`vibe` 하네스가 스스로의 품질도 AI 감사를 통해 증명하고 보장하는 선순환 구조를 만든 셈입니다.

Claude와 Codex를 교차 검증 도구로 활용하고, 거기서 도출된 태스크를 Wave A~D 흐름으로 하나씩 깔끔하게 해결해 나가니 프로젝트의 단단함이 완전히 달라진 느낌입니다.

npm 패키지 `@su-record/vibe`는 언제나 **"최소한의 품질을 자동으로 보장하는 에이전트 환경"**을 향해 달려갑니다. 다음 업데이트도 기대해 주세요!
