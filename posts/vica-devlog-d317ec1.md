# vica 개발일지: 실행 경로에 맥락을 더하고, 전송 전에 확인하기

2026년 11월 26일의 vica 변경은 데스크톱에서 작업을 맡길 때 전달하는 정보와 대화창에서 보내는 민감정보를 다룹니다. CLI에는 첨부 문서의 글 사본을 함께 주고, 비카 자체 에이전트는 `.claude` 아래의 규칙 문서도 읽도록 했습니다. 대화창에 붙인 API 키는 전송 전에 확인하고 가려서 보낼 수 있게 했습니다. 지식 문서에는 실무 습관 가이드와 대조하며 더한 세 가지를 기록했습니다.

## 작업을 맡길 때 문서와 규칙을 함께 전달하기

데스크톱에서 CLI에 작업을 맡기는 흐름에 첨부 문서의 글 사본을 함께 전달하는 기능을 넣었습니다. 사용자가 붙인 문서의 내용을 CLI 쪽에도 넘기는 변경입니다. 첨부 문서가 있는 작업에서는 요청 문장뿐 아니라 문서 본문도 작업 맥락이 되므로, 실행을 맡기는 경로에서 그 내용을 전달하는 데 의미가 있습니다.

이번 변경에서 확인할 수 있는 범위는 ‘글 사본을 함께 준다’는 점까지입니다. 지원하는 문서 형식이나 표·이미지를 다루는 방식, 원본의 구조를 얼마나 보존하는지는 커밋 요약만으로 알 수 없습니다. 첨부 파일의 모든 정보를 그대로 전달한다고 넓혀 설명하지는 않겠습니다.

비카 자체 에이전트가 읽는 규칙 파일의 범위도 넓혔습니다. 이제 `.claude/rules`와 `.claude/CLAUDE.md`도 읽습니다. 해당 위치에 프로젝트 규칙을 두고 있다면, 자체 에이전트가 그 내용을 읽을 수 있는 경로가 생긴 셈입니다.

이 두 변경은 작업을 수행하는 쪽에 필요한 맥락을 전달한다는 점에서 묶을 수 있습니다. 다만 대상은 다릅니다. CLI 위임에서는 첨부 문서의 내용을 함께 넘기고, 자체 에이전트에서는 프로젝트 규칙을 읽는 범위를 확장했습니다. 파일을 읽는 것과 실제 작업에서 규칙을 정확히 따르는 것은 별개이므로, 이번 기록에서는 읽기 지원의 확장까지를 변화로 짚겠습니다.

## API 키는 보내기 전에 확인하기

대화창에 붙인 API 키는 전송 전에 묻고, 가려서 보낼 수 있도록 했습니다. 작업 내용을 설명하면서 키를 함께 붙여 넣은 경우, 그대로 전송하기 전에 사용자가 다시 판단할 수 있는 단계가 추가됐습니다.

핵심은 확인 시점과 선택권입니다. 전송 전에 API 키를 확인하고, 사용자가 가린 형태로 보낼 수 있습니다. 대화창에 입력한 내용을 곧바로 보내는 흐름에 민감정보를 살펴볼 기회를 둔 것입니다.

다만 이를 모든 비밀정보의 유출을 막는 기능이라고 소개할 수는 없습니다. 이번 커밋 요약에는 감지하는 키의 종류나 판별 기준까지 담겨 있지 않습니다. 확인된 변화는 대화창에 붙인 API 키에 대해 전송 전 확인과 가림 전송을 지원한다는 점입니다. 사용자의 검토를 돕는 기능으로 범위를 분명히 두겠습니다.

## 실무 가이드와 대조한 내용을 지식 문서에 남기기

지식 문서에는 실무 습관 가이드와 대조하며 더한 세 가지를 기록했습니다. 기능 변경과 함께, 가이드를 참고해 보완한 내용을 문서에도 남긴 작업입니다.

제공된 커밋 요약에는 세 항목의 구체적인 내용이 없습니다. 어떤 습관을 추가했는지, 개발 과정에 어떤 영향을 주었는지는 여기서 추측해 채우지 않겠습니다. 이번 개발일지에는 대조를 통해 더한 내용 세 가지를 기록했다는 사실까지만 담습니다.

이번 변경을 살펴볼 때도 영역별로 확인할 지점이 나뉩니다. CLI 위임에서는 첨부 문서의 글 사본이 전달되는지, 자체 에이전트에서는 추가된 경로의 규칙을 읽는지, 대화창에서는 API 키를 보내기 전에 확인하고 가릴 수 있는지가 핵심입니다. 실제 동작의 세부 범위와 검증 결과는 커밋 요약에 없는 만큼, 구현과 테스트를 확인한 뒤 별도로 다룰 부분으로 남겨둡니다.
