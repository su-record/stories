# vica 개발일지: 채팅 모델 선택과 업데이트 영수증 처리

2026년 11월 8~9일, vica에서는 채팅 답변에 사용할 모델을 결정 모델이 선택하도록 바꾸고, 결정 호출에 걸린 시간을 기록했습니다. 업데이트 쪽에서는 영수증 처리가 업데이트를 막지 않도록 수정했습니다. 최근 커밋 세 개를 바탕으로, 모델 선택과 관측, 업데이트 흐름이라는 영역으로 나눠 정리해 보겠습니다.

## 채팅 답변 모델 선택을 결정 모델에 맡겼습니다

채팅 답변을 생성할 때 어떤 모델을 사용할지 결정 모델이 고르도록 변경했습니다. 이번 변경에서 핵심은 답변 내용보다 그 답변을 만들 모델의 선택을 누가 맡느냐에 있습니다. 결정 모델이 채팅 답변용 모델 선택까지 담당하게 된 셈입니다.

다만 커밋 메시지만으로 선택 기준까지 설명할 수는 없습니다. 질문의 난이도에 따라 모델을 나누는지, 비용이나 응답 속도를 고려하는지, 어떤 모델이 후보인지는 확인되지 않습니다. 따라서 이번 작업을 곧바로 ‘비용 최적화’나 ‘답변 품질 개선’이라고 소개하기보다는, 모델 선택을 결정 모델에 맡기는 구조 변경으로 보는 것이 정확합니다.

이 구조를 평가하려면 실제로 어떤 모델이 선택되는지, 그 선택이 답변에 어떤 영향을 주는지 살펴봐야 합니다. 선택을 맡기는 기능이 들어갔다는 사실과 선택이 잘 작동한다는 평가는 구분해 두려고 합니다.

## 결정 호출에 걸리는 시간을 기록했습니다

모델 선택과 맞닿은 관측 영역에서는 결정 호출의 소요 시간을 기록했습니다. 채팅 답변을 만드는 과정에서 결정 호출에 시간이 얼마나 드는지 확인할 수 있도록 기록을 추가한 변경입니다.

여기서 기록 대상은 결정 호출입니다. 이 시간이 곧 사용자에게 답변이 도착하기까지의 전체 시간을 뜻하지는 않습니다. 이후 성능을 살펴볼 때도 결정에 걸린 시간과 답변 생성에 걸린 시간을 혼동하지 않는 것이 중요합니다.

시간을 기록하기 시작했다고 해서 호출이 빨라졌다고 말할 수는 없습니다. 제공된 커밋 메시지에는 측정값이나 전후 비교 결과가 제시되어 있지 않습니다. 현재 확인할 수 있는 진전은 속도 개선 자체보다, 결정 호출의 시간을 따로 살펴볼 근거를 남겼다는 점입니다.

## 업데이트가 영수증 처리에 막히지 않도록 했습니다

업데이트 영역에서는 업데이트 영수증이 업데이트를 가로막지 않도록 수정했습니다. 커밋 메시지가 밝히는 수정 방향은 분명합니다. 영수증 처리 때문에 업데이트 진행이 막히는 상황을 허용하지 않겠다는 것입니다.

다만 여기서 말하는 영수증의 구체적인 형태와 처리 방식은 메시지에 드러나지 않습니다. 어떤 조건에서 문제가 발생했는지, 실패한 영수증을 다시 처리하는지, 별도로 보관하는지까지는 설명하기 어렵습니다. 비동기 처리나 재시도를 도입했다고 단정하지 않고, 업데이트를 막지 않도록 수정했다는 범위에서 정리하겠습니다.

같은 날의 다른 커밋에서도 영수증 수정이 함께 언급됩니다. 이를 별개의 기능으로 부풀리기보다는 하나의 업데이트 처리 영역으로 묶었습니다. 사용자에게 중요한 결과도 영수증 관련 커밋의 개수보다는, 해당 처리가 업데이트를 방해하지 않도록 바뀌었다는 점에 있습니다.

## 이번 변경에서 확인한 범위

이번 세 커밋은 채팅 답변 모델을 선택하는 역할, 결정 호출 시간을 기록하는 관측, 업데이트를 막는 영수증 처리의 수정으로 이어집니다. 모델 선택 기준과 실제 측정 결과, 영수증 수정의 세부 구현은 커밋 메시지만으로 확인할 수 없습니다. 이번 일지에는 변경된 책임과 처리 방향까지 담고, 품질이나 성능이 얼마나 좋아졌는지는 판단을 남겨 두겠습니다.
