# vica 개발일지: 중계 구독 결제와 키 전달, 저장 코드 정리

2026년 10월 30일에는 vica의 중계 구독을 Paddle로 판매하고, 결제 후 받은 vica 구독 키로 사용하는 흐름을 추가했습니다. 구독 키를 결제 이메일로 보내는 기능도 함께 넣었습니다. 코드 내부에서는 큰 파일을 맡은 일에 따라 나누고, 안전 저장 코드를 한곳으로 모았습니다. 이번 작업은 구독을 구매해 사용하는 흐름과, 그 코드를 관리하는 구조로 나눠 정리해 보겠습니다.

## 중계 구독: 결제부터 구독 키 전달까지

중계 구독의 결제 수단으로 Paddle을 연결했습니다. 사용자는 Paddle로 구독을 결제하고, 결제 후 받는 vica 구독 키로 중계 구독을 사용하게 됩니다. 이번 변경에서 사용자에게 직접 보이는 핵심은 구독을 구매하는 단계와 실제 사용할 때 필요한 키가 이어졌다는 점입니다.

여기서 Paddle은 구독을 판매하고 결제하는 쪽을 맡고, vica 구독 키는 구매한 구독을 사용하는 데 쓰입니다. 결제 수단과 사용 수단의 역할이 구분되는 셈입니다. 다만 이번 커밋 정보에는 구독 키를 어느 화면에 입력하는지, 사용 과정에서 어떤 안내를 보여 주는지까지는 나와 있지 않습니다. 그래서 화면 구성이나 구체적인 사용 절차를 덧붙이기보다는, 결제 후 받은 키로 사용한다는 범위까지 정리하려고 합니다.

키를 사용자에게 전달하는 경로도 추가했습니다. 결제가 이루어지면 구독 키를 결제 이메일로 보냅니다. 구독 키가 있어야 사용할 수 있는 흐름인 만큼, 구매한 사람이 그 키를 받을 경로까지 함께 마련한 작업입니다. 사용자가 키를 확인할 곳은 결제에 사용한 이메일이라는 점도 분명해졌습니다.

다만 이메일 발송 기능을 넣었다는 사실과 모든 전달 상황을 처리한다는 것은 구분해야 합니다. 제공된 변경 정보만으로는 메일이 도착하지 않았을 때의 재발송 방식이나, 결제 이메일을 잘못 입력했을 때의 처리까지 확인할 수 없습니다. 이번 기록에서는 결제 이메일로 구독 키를 보내는 기능이 추가됐다는 점까지만 다루겠습니다.

## 코드 구조: 역할별 파일 분리와 안전 저장 코드 통합

구독 기능을 추가하는 작업과 함께 내부 구조도 정리했습니다. 큰 파일을 맡은 일별로 나누고, 안전 저장 코드는 하나로 모았습니다. 두 변경 모두 코드의 위치와 책임을 정돈하는 작업이지만, 정리한 방향에는 차이가 있습니다.

파일 분리는 한 파일에 모여 있던 코드를 역할에 따라 나누는 쪽입니다. 파일을 볼 때 어떤 일을 맡는지 구분할 수 있도록 구조를 바꾸는 작업으로 볼 수 있습니다. 다만 어떤 파일을 몇 개로 나눴는지는 제공된 정보에 없으므로, 특정 모듈 구성을 소개하거나 파일 크기가 얼마나 줄었는지 수치로 설명하지는 않겠습니다.

안전 저장 코드는 공통으로 다룰 부분을 한곳에 모았습니다. 저장과 관련한 코드를 수정하거나 확인할 때 살펴볼 지점을 모으는 방향의 변경입니다. 여기서 ‘안전 저장’이라는 이름만으로 구체적인 저장 방식이나 오류 복구 범위까지 추정할 수는 없습니다. 이번 리팩터링의 확인 가능한 내용은 해당 코드를 하나로 통합했다는 것입니다.

## 이번 변경에서 달라진 점

이번 작업으로 vica에는 Paddle 결제, 구독 키를 통한 사용, 결제 이메일로의 키 전달이 연결됐습니다. 내부적으로는 역할이 다른 코드를 파일로 나누고, 함께 관리할 안전 저장 코드를 모았습니다.

결제와 키 전달은 사용자가 구독을 시작할 때 접하는 변화이고, 파일 분리와 저장 코드 통합은 이후 코드를 다루는 쪽의 변화입니다. 실제 동작 검증 결과나 운영 중 확인한 문제는 이번 자료에 포함돼 있지 않습니다. 이번 개발일지는 기능이 추가된 범위와 구조가 바뀐 지점까지 기록해 둡니다.
