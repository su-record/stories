# vica 개발일지: 에이전트의 역할 배정과 화면 확인 범위 정리

2026년 10월 30일의 vica 데스크톱 변경은 에이전트에게 어떤 일을 맡길지에 초점을 맞추고 있습니다. 최근 네 개 커밋에서는 조사·UI·대량 읽기의 담당을 정리하고, Chat 역할의 선택지를 넓혔습니다. 화면 확인에는 Playwright 유무를 조건으로 두었고, 회사가 하나뿐인 구성에서도 리뷰 담당을 정하도록 수정했습니다.

이번 내용을 기능별로 묶으면 작업 담당과 Chat 선택, 화면 확인, 단일 회사 구성의 리뷰로 나눌 수 있습니다. 다만 커밋 메시지만으로 확인할 수 있는 범위가 정해져 있어, 실제 실행 결과나 성능 변화까지 이야기하지는 않겠습니다.

## 작업 성격에 맞춘 담당과 Chat 선택지

조사는 Muse와 Grok이 함께 맡고, UI 작업과 대량 읽기는 Muse가 맡도록 바뀌었습니다. 조사에는 두 에이전트를 배정하되, UI와 많은 내용을 읽는 작업에는 Muse를 담당으로 두는 구분입니다.

여기서 ‘함께 조사한다’는 범위를 넘겨 해석하지 않는 것이 중요합니다. 두 에이전트가 병렬로 실행되는지, 서로의 결과를 검토하는지, 최종 결과를 어떻게 합치는지는 이번 커밋 메시지에 드러나지 않습니다. 이번 일지에서 확실히 짚을 수 있는 변화는 조사 담당에 Muse와 Grok이 함께 포함됐다는 점입니다.

Chat 역할에서는 Muse Code를 선택할 수 있게 됐습니다. 앞의 변경이 작업 종류에 따라 담당을 정하는 내용이라면, 이 변경은 Chat에 배정할 수 있는 선택지를 추가한 내용입니다. Muse Code가 기본값이 됐다거나 기존 선택지를 대체했다는 뜻은 아닙니다. Chat 역할에 Muse Code를 쓰고 싶은 경우, 이제 선택할 수 있다는 범위로 이해하시면 됩니다.

이 두 변경을 함께 보면, 작업별 담당과 사용자가 고를 수 있는 역할 선택지가 각각 정리됐습니다. 조사·UI·대량 읽기의 배정과 Chat 설정은 구분해서 살펴보는 편이 변경 내용을 이해하기 쉽습니다.

## Playwright가 있으면 모든 에이전트가 화면 확인

화면 확인은 Playwright가 있는 환경에서 모든 에이전트가 맡을 수 있도록 범위를 넓혔습니다. 이번 변경에서 핵심 조건은 **Playwright가 있어야 한다**는 점입니다. 환경과 관계없이 모든 에이전트가 화면을 확인할 수 있게 된 것은 아닙니다.

UI 작업을 Muse가 맡는다는 변경과 화면 확인 범위가 넓어졌다는 변경도 따로 볼 필요가 있습니다. UI 담당은 Muse로 정했지만, 화면 확인은 Playwright가 있으면 다른 에이전트도 맡을 수 있습니다. UI 작업의 담당과 화면을 확인할 수 있는 에이전트의 범위가 서로 같지는 않은 셈입니다.

다만 화면 확인을 맡을 수 있다는 것과 매 작업에서 자동으로 화면을 확인한다는 것은 별개의 이야기입니다. 실행 시점이나 확인 방식은 커밋 메시지만으로 알 수 없으므로, 자동 검증까지 추가됐다고 설명하기는 어렵습니다.

## 회사가 하나뿐인 구성의 리뷰 담당 수정

회사가 하나뿐일 때는 그 회사가 리뷰를 맡도록 수정했습니다. 단일 회사 구성에서 리뷰 담당을 어떻게 정할지 명확히 한 변경입니다.

여러 회사가 있는 경우의 배정 규칙까지 바뀌었다고 볼 근거는 없습니다. 이번 수정은 회사가 하나뿐인 경우에 해당하며, 그때 유일한 회사에 리뷰를 맡긴다는 내용입니다. 구성의 선택 폭이 좁은 경우에도 리뷰 역할의 담당을 정해 둔 셈입니다.

이번 네 커밋을 확인할 때는 조건을 함께 보는 것이 좋겠습니다. Chat에서는 Muse Code를 선택할 수 있는지, Playwright가 있는 환경에서는 각 에이전트가 화면 확인을 맡을 수 있는지, 회사가 하나인 구성에서는 해당 회사에 리뷰가 배정되는지가 구체적인 확인 지점입니다. 실제 동작을 검증했다는 기록은 제공되지 않았으므로, 이번 일지는 역할 배정과 선택 범위가 어떻게 달라졌는지까지 담았습니다.
