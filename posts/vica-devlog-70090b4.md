# vica 개발일지: 작업 스타일 설정부터 실행까지

2026년 11월 9일의 최근 커밋 11개는 ‘작업 스타일’을 중심으로 이어졌습니다. 공통 데이터 계약을 마련하고, 설정 화면과 템플릿을 거쳐 저장한 스타일을 실행하는 경로까지 연결했습니다. 이번 글은 커밋 메시지를 바탕으로 정리했습니다. 코드와 테스트 결과를 직접 확인한 기록은 아니므로, 구현 내용과 검증된 동작을 구분해서 읽어주시면 좋겠습니다.

## 작업 스타일의 공통 구조와 선택 화면

작업 스타일의 기반으로 공유 데이터 계약을 추가하고, 여기에 템플릿 목록과 카탈로그를 포함했습니다. 설정 화면과 실행 경로에서 함께 다룰 데이터의 틀을 잡는 작업입니다. 설계 문서에도 작업 스타일을 설명해, 기능이 사용하는 개념을 문서로 남겼습니다.

화면 쪽에서는 작업 스타일 설정과 단계별 모델 선택을 목업으로 구체화했습니다. 이어 설정, 템플릿, 작성창에서 스타일을 선택하는 기능을 구현했습니다. 다만 단계별 모델 선택은 커밋 메시지에서 목업으로 언급된 만큼, 실제 실행에 적용되는 범위까지 완성됐다고 단정하지 않겠습니다.

이번 묶음에서는 데이터 구조와 사용자가 만지는 화면을 함께 다뤘다는 점이 눈에 띕니다. 작업 스타일을 어떤 형태로 저장할지 정하는 작업에서 출발해, 사용자가 이를 고를 수 있는 지점까지 범위를 넓혔습니다.

## 저장한 스타일을 실행하는 경로와 우선순위

실행 영역에서는 저장한 작업 스타일을 슬래시 명령, 작성창, 프로젝트 기본값, ‘Vica 자동’ 경로로 사용할 수 있도록 작업했습니다. 같은 기능이라도 사용자가 어디서 선택하느냐에 따라 진입점이 달라지므로, 실행 경로를 함께 정리한 부분입니다.

선택의 우선순위도 다뤘습니다. 명시적으로 고른 ‘자동’이 기본값보다 우선하도록 했습니다. 자동 선택을 직접 요청한 경우와 별도 선택 없이 기본값을 따르는 경우를 구분한 셈입니다. 기본값이 있더라도 사용자의 이번 선택을 덮어쓰지 않도록 하는 규칙으로 읽힙니다.

작업 스타일의 단계 초안을 만들 때는 모든 도구를 끄도록 했습니다. 여기서 확인할 수 있는 범위는 ‘초안 작성 시 도구를 사용하지 않는다’는 점입니다. 이후 단계의 도구 사용 정책까지 같은 규칙이라고 확대해서 해석하지는 않았습니다.

## 단계별 역할과 사용자의 차례

단계 초안을 작성하는 쪽에는 각 역할이 무엇을 하는지 알려주도록 했습니다. 역할 이름만 전달하는 데서 그치지 않고, 역할별 책임을 초안 작성에 반영하려는 변경입니다.

사용자의 차례는 별도 상태로 표시하도록 바꿨습니다. 작업 흐름 안에서 사용자가 참여하는 구간을 독립적으로 표현한 부분입니다. 이 변경이 화면에서 어떤 모습으로 드러나는지, 어떤 조건에서 다음 상태로 넘어가는지는 메시지만으로 확인하기 어렵습니다. 이번 기록에서는 역할 설명과 사용자 차례의 상태 표현을 보강했다는 데까지 정리하겠습니다.

## 입력·복사 처리와 권한 기록

작업 스타일 밖에서도 처리 순서를 손봤습니다. 영역 복사에서는 어느 하나라도 저장하기 전에 모든 복사본을 먼저 그리도록 변경했습니다. 태블릿에서 텍스트를 전송하는 작업도 같은 커밋에 포함됐습니다. 구체적인 재현 조건이나 수정 전 증상은 제공된 기록에 없어 덧붙이지 않았습니다.

대화 권한 처리에서는 프롬프트를 내보내기 전에 대화 권한 부여 기록을 남기도록 순서를 정리했습니다. 권한 기록과 프롬프트 전달 사이의 선후 관계를 명시한 변경입니다. 이 사실만으로 권한 처리 전반의 안전성이 검증됐다고 말할 수는 없습니다.

마지막으로 작업 스타일 병합과 0.1.8 릴리스 경로를 기록했습니다. 이번 커밋 묶음은 공통 구조, 선택 화면, 실행 규칙, 설계·병합 문서까지 이어집니다. 다만 릴리스 경로를 기록한 것과 실제 배포 완료는 구분해야 합니다. 현재 자료로 확인되는 마무리는 작업 스타일을 병합하고 다음 릴리스로 이어지는 경로를 문서에 남긴 단계입니다.
