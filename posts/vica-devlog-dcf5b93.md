# 규칙 준수 실험을 다시 설계하며 발견한 진짜 문제

이번 `vica` 작업은 규칙을 더 잘 설명하면 실제로도 더 잘 지켜지는지 확인하는 실험에서 시작했습니다. 예상했던 가설은 시원하게 맞지 않았지만, 실패한 실험을 다시 들여다보는 과정에서 도구의 검증 시점에 숨어 있던 결함을 찾고 수정할 수 있었습니다.

## 규칙에 이유를 붙이면 더 잘 지켜질까?

먼저 같은 규칙을 제시하되, 한쪽에는 규칙만 전달하고 다른 쪽에는 그 규칙이 필요한 이유까지 함께 제공하는 방식으로 비교했습니다. 직관적으로는 이유를 이해한 쪽이 규칙을 더 안정적으로 따를 것 같았습니다. 하지만 현재 실험 조건에서는 이유를 덧붙인다고 해서 준수율이 유의미하게 좋아지지 않았습니다.

이 결과를 곧바로 “이유 설명은 효과가 없다”라고 해석하기는 어려웠습니다. 표본과 평가 방식, 대화 흐름, 규칙이 실제로 적용되는 시점 등 여러 요소가 결과에 섞여 있었기 때문입니다. 특히 무엇을 성공으로 볼지와 언제 위반 여부를 확인할지가 충분히 분리되지 않아, 원래 질문에 정확히 답하기 어려운 구조였습니다.

그래서 문서를 단순히 결과 기록으로 마무리하지 않고 실험 자체를 다시 설계했습니다. 비교 조건을 더 명확하게 나누고, 관찰하려는 효과와 도구 동작에서 생기는 변수를 구분하려고 했습니다. 재설계 후에도 아직 가설에 대한 확정적인 답은 얻지 못했습니다. 다만 “답을 못 찾았다”는 사실보다, 왜 답할 수 없었는지를 구체적으로 설명할 수 있게 된 점은 의미가 있었습니다.

## 실험을 흐리던 검증 시점 수정

분석 과정에서 더 직접적인 문제가 드러났습니다. 평가 기준이 등록될 때 확인해야 할 값을 즉시 검사하지 않고, 무려 다섯 턴 뒤에 확인하고 있었습니다. 이 때문에 기준 등록 당시의 상태가 아니라 이후 대화에서 달라진 상태를 기준으로 판정할 가능성이 있었습니다.

이 문제는 단순한 지연이라기보다 측정의 의미를 바꾸는 결함이었습니다. 실험자는 등록 시점의 값을 평가한다고 생각하지만, 실제 도구는 한참 뒤의 값을 보고 있었기 때문입니다. 이런 상태에서는 규칙을 지켰는지뿐 아니라, 이유를 제공한 효과가 있었는지도 신뢰하기 어렵습니다.

이번 수정에서는 기준이 등록되는 순간 해당 값을 검사하도록 동작을 옮겼습니다. 이제 평가 대상과 평가 시점이 일치하므로, 이후 턴의 변화가 초기 판정에 섞이지 않습니다. 실험 문서에서 발견한 의문이 실제 구현 결함으로 이어졌고, 그 결함을 다시 도구 수준에서 바로잡은 셈입니다.

## 이번 작업에서 얻은 것

가설은 아직 입증되지 않았습니다. 이유를 함께 설명하는 것이 언제나 규칙 준수를 높여 준다고 말할 수도 없습니다. 그래도 이번에는 성급한 결론 대신 실험 설계의 한계를 기록했고, 관측을 왜곡하던 실제 결함까지 제거했습니다.

좋은 실험은 원하는 답을 주는 실험이 아니라, 무엇을 아직 모르는지 드러내는 실험에 더 가깝다는 생각이 듭니다. 다음 단계에서는 수정된 검증 시점을 바탕으로 실험을 다시 수행하고, 규칙의 종류와 이유의 구체성 같은 조건도 분리해 살펴볼 예정입니다.
