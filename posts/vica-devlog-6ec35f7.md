# vica 개발일지: 호출 표시, 구독 키 상태, 쓰기 작업 분리

2026년 11월 6일의 vica 커밋 네 개에서는 채팅의 호출 표시와 쓰기 작업 실행 방식, 데스크톱 화면 구성, 구독 키 상태 표시를 손봤습니다. 화면에서 사용자가 확인할 정보와 프로젝트 작업을 실행하는 규칙에 함께 변화가 있었습니다. 이번 글에서는 커밋 메시지에서 확인할 수 있는 변경을 영역별로 묶어 정리했습니다.

## 채팅: 호출은 배지로, 두 번째 쓰기는 워크트리로

채팅에서는 모델·명령·스킬 호출을 배지로 보여 주도록 했습니다. 호출 정보를 구분해 표시하는 방식이 생긴 셈입니다. 툴팁도 함께 다듬었습니다. 다만 커밋 요약만으로는 각 배지의 모양이나 툴팁에 담긴 문구까지 알 수 없어, 여기서는 표시 방식이 바뀌었다는 범위까지만 말씀드리겠습니다.

실행 쪽에서는 같은 프로젝트의 두 번째 쓰기 작업을 워크트리에서 돌리도록 했습니다. 이번 변경에서 중요한 조건은 ‘같은 프로젝트’와 ‘두 번째 쓰기 작업’입니다. 모든 작업의 실행 위치를 바꿨다고 읽기보다는, 해당 조건의 쓰기 작업에 별도 작업 공간을 쓰도록 했다고 보는 편이 정확합니다.

이 변경에는 관련 노트와 결정, 실행 한도, CLI 점검도 포함됐습니다. 실행 경로를 바꾸면서 그 주변의 기록과 점검 항목도 함께 다룬 점이 눈에 띕니다. 다만 구체적인 한도 값이나 CLI 점검 결과는 제공된 요약에 없습니다. 따라서 이번 기록만으로 쓰기 작업 사이의 충돌이 모두 해결됐다거나, 모든 실행 환경에서 검증을 마쳤다고 말할 수는 없습니다.

채팅 영역의 두 변화는 서로 다른 층위를 다룹니다. 배지는 호출 정보를 화면에 어떻게 보여 줄지에 관한 변경이고, 워크트리는 쓰기 작업을 어디서 실행할지에 관한 변경입니다. 사용자에게 보이는 표시와 실제 작업 공간을 나눠 살펴보면 이번 수정의 범위가 더 분명해집니다.

## 데스크톱과 설정: 화면 구성과 이동 흐름 정리

데스크톱 화면은 승인된 단순 UI 시안을 기준으로 다시 구성했습니다. 이번 커밋에서 확인되는 기준은 ‘승인된 시안’입니다. 단순한 구성을 화면에 반영했다는 점은 알 수 있지만, 어떤 요소를 없애거나 옮겼는지는 요약에 드러나지 않습니다. 화면이 얼마나 편해졌는지는 실제 구성과 사용 흐름을 확인한 뒤 평가할 부분입니다.

설정에서는 뒤로가기를 다듬었습니다. 데스크톱 전체 구성 변경과는 별개로, 설정 안에서 이동하는 동작도 손본 것입니다. 관련 노트 역시 정리 대상에 포함됐습니다. 화면을 다시 짠 작업과 세부 이동 흐름을 다룬 작업을 구분해 두면, 이후 변경 내용을 확인할 때도 범위를 혼동하지 않을 수 있습니다.

## 구독: 판매 전에도 보유한 키 상태 표시

구독 탭에서는 구독 키가 있으면 판매 전에도 키 상태를 보여 주도록 했습니다. 상태 표시의 조건에서 눈여겨볼 부분은 키 보유 여부입니다. 판매가 시작되기 전이라도 키가 있는 사용자는 구독 탭에서 그 상태를 확인할 수 있게 바뀌었습니다.

이 변경을 구독 판매 개시나 결제 기능 추가로 확대해서 읽지는 않으려 합니다. 이번 커밋이 다룬 범위는 보유한 키의 상태 표시입니다. 판매 여부와 키 상태 확인을 구분한 변경으로 정리할 수 있습니다.

이번 네 커밋은 표시 방식, 화면 구성, 실행 공간을 각각 손봤습니다. 배지와 구독 탭에는 확인할 정보를 드러냈고, 데스크톱에는 승인된 시안을 반영했으며, 같은 프로젝트의 두 번째 쓰기 작업에는 워크트리를 적용했습니다. 구체적인 화면 차이와 실행 한도, 점검 결과는 커밋 본문이나 코드에서 추가로 확인할 내용으로 남겨 둡니다.
