# vica 개발일지: 대화와 원격 프로젝트, 데스크톱 작업 화면 정리

2026년 10월 29일 vica의 최근 커밋 세 개에서는 데스크톱 앱의 작업 방식과 화면 구성을 함께 넓혔습니다. 대화 모드와 laya 자동 맡기기, SSH 원격 프로젝트를 추가했고, 화면 갱신 방식과 프로젝트·세션 정보를 살펴보는 UI도 손봤습니다. 이번 기록은 커밋 메시지에서 확인되는 변경을 기능별로 묶었습니다. 구체적인 내부 동작이나 성능 수치까지 확인한 것은 아니어서, 추가된 기능과 확인이 필요한 부분을 나눠 적겠습니다.

## 대화 모드와 laya 자동 맡기기

작업 방식에는 대화 모드와 laya 자동 맡기기가 들어갔습니다. 데스크톱에서 대화를 이어가는 모드와 작업을 자동으로 맡기는 기능이 함께 추가된 셈입니다.

두 기능을 실제로 어떻게 연결해 쓰는지는 별도로 살펴볼 부분입니다. 커밋 메시지만으로는 대화 중 어떤 시점에 laya에 작업을 맡기는지, 자동으로 맡길 범위를 어디서 정하는지까지 알 수 없습니다. 그래서 이번 변경을 곧바로 “작업 전 과정의 자동화”라고 설명하기는 어렵습니다. 지금 기록할 수 있는 범위는 대화와 자동 맡기기라는 작업 방식이 데스크톱에 추가됐다는 점입니다.

## SSH 원격 프로젝트와 프로젝트 목록

프로젝트 영역에서는 SSH 원격 프로젝트 지원과 프로젝트 목록 사이드바가 추가됐습니다. 원격 프로젝트를 다루는 기능이 생기는 동시에, 프로젝트 목록을 사이드바에서 볼 수 있도록 화면 구성도 바뀌었습니다.

이 둘은 프로젝트를 어디서 실행하고 어떻게 찾아 들어갈지와 관련된 변경입니다. 다만 SSH 연결에 필요한 인증 방식, 연결이 끊겼을 때의 처리, 로컬 프로젝트와 원격 프로젝트를 구분하는 표시는 커밋 메시지에 드러나지 않습니다. 원격 지원의 사용성을 판단하려면 연결 성공 여부뿐 아니라 이런 상황도 확인해야겠습니다.

사이드바 역시 목록이 추가됐다는 사실과 탐색이 충분히 편해졌다는 평가는 구분하려고 합니다. 프로젝트가 많아졌을 때 이름을 알아보기 쉬운지, 현재 작업 중인 프로젝트를 찾기 쉬운지는 실제 화면에서 살펴볼 항목입니다.

## 바뀐 줄만 보내는 화면 갱신

화면 갱신에는 바뀐 줄만 보내는 방식이 추가됐습니다. 이번 변경 가운데 갱신 데이터를 다루는 방식이 명시된 부분입니다. 변경된 줄을 전달 대상으로 삼는다는 점은 확인할 수 있지만, 그 결과 전송량이나 응답 시간이 얼마나 줄었는지는 아직 수치로 말할 수 없습니다.

특히 화면 변화가 적을 때와 많은 때의 차이는 따로 확인할 필요가 있습니다. 전달 범위를 줄이는 방식의 효과와 화면이 정확하게 갱신되는지는 각각 검증해야 할 문제니까요. 이번 일지에서는 갱신 방식의 변경까지 기록하고, 성능 개선의 정도는 측정 이후로 남겨두겠습니다.

작업 정보를 살펴보는 쪽에는 세션 작업 맵과 토큰 상태줄이 추가됐습니다. 프로젝트 목록이 프로젝트 단위의 탐색을 맡는다면, 이 영역은 세션의 작업과 토큰 상태를 확인하는 데 관련된 변경으로 묶을 수 있습니다. 다만 작업 맵이 어떤 관계를 보여주는지, 토큰 상태줄이 어떤 값과 기준을 표시하는지는 메시지만으로 확정하기 어렵습니다.
