# vica 개발일지: 채팅 화면 정리와 반복 작업 줄이기

11월 9일부터 10일까지 vica에서는 채팅 화면의 정보 배치와 UI 체계를 손보고, 다시 그리기·터미널 폴링·저장 작업을 줄였습니다. 사용량 패널과 빈 채팅의 시작점도 이번 작업에 포함됐습니다. 최근 커밋 세 개를 화면 구성, 성능, 후속 수정으로 묶어 정리해 보겠습니다.

## 채팅을 시작하고 지난 대화를 찾는 화면

빈 채팅에서는 대화를 시작할 지점을 마련했습니다. 아직 메시지가 없는 상태도 채팅 화면의 일부인 만큼, 대화가 쌓인 뒤의 모습과 함께 다뤘습니다. 시작 화면 카드 높이도 후속 수정 대상이 됐는데, 이 부분은 아래에서 따로 짚겠습니다.

대화 안에서는 답변 머리 영역을 한 줄로 정리했고, 사이드바에서는 날짜별로 대화를 묶었습니다. 두 변경은 서로 다른 위치에서 정보 배치를 정돈한 작업입니다. 답변 머리는 각 답변에 붙는 영역을 다루고, 날짜 묶음은 대화 목록을 나누는 기준을 제공합니다. 다만 커밋 요약만으로는 머리 영역에 어떤 항목이 들어가는지, 날짜를 어떤 단위로 구분하는지까지 확인할 수는 없습니다.

## 사용량 확인과 UI 체계 정리

사용량 패널을 추가하고, 설정 화면의 다크 팔레트와 버튼 체계를 함께 손봤습니다. 사용량을 확인할 영역을 마련하는 한편, 설정 화면의 색상과 버튼 표현도 정리한 셈입니다.

이 작업은 새 화면 요소를 넣는 일과 기존 UI의 기준을 다듬는 일이 함께 진행됐다는 점에서 묶어 볼 수 있습니다. 사용량 패널은 표시할 정보의 영역을 늘리는 변경이고, 다크 팔레트와 버튼 체계는 그 정보를 둘러싼 화면 표현을 다루는 변경입니다. 다만 사용량의 집계 기준이나 버튼별 세부 규칙은 제공된 기록에 없어서, 이번 일지에서는 적용 범위까지만 적겠습니다.

## 채팅 갱신부터 저장까지, 반복 작업 줄이기

성능 쪽에서는 채팅 다시 그리기, 터미널 폴링, 저장을 줄였습니다. 화면을 갱신하는 작업뿐 아니라 터미널 상태를 반복해서 확인하고 데이터를 저장하는 작업까지 조정 범위에 들어갔습니다.

여기서 말할 수 있는 결과는 해당 작업들을 줄였다는 데까지입니다. 어느 조건에서 다시 그리기를 생략했는지, 폴링이나 저장 횟수가 얼마나 달라졌는지는 커밋 요약에 나와 있지 않습니다. 따라서 “채팅이 몇 배 빨라졌다”거나 “자원 사용량이 크게 줄었다”고 설명하기는 어렵습니다. 이번 성능 작업은 반복 수행되는 일을 줄이는 방향으로 진행됐다고 정리하는 편이 정확하겠습니다.

## 기능 추가 뒤 이어진 정확성·레이아웃 수정

UI 기능을 묶어 적용한 뒤에는 정확성과 성능을 위한 후속 수정도 이어졌습니다. 다만 정확성 문제가 발생한 조건이나 수정 방식은 제공된 내용만으로 특정할 수 없습니다. 기능 추가와 함께 후속 보정이 있었다는 사실을 남겨 둡니다.

구체적인 원인이 드러난 것은 시작 화면 카드 높이 문제입니다. 채팅 시작 줄에서 클래스 이름이 충돌했고, 이를 해소했습니다. 이 문제는 빈 채팅의 시작점을 다룬 작업과 연결해 볼 수 있습니다. 시작할 영역을 마련한 뒤, 그 영역의 클래스 충돌로 영향을 받은 카드 높이까지 바로잡은 흐름입니다.

이번 변경에는 화면에 새로 드러나는 사용량 패널부터 눈에 덜 띄는 폴링·저장 조정까지 함께 들어 있습니다. 커밋 기록으로 확인되는 것은 각 영역의 변경과 후속 수정이며, 실제 체감 성능이나 세부 동작까지 입증된 것은 아닙니다. 다음 기록에서 효과를 더 구체적으로 설명하려면, 반복 작업이 줄어든 조건과 변경 전후 측정값을 함께 남기는 것이 좋겠습니다.
