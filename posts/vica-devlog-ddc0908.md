# vica 개발일지: 독립 작업 병렬 실행과 개발 작업 공간 확장

2026년 11월 21일, vica 데스크톱에서는 단일 판단 모델의 독립 작업을 병렬로 실행하도록 바꾸고, 개발 도구와 워크트리 관리를 확장했습니다. 같은 날 버전도 0.2.3으로 올렸습니다. 이번 기록은 작업 실행 방식과 개발 작업 공간이라는 두 영역으로 나눠 정리했습니다. 다만 커밋 메시지만을 바탕으로 작성했기 때문에, 구체적인 화면이나 내부 구현, 성능 수치까지 확인한 기록은 아니라는 점을 먼저 말씀드립니다.

## 작업 실행: 독립 작업을 병렬로 처리합니다

실행 영역의 변화는 단일 판단 모델에서 독립 작업을 병렬로 실행한다는 점입니다. 여기서 눈여겨볼 표현은 ‘단일 판단 모델’과 ‘독립 작업’입니다. 판단 모델을 여러 개로 늘렸다는 내용은 없으며, 병렬 실행의 대상도 모든 작업으로 명시돼 있지는 않습니다. 이번 변경은 해당 모델의 작업 가운데 독립적으로 실행할 수 있는 작업을 다룹니다.

병렬 실행에서는 어떤 작업을 함께 진행할 수 있는지가 중요합니다. 일반적으로 앞선 작업의 결과가 있어야 시작할 수 있는 작업은 실행 순서를 고려해야 합니다. 반면 서로의 결과를 기다릴 필요가 없는 작업에는 동시에 진행할 여지가 있습니다. 이번 커밋에 ‘독립’이라는 조건이 붙어 있다는 점에서, 개발일지에서도 병렬화의 범위를 넓혀 설명하지 않으려 합니다.

이 변화로 실제 대기 시간이 얼마나 줄었는지는 아직 말하기 어렵습니다. 제공된 기록에는 측정 결과나 비교 조건이 없기 때문입니다. 병렬 실행을 지원하게 됐다는 기능 변화와, 사용자가 체감하는 속도 개선은 구분해서 보는 편이 정확하겠습니다. 작업 간 독립성을 판별하는 방식이나 동시 실행 수 제한 역시 커밋 메시지만으로는 알 수 없습니다.

## 개발 환경: 도구와 워크트리 관리 범위를 넓혔습니다

개발 환경 쪽에서는 데스크톱의 개발 도구와 워크트리 관리를 확장했습니다. 실행 영역이 작업을 어떻게 진행할지에 관한 변경이라면, 이 영역은 개발에 사용하는 도구와 작업 공간을 어떻게 다룰지에 관한 변경으로 묶을 수 있습니다.

Git 워크트리는 하나의 저장소에서 여러 작업 디렉터리를 사용할 수 있게 해주는 기능입니다. 서로 다른 브랜치를 별도 디렉터리에서 다루는 개발 흐름과 연결되므로, 워크트리 관리는 작업 공간을 오가는 과정에서 의미가 있습니다. 다만 이것은 워크트리에 대한 일반적인 설명입니다. 이번 vica 변경에 생성·삭제·전환 중 어떤 조작이 추가됐는지, 기존 관리 기능이 어떻게 달라졌는지는 제공된 정보에 없습니다.

개발 도구 확장도 같은 범위에서 기록하려 합니다. 새로운 도구의 이름이나 지원 동작을 임의로 붙이기보다는, 데스크톱에서 다루는 개발 도구와 워크트리 관리가 함께 확장됐다는 사실까지 남깁니다. 실제 사용 흐름을 소개하려면 변경된 코드나 화면을 확인한 설명이 더 필요합니다.

## 버전: 0.2.3으로 올렸습니다

같은 날 릴리스 관련 커밋으로 버전을 0.2.3으로 올렸습니다. 버전 변경 자체를 별도의 사용자 기능처럼 설명하지 않고, 이번 개발 기록의 버전 정보로 정리합니다. 커밋 날짜와 버전은 확인할 수 있지만, 이 정보만으로 배포 완료 여부나 배포 채널까지 단정할 수는 없습니다.

이번 세 커밋에서 확인할 수 있는 변화는 독립 작업의 병렬 실행, 개발 도구와 워크트리 관리 확장, 그리고 0.2.3 버전 변경입니다. 구체적인 사용 예시나 성능 비교를 담기에는 자료가 부족하지만, 실행 방식과 개발 작업 공간 양쪽에 손을 댔다는 점은 분명합니다. 후속 기록에서 효과를 설명할 때도 병렬 실행의 실제 측정 결과와 워크트리 관리의 지원 동작을 각각 확인해 다루는 것이 좋겠습니다.
