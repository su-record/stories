# vica 개발일지: 배포 설명과 업데이트 알림에 변경 내용 담기

2026년 11월 5일, vica에서는 배포 설명을 읽어 오는 경로와 업데이트 알림에 담기는 정보를 손봤습니다. 배포 설명은 `release-notes/<버전>.md`에서 읽도록 바꾸고, 업데이트 알림에는 바뀐 내용 목록을 보여 주도록 했습니다. 작업 기록도 함께 갱신했습니다. 이번 일지는 이 세 변경을 배포 정보 관리, 사용자에게 보이는 안내, 작업 기록으로 나누어 정리합니다.

## 배포 정보 관리: 버전별 파일에서 설명 읽기

배포 설명을 `release-notes/<버전>.md`에서 읽도록 했습니다. 경로에 버전이 들어가므로, 배포할 버전과 그 버전의 설명 파일을 대응시키는 구조입니다. 배포 설명을 어디에서 가져올지에 대한 코드 변경의 의도가 분명하게 드러나는 부분입니다.

이제 배포 설명을 준비하거나 확인할 때 살펴볼 위치는 `release-notes` 아래의 해당 버전 마크다운 파일입니다. 버전마다 설명을 별도 파일로 다루는 만큼, 어떤 버전에 어떤 내용을 안내할지 파일 단위로 확인할 수 있습니다. 다만 이번에 제공된 커밋 정보에는 파일 안의 작성 형식이나 필수 항목까지 나와 있지는 않습니다.

확인할 수 있는 변경 범위도 구분해 두려고 합니다. 이번 기록으로 알 수 있는 것은 배포 설명을 읽는 위치입니다. 파일이 없을 때 어떻게 처리하는지, 버전 문자열을 어떤 규칙으로 파일명에 연결하는지, 기존에는 설명을 어디에서 가져왔는지는 알 수 없습니다. 이 부분까지 구현된 것처럼 설명하지 않고, 버전별 설명 파일을 읽도록 바뀌었다는 데 초점을 맞췄습니다.

## 업데이트 안내: 알림에 바뀐 내용 목록 표시

사용자에게 보이는 쪽에서는 업데이트 알림에 바뀐 내용 목록을 추가했습니다. 새 버전 안내를 받는 자리에서 변경 항목도 함께 볼 수 있도록 한 작업입니다. 업데이트 여부를 판단할 때 확인할 정보가 알림 안에 더해졌습니다.

배포 설명을 파일에서 읽는 작업이 설명의 출처를 다룬다면, 이번 변경은 알림에 무엇을 보여 줄지를 다룹니다. 두 작업 모두 버전의 변경 내용을 전달한다는 점에서 맞닿아 있습니다. 다만 업데이트 알림의 목록이 앞서 말한 마크다운 파일에서 직접 만들어지는지는 제공된 정보만으로 확인되지 않습니다. 같은 날 들어간 변경이라고 해서 하나의 자동화 흐름으로 연결됐다고 단정하지는 않겠습니다.

목록의 표시 순서나 길이, 구체적인 화면 구성도 이번 기록에는 없습니다. 그래서 사용성이 얼마나 좋아졌는지를 평가하기보다는, 업데이트 알림에 변경 내용 목록이 표시되기 시작했다는 기능상의 차이를 남깁니다. 실제 안내 문구가 얼마나 이해하기 쉬운지 판단하려면 목록에 어떤 내용을 적는지도 함께 살펴봐야 합니다.

## 작업 기록: 이번 변경 내역 갱신

기능 변경과 함께 작업 기록도 갱신했습니다. 이 작업은 배포 설명을 읽거나 알림을 표시하는 동작과는 구분해 두었습니다. 사용자에게 직접 보이는 기능을 추가한 항목은 아니지만, 이번 작업 내역을 정리하는 변경으로 개발일지에 함께 남깁니다. 기록의 위치와 구체적인 내용은 제공되지 않아 더 자세히 소개하기는 어렵습니다.

이번 변경에서 확인되는 핵심은 두 가지입니다. 배포 설명은 버전별 마크다운 파일에서 읽고, 업데이트 알림에는 바뀐 내용 목록을 보여 줍니다. 작업 기록 갱신까지 포함해 이번 개발일지의 범위를 정리했습니다. 테스트 결과나 실제 배포 후 반응은 전달받은 정보에 없으므로, 여기서는 구현 변경 내역까지만 기록합니다.
