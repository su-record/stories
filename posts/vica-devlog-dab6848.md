# vica 0.2.9 개발일지: 명령 판단과 검증 근거, 긴 도구 표시 다듬기

2026년 11월 27일의 최근 커밋 5개에서는 채팅의 명령 처리와 검증 근거 확인, 화면에서 넘치는 텍스트 표시를 손봤습니다. 명령 요청의 위험 확인을 어떤 모델에 맡길지 조정하고, 정보를 합칠 때 숫자에 붙은 조건을 보존하도록 수정했습니다. 이 변경들과 UI 수정을 묶어 버전은 **0.2.9**로 올렸습니다.

## 명령 처리: 판단과 합치기의 담당을 조정했습니다

명령 요청에서는 위험 확인도 판단 모델에게 묻도록 바꿨습니다. 명령을 처리하는 과정에서 위험 여부를 확인하는 일을 판단 모델이 맡게 한 변경입니다. 다만 커밋 메시지만으로는 어떤 위험을 확인하는지, 확인 결과가 이후 실행에 어떻게 반영되는지까지 알 수 없습니다. 이번 기록에서는 위험 확인의 담당이 바뀌었다는 범위로 설명드리는 게 정확하겠습니다.

명령 단계에서 조사 내용을 합치는 작업은 빠른 모델이 맡도록 했습니다. 위험을 확인하는 작업과 조사 내용을 모으는 작업에 각각 어떤 모델을 쓰는지 구분한 셈입니다. 빠른 모델이라는 이름만으로 전체 응답 시간이 얼마나 줄었다고 말할 수는 없습니다. 성능 수치가 없는 만큼, 이번 변경의 핵심은 명령 처리 과정의 역할 배분에 두었습니다.

합치기에서는 **숫자에 붙은 조건을 그대로 옮기는 것**도 함께 수정했습니다. 숫자만 남기고 그 숫자가 성립하는 조건을 놓치면, 합쳐진 내용의 의미가 달라질 수 있습니다. 그래서 이번 수정은 숫자 자체뿐 아니라 조건까지 보존하는 데 초점이 있습니다. 조사 내용을 합치는 담당을 정하는 일과, 합친 결과에 무엇을 남겨야 하는지를 다루는 일이 함께 들어갔습니다.

## 검증 근거: 도구 이름이 붙어 있어도 기록과 대조합니다

채팅의 검증 근거를 확인하는 범위도 손봤습니다. 근거 앞에 도구 이름을 붙인 경우에도 실제 도구 기록과 맞춰 보도록 수정했습니다.

여기서 확인하는 대상은 도구 이름의 유무만이 아닙니다. 도구 이름을 앞세운 근거가 실제 기록과 맞는지까지 대조하도록 한 것이 이번 변경의 요점입니다. 도구 이름이 붙었다는 이유만으로 근거를 받아들이지 않도록 확인 범위를 보완했습니다.

다만 이 수정으로 모든 검증 오류를 막았다고 말씀드릴 수는 없습니다. 제공된 커밋에서 확인할 수 있는 범위는 ‘도구 이름을 앞에 붙인 검증 근거’도 실제 도구 기록과 대조한다는 데까지입니다. 검증 정확도가 얼마나 달라졌는지는 별도의 결과가 있어야 설명할 수 있습니다.

## UI: 넘치는 칩과 도구 줄은 말줄임으로 마무리합니다

화면에서는 칩과 도구 줄의 텍스트가 영역을 넘칠 때 표시되는 방식을 고쳤습니다. 글자가 중간에서 잘린 채 보이지 않도록, 넘치는 부분을 말줄임으로 끝내게 했습니다.

이번 수정은 긴 내용을 화면 안에 모두 펼쳐 보여 주는 기능은 아닙니다. 제한된 공간에서 텍스트가 더 이어진다는 점을 말줄임으로 표시하는 변경입니다. 칩과 도구 줄처럼 표시 폭이 정해진 요소에서, 텍스트의 끝을 어떻게 보여 줄지 다듬었습니다.

## 0.2.9에 담은 범위

이번 릴리스는 명령 처리의 역할 배분, 숫자 조건의 보존, 도구 기록과 검증 근거의 대조, 긴 텍스트 표시를 묶었습니다. 각 수정의 대상은 다르지만, 채팅이 정보를 처리하고 화면에 내보내는 과정에서 놓치기 쉬운 조건을 구체적으로 다뤘습니다.

릴리스 커밋으로 확인되는 버전은 0.2.9입니다. 테스트 결과나 배포 상태는 제공된 기록에 없어 덧붙이지 않았습니다. 이번 개발일지는 최근 커밋에서 확인할 수 있는 변경 범위까지 담았습니다.
