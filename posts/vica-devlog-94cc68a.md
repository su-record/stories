# vica 개발일지: 커밋 대상 선택과 네이티브 런타임 재구성

2026년 10월 31일의 vica 변경은 데스크톱에서 커밋할 파일을 고르는 기능, 네이티브 크로스플랫폼 런타임과 컴퓨터 사용 기능의 재구성, 호스팅 CI 워크플로 정리로 나뉩니다. 이번 일지는 최근 커밋 세 개의 메시지를 바탕으로 정리했습니다. 코드와 실행 결과까지 확인한 기록은 아니므로, 구현 방식이나 검증 결과는 단정하지 않겠습니다.

## 데스크톱: 변경 목록에서 커밋 대상 조정하기

데스크톱에는 변경 목록에서 커밋할 파일을 제외하는 기능이 추가됐습니다. 변경된 파일을 확인하는 화면에서 이번 커밋에 넣지 않을 파일을 선택할 수 있도록 한 작업입니다.

작업하다 보면 변경된 파일이 모두 같은 커밋에 들어가야 하는 것은 아닙니다. 한 기능을 수정하는 동안 다른 수정이 함께 생길 수도 있고, 일부 파일은 다음 커밋으로 남겨두고 싶을 수도 있습니다. 이번 기능은 그런 상황에서 커밋 범위를 조정하는 데 쓰일 수 있습니다. 변경 목록과 커밋 대상을 구분해 다룰 수 있다는 점이 이번 데스크톱 작업의 핵심입니다.

다만 여기서 ‘제외’는 커밋 대상에 관한 설명입니다. 파일 자체를 삭제하거나 수정 내용을 되돌리는 기능으로 읽어서는 안 됩니다. 제외 상태가 얼마나 유지되는지, 다시 포함하는 조작은 어떻게 제공되는지, Git 스테이징과 어떤 관계인지는 커밋 메시지만으로 알 수 없습니다. 실제 사용 흐름을 설명하려면 이 부분을 코드나 화면에서 더 확인해야 합니다.

## 실행 기반: 런타임과 컴퓨터 사용 기능 재구성

실행 기반에서는 네이티브 크로스플랫폼 런타임과 컴퓨터 사용 기능을 다시 구성하는 작업이 진행됐습니다. 커밋 메시지에 두 영역이 함께 명시돼 있어, 이번 기록에서는 하나의 영역으로 묶었습니다.

런타임은 실행 기반에 해당하고, 컴퓨터 사용 기능은 그 기반 위에서 제공되는 동작과 관련된 영역입니다. 따라서 후속 검증에서는 각각의 구현뿐 아니라 두 영역이 연결되는 지점도 살펴볼 필요가 있습니다. 다만 실제로 어떤 구조를 바꿨고 어떤 의존성을 정리했는지는 현재 자료에 담겨 있지 않습니다.

특히 ‘네이티브’와 ‘크로스플랫폼’이라는 표현만으로 지원 운영체제나 배포 범위를 확정할 수는 없습니다. 이번 재구성으로 속도가 빨라졌거나 안정성이 높아졌다고 말할 근거도 아직 없습니다. 확인할 과제는 대상 환경에서 런타임이 정상적으로 시작되는지, 컴퓨터 사용 기능이 의도한 동작을 수행하는지입니다. 이는 이번 커밋의 검증 결과가 아니라, 변경 효과를 판단하기 위해 필요한 확인 사항입니다.

## 자동화 설정: 호스팅 CI 워크플로 제거

저장소 설정에서는 요청하지 않은 호스팅 CI 워크플로를 제거했습니다. 사용자 화면에 기능을 더하는 작업과는 구분되지만, 저장소에 어떤 자동화 설정을 남길지 정리했다는 의미가 있습니다.

이번 기록으로 확인할 수 있는 범위는 해당 워크플로의 제거까지입니다. 다른 CI로 옮겼는지, 별도의 테스트 자동화가 남아 있는지, 기존 실행에 비용이나 보안 문제가 있었는지는 알 수 없습니다. 따라서 CI 전체를 없앴다거나 운영 문제가 해결됐다고 확대해서 설명하지 않겠습니다.

## 이번 변경에서 남겨둘 확인점

이번 세 커밋은 커밋 대상 선택, 실행 기반 재구성, 자동화 설정 정리라는 서로 다른 층위를 다뤘습니다. 사용자 관점에서 가장 구체적으로 설명할 수 있는 변화는 데스크톱 변경 목록에서 파일을 커밋 대상에서 제외할 수 있게 된 점입니다.

런타임 재구성은 세부 구현과 실행 결과를 함께 봐야 효과를 평가할 수 있습니다. 다음 기록에서는 파일 제외 기능의 실제 조작 흐름과 런타임 검증 결과를 확인할 수 있다면, 무엇이 달라졌고 어떤 제약이 남았는지 더 구체적으로 다루겠습니다.
