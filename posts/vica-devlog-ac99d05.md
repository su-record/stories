# vica 개발일지: macOS 개발 앱 아이콘 수정과 0.1.1 버전 정리

2026년 11월 5일, vica에서는 개발용 데스크톱 앱의 아이콘을 수정하고 버전을 0.1.1로 올렸습니다. 지식 문서에 남아 있던 vica-laya 작업 상태도 실제 커밋 여부에 맞게 고쳤습니다. 이번 세 커밋은 데스크톱 표시 문제, 릴리스 버전, 작업 기록으로 나눠 살펴보겠습니다.

## 데스크톱: Vica-dev에도 시작할 때 앱 아이콘 적용

macOS에서 Vica-dev를 켰을 때 앱 아이콘 대신 회색 판이 보이던 문제를 수정했습니다. 개발용 앱인 Vica-dev에도 시작 시점에 앱 아이콘을 적용하도록 바꾼 것이 이번 데스크톱 수정의 핵심입니다.

개발용 앱은 사용자에게 배포하는 앱과 구분해서 다루지만, 실행했을 때 보이는 모습도 개발 과정의 일부입니다. 회색 판이 나타나던 자리에 앱 아이콘을 표시하도록 손보면서, Vica-dev를 켰을 때 눈에 들어오는 표시 문제를 정리했습니다. 기능을 추가한 작업은 아니어도, 앱을 실행하며 마주치는 구체적인 불편을 고친 변경입니다.

다만 수정 범위를 넓혀 설명하지는 않으려고 합니다. 이번 커밋에서 확인할 수 있는 대상은 macOS의 Vica-dev이며, 변경 시점은 앱이 켜질 때입니다. 다른 운영체제의 아이콘 처리나 데스크톱 앱 전반의 외형까지 개선했다고 볼 근거는 없습니다. 실제 실행 화면이나 별도 테스트 결과도 주어진 기록에 없으므로, 여기서는 아이콘 적용을 수정했다는 내용까지만 남깁니다.

## 릴리스: 버전을 0.1.1로 변경

릴리스 영역에서는 버전을 0.1.1로 올렸습니다. 이번 기록에서 버전 변경과 함께 확인되는 앱 수정은 앞서 설명한 개발용 데스크톱 앱의 아이콘 처리입니다. 버전 번호 자체의 변경과 구체적인 수정 내용을 나눠 적어두면, 나중에 이 시점의 작업을 다시 확인하기에도 범위가 분명해집니다.

버전을 올린 것과 배포를 완료한 것은 구분할 필요가 있습니다. 제공된 커밋에는 배포 파일 생성, 공개 여부, 업데이트 전달 결과가 담겨 있지 않습니다. 따라서 이번 개발일지에서는 “0.1.1 버전으로 변경했다”라고 정리하겠습니다. 사용자가 이미 새 버전을 받을 수 있다거나 설치까지 확인됐다고 안내할 단계인지는 이 기록만으로 알 수 없습니다.

## 지식 문서: vica-laya 작업을 커밋된 상태로 정정

문서에서는 vica-laya 작업 상태를 ‘커밋된 상태’로 고쳤습니다. 이 변경은 vica-laya의 기능을 새로 구현했다는 내용이 아니라, 작업 기록에 적힌 상태를 바로잡은 문서 수정입니다.

작업 상태는 다음에 무엇을 해야 하는지 판단할 때 참고하는 정보입니다. 이미 커밋된 작업이라면 문서에도 그 사실이 드러나야, 기록을 읽는 사람이 커밋 여부를 다시 확인하는 혼선을 줄일 수 있습니다. 이번 수정의 의미도 그 지점에 있습니다. 코드 변경과 별개로, 작업이 어디까지 진행됐는지 설명하는 기록을 맞췄습니다.

다만 ‘커밋됨’을 ‘검증 완료’나 ‘배포 완료’와 같은 뜻으로 쓰지는 않겠습니다. 이번 문서 변경에서 확인되는 것은 커밋 여부의 정정이며, vica-laya 작업 전체의 완료 범위나 후속 검증 결과는 포함되어 있지 않습니다.

이번 작업은 앱 실행 시 보이는 문제를 고치고, 버전과 문서에 그 시점의 상태를 정리한 기록입니다. 0.1.1을 돌아볼 때도 macOS 개발 앱의 아이콘 수정과 vica-laya 문서 정정을 각각 구분해서 확인할 수 있도록 남겨둡니다.
