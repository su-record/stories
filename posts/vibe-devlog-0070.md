# vibe 개발일지 #70 - 에이전트 계약을 빌드타임으로: 에이전틱 공백 해소와 일회성 코드 레인 (11개 커밋)

**작업 기간**: 2026-09-02 ~ 2026-09-03

안녕하세요, vibe를 개발하고 있는 Su입니다.

vibe의 핵심 철학은 **"Agent = Model + Harness"**입니다. 모델의 자율성에만 품질을 맡기면 언젠가 틈이 생깁니다. 하네스가 구조적으로 실수를 차단해 주어야 "Easy vibe coding"과 "Minimum quality guaranteed"가 공존할 수 있죠.

이번 이틀간은 런타임에 모델이 자의적으로 판단하던 영역들을 **빌드타임 계약(Contract)**과 **명시적 경로 규칙**으로 끌어올리는 작업을 집중적으로 진행했습니다. 11개의 커밋과 함께 v3.2.62에서 v3.2.63으로 올라간 과정의 고민들을 공유합니다.

## 📝 이번 기간 작업 내용

### 1. 에이전트 계약 & 수명주기 아키텍처
모델에게 "이 코드는 임시 코드야"라고 프롬프트로 속삭이는 대신, 시스템 구조로 강제하는 기반을 닦았습니다.

- **feat(contract): 에이전트 계약 — 런타임 축을 빌드타임에 잡는다**  
  에이전트가 호출하는 도구와 훅의 인터페이스 정합성을 빌드 단계에서 타입 레벨로 검증합니다. 런타임에 가서야 터지는 계약 위반을 사전에 봉쇄했습니다.
- **feat(lifetime): 일회성 코드 레인 — 판정을 모델이 아니라 경로가 한다**  
  임시 프로토타입이나 스파이크성 코드가 메인 베이스에 스며들지 않도록 별도 레인을 분리했습니다. 일회성 여부 판단을 모델의 의사결정에 맡기지 않고, 파일 경로(Path) 기반 룰로 강제합니다.
- **feat: 에이전틱 패러다임 공백 3건 (#100)**  
  실제 멀티 세션 운영에서 드러난 공백 3가지(역방향 계약 드리프트 감지, 모델 턴 회전 비용 계측, 자기 대조 벤치마크)를 하네스 코어에 구현했습니다.

### 2. 테스트 안정성 및 CI 환경 현대화
병렬 테스트 경쟁 문제를 해결하고, 워크플로 런타임을 Node 24로 전환했습니다.

- **test(ephemeral): 대조 파일을 src/ 밖으로 — wiring-integrity 병렬 경쟁 해소**  
  `wiring-integrity` 검사가 실행되는 도중 임시 대조 파일이 `src/` 내부에 생성되면서 발생하던 레이스 컨디션을 수정했습니다. 대조 파일 경로를 `src/` 외부 격리 디렉터리로 이전했습니다.
- **ci(actions): 워크플로 액션을 Node 24 대상 메이저로 올린다 (#99)**  
  GitHub Actions 환경을 Node 24 런타임 호환 메이저 버전으로 일괄 업그레이드했습니다.
- **ci(release): 태그를 밀 수 없는 환경을 위한 workflow_dispatch 입구**  
  환경 제약상 Git Tag를 직접 푸시하기 어려운 CI 환경에서도 안전하게 릴리스를 트리거할 수 있도록 수동 디스패치 파이프라인을 추가했습니다.

## 💡 작업 하이라이트

### "판정은 모델이 아니라 경로가 한다" — 일회성 코드 레인

AI 코딩 하네스를 만들다 보면 흔히 빠지는 함정이 있습니다. "이 코드가 영구 유지될 코드인지, 아니면 POC용 일회성 코드인지"를 모델 스스로 판단해 주석을 달거나 분류하도록 지시하는 것입니다.

하지만 모델은 맥락이 길어지면 약속을 잊습니다. 결국 하네스의 역할은 **물리적 경계**를 치는 것입니다.

```text
[AS-IS: 프롬프트 의존형]
Model ──> "이 함수는 임시입니다" 주석 작성 ──> src/utils/ 에 저장 ──> 프로덕션 오염

[TO-BE: 하네스 경로 강제형]
Model ──> .vibe/ephemeral/* 레인에만 작성 가능 ──> wiring 검증 대상에서 원천 배제
            └── 빌드타임 계약 위반 시 즉각 에러 반환
```

판정의 주체를 모델의 '이해'에서 파일 시스템의 '경로'로 넘겼습니다. 임시 코드는 무조건 격리된 레인에만 머물고, 메인 브랜치로 승격하려면 하네스의 계약 검증을 명시적으로 통과해야 합니다. 

이 변경 과정에서 임시 대조 파일이 `src/`에 남아 병렬 테스트를 깨뜨리던 문제도 함께 잡았습니다. 테스트 파일을 밖으로 완전히 빼내면서 CI 빌드 안정성이 눈에 띄게 높아졌습니다.
