# vibe 개발일지 #54 - 파이프라인 Stakes 비례 실행과 CC↔Codex 동등성 확보 (12개 커밋)

**작업 기간**: 2026-07-22 ~ 2026-07-26

안녕하세요, Su입니다! 

AI 코딩 하네스 도구인 `vibe`(@su-record/vibe)를 개발하면서 가장 고민하는 지점은 **"어떻게 하면 AI에게 최소한의 품질을 보장받으면서도 개발 속도를 저해하지 않을까?"**입니다. 이번 며칠 동안은 작업의 위험도(Stakes)에 따라 검증 강도를 다르게 적용하고, 지원하는 AI CLI(Claude Code, Codex CLI) 간의 하네스 격차를 줄이는 데 집중했습니다.

최근 5일간 진행된 12개 커밋의 주요 변화를 정리해 공유해 드립니다.

---

## 📝 이번 기간 작업 내용

이번 작업은 크게 **파이프라인 유연화**, **워크플로우 제어 강화**, **품질 게이트 및 멀티 CLI 동등성 확보**의 3가지 영역으로 나누어 진행되었습니다.

### 1. Stakes 기반 파이프라인 & SPEC 시스템 고도화
- **파이프라인에 stakes 비례 실행 도입**: 작업 위험도(Stakes)에 맞춰 검증 파이프라인의 무거움을 조절하도록 개선했습니다.
- **stakes 분류 강제화 & RTM 분할 SPEC 지원**: 파이프라인 시작 시 Stakes 단계를 필수로 정의하게 하고, 복잡한 요구사항은 RTM(Requirement Traceability Matrix) 기반 분할 SPEC으로 다룰 수 있게 했습니다.
- **SPEC 기각 대안(Traps) 기록 기능 추가**: AI가 이전에 시도했다가 실패했거나 배제한 대안(Traps)을 SPEC에 기록하여, 반복적인 잘못된 접근을 방지하도록 유도했습니다.

### 2. 워크플로우 제어 및 런타임 환경 정리
- **Hard trigger 명령형 규칙 추가**: 글로벌 워크플로우에서 `vibe` 실행 조건이 모호할 때 AI가 판단을 미루지 않고 즉시 발동하도록 강력한 Trigger 규칙을 주입했습니다.
- **.gitignore 최적화**: `.vibe/runs` 이하 생성되는 런타임 아티팩트가 Git 추적에 남지 않도록 정리했습니다.
- **버전 릴리즈**: v3.2.3, v3.2.4, v3.2.5, v3.2.6 연속 패치 배포.

### 3. 스킬 품질 게이트(STCV) & CC↔Codex 하네스 동등성 (7/26 메이저 합병)
- **스킬 품질 게이트(STCV) 도입 및 보강**: AI 스킬이 일정한 품질 기준을 통과해야만 실행되도록 STCV(Skill Testing & Validation) 규칙을 구축했습니다.
- **Claude Code ↔ Codex CLI 하네스 동등성(Parity) 확보**: 사용자가 Claude Code를 쓰든 Codex CLI를 쓰든 vibe의 하네스 훅과 스킬이 동일한 수준으로 보장되도록 레이어를 정렬했습니다.
- **조건부 로드 기반 진짜 분리**: 모든 프롬프트와 규칙을 매번 불러오지 않고, 필요한 시점에 조건부 로드(Lazy Load)되도록 분리하여 AI 오버헤드를 약 35% 줄였습니다.

## 💡 작업 하이라이트

### 1. Stakes 비례 실행: "단순 오타 수정에 고중량 파이프라인은 과유불급"

이전에는 아주 간단한 UI 텍스트 수정 작업에도 똑같이 무거운 SPEC 검증 과정을 거쳐야 했습니다. AI 코딩의 장점인 빠른 속도가 둔화되는 원인이었죠.

```
[Before]
모든 작업 (Low/High Stakes 구분 없음) 
└─> 동일한 고중량 SPEC 검증 파이프라인 실행 🐢

[After]
작업 요청
├─> Low Stakes  (단순 수정) ──> 경량화된 Fast-track 파이프라인 ⚡
└─> High Stakes (핵심 로직) ──> RTM 분할 SPEC + Traps 검증 파이프라인 🛡️
```

High Stakes 작업에서는 **Traps(기각된 대안)** 기록을 필수화했습니다. AI가 "이 방식은 왜 안 되는가?"를 스스로 정리해두게 하니, 같은 실수를 반복하며 프롬프트를 소모하는 현상이 눈에 띄게 줄었습니다.

### 2. Claude Code ↔ Codex CLI 하네스 동등성 (Parity)

"Agent = Model + Harness"라는 vibe의 철학에 맞춰, AI 모델이 바뀌더라도 **Harness가 제공하는 안정성**은 동일해야 합니다.

![]() *(Claude Code와 Codex CLI가 vibe 하네스를 통해 동일한 게이트를 통과하는 구조)*

```
[Claude Code] ──┐
                ├──> [vibe Harness (STCV Gate & Hooks)] ──> 균일한 품질의 결과물
[Codex CLI]   ──┘
```

두 CLI 환경의 프롬프트 해석 방식 차이로 인해 특정 훅이 실행되지 않거나 스킬 로딩 방식이 달라지는 문제가 있었습니다. 이를 해결하기 위해 조건부 로딩 레이어를 전면 재구성하여 두 환경 모두에서 100% 동등한 훅 실행 타이밍을 확보했습니다.

AI 에이전트 도구를 만들면서 느끼는 가장 큰 배움은 **"AI에게 자율성을 주되, 가이드레일(Harness)은 선명하고 촘촘해야 한다"**는 것입니다. 

검증 규칙이 너무 빡빡하면 AI가 답답해하고, 너무 느슨하면 품질이 무너집니다. 이번 파이프라인 유연화와 STCV 스킬 게이트 도입은 그 균형점을 찾아가는 의미 있는 발걸음이었습니다.

vibe 프로젝트에 관심이 있으시다면 npm에서 `@su-record/vibe`를 이용해 보시고, 언제든 피드백 부탁드립니다. 감사합니다!
