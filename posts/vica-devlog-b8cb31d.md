# vica 개발일지: 모델 설정 위치와 채팅의 역할 분담 정리

2026년 11월 27일의 최근 커밋 세 개에서는 모델 설정 화면과 채팅 처리 흐름을 손봤습니다. 설정에서는 모델 목록을 갱신하는 줄의 위치를 바꿨고, 채팅에서는 판단 모델이 도구 묶음을 고르는 범위를 넓혔습니다. 조사 결과를 합치는 일도 빠른 모델에 맡겼습니다. 이번 기록은 커밋 메시지에서 확인할 수 있는 변경을 중심으로 정리했습니다.

## 설정: 모델 목록 갱신을 ‘모델 사용’ 쪽으로

모델 목록 갱신 줄을 **모델 등록 영역에서 모델 사용 영역으로 옮겼습니다.** 목록을 갱신하는 기능을 새로 추가한 것은 아니고, 기존 항목이 놓이는 자리를 바꾼 작업입니다.

등록과 사용은 같은 모델을 다루더라도 사용자가 하려는 일이 다른 영역입니다. 이번 변경으로 목록 갱신은 등록 쪽을 떠나 사용 쪽에 자리하게 됐습니다. 설정 화면에서 이 항목을 찾으실 때는 이제 모델 사용 영역을 보시면 됩니다.

커밋 메시지만으로는 갱신 방식이나 가져오는 목록의 범위까지 달라졌다고 말할 수 없습니다. 이번 설정 변경의 핵심은 기능 자체보다 배치에 있습니다. 화면 전체를 개편했다는 식으로 설명하기보다는, 모델 목록을 갱신하는 항목의 위치를 조정했다고 보는 편이 정확하겠습니다.

## 채팅: 도구 묶음 선택을 판단 모델에 맡기기

채팅 쪽에서는 **판단 모델이 일꾼에게 줄 도구 묶음을 고르도록** 바꿨습니다. 어떤 도구 묶음을 전달할지 결정하는 역할을 판단 모델이 맡는다는 점이 핵심입니다. 일꾼이 작업을 수행하는 흐름에서, 그 작업에 사용할 도구 묶음을 선택하는 주체가 명확해졌습니다.

이 흐름은 명령으로 넘긴 단계에도 적용했습니다. 명령을 통해 전달된 단계라고 해서 도구 묶음 선택을 별도로 취급하지 않고, 이 경우에도 판단 모델이 고르도록 했습니다. 두 변경을 함께 보면, 도구 선택을 판단 모델에 맡기는 흐름을 만들고 그 적용 범위를 명령으로 넘긴 단계까지 넓힌 작업으로 묶을 수 있습니다.

다만 판단 모델이 어떤 기준으로 도구 묶음을 고르는지, 선택할 수 있는 묶음에는 무엇이 있는지는 주어진 기록에 나오지 않습니다. 도구 선택의 정확도가 높아졌다거나 불필요한 호출이 줄었다고 단정할 근거도 아직 없습니다. 이번 일지에서는 선택 주체와 적용 범위가 바뀌었다는 데 초점을 맞추겠습니다.

## 채팅: 조사 합치기 담당 변경과 vibe 훅 제거

조사 결과를 합치는 단계는 **빠른 모델이 맡도록** 했습니다. 도구 묶음을 고르는 일은 판단 모델에, 조사 내용을 합치는 일은 빠른 모델에 배정한 셈입니다. 채팅 안에서도 작업의 성격에 따라 담당 모델을 나누는 방향이 드러납니다.

이 변경을 곧바로 응답 속도나 비용 개선으로 설명하기는 어렵습니다. 빠른 모델에 일을 맡겼다는 사실과 실제 처리 시간이 얼마나 달라졌는지는 구분해야 하니까요. 커밋 메시지에는 측정 결과가 없으므로, 확인된 변화는 조사 합치기 단계의 담당 모델이 바뀌었다는 점까지입니다.

같은 채팅 영역에서 vibe 훅도 제거했습니다. 다만 훅을 뺀 이유나 사용자에게 보이는 동작에 어떤 차이가 생기는지는 기록만으로 알 수 없습니다. 도구 선택 방식 변경과 함께 들어간 작업이지만, 둘 사이의 인과관계까지 덧붙이지는 않겠습니다.

이번 변경을 확인할 지점은 구체적입니다. 설정에서는 목록 갱신 줄이 모델 사용 영역에 놓였는지, 채팅에서는 명령으로 넘긴 단계도 판단 모델의 도구 선택을 거치는지 살펴볼 수 있습니다. 조사 합치기를 빠른 모델이 담당하는지도 별도로 확인해야 합니다. 성능에 대한 평가는 그 동작과 결과를 확인한 뒤에 붙이는 것이 맞겠습니다.
