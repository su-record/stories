# vibe 개발일지 #59 - 게이트의 재정의와 3,400줄의 레거시 다이어트 (11개 커밋)

**작업 기간**: 2026-08-08 ~ 2026-08-09

안녕하세요! AI 코딩 하네스 도구 **vibe(`@su-record/vibe`)**를 만들고 있는 Su입니다.

vibe의 핵심 철학은 **"Easy vibe coding + Minimum quality guaranteed"**입니다. 이번 릴리즈(v3.2.19 ~ v3.2.20)에서는 품질을 보장하기 위한 게이트(Gate) 시스템을 대폭 강화하는 한편, 프로젝트에 쌓여 있던 묵은 레거시 코드 3,444줄을 시원하게 다이어트했습니다.

짧은 시간 동안 밀도 있게 진행된 11개 커밋의 여정을 공유합니다!

---

## 📝 이번 기간 작업 내용

### 1. 안전 장치 및 게이트 레이어 강화 (Feat)
AI 에이전트가 코드를 작성하고 루프를 돌 때, 제어권을 잃거나 불필요한 비용이 낭비되는 것을 막기 위한 검증 게이트를 파이프라인 중간중간에 배치했습니다.
- **SPEC 노드 내 Code Guard 도입**: 검증 및 게이트를 파이프라인 최후반부에만 두지 않고, SPEC 단계 자체에 Code Guard를 추가해 조기 검증이 가능하도록 개선
- **Loop 비용 게이트 추가**: 에이전트 루프 실행 시 사람을 오직 시작점에만 세워두지 않고, 실행 중간 비용 threshold를 체크하는 안전 게이트 신설

### 2. 레거시 정리 및 오케스트레이터 단순화 (Refactor)
vibe의 가벼운 동작을 방해하던 죽은 모듈과 복잡한 오케스트레이션 구조를 대대적으로 정리했습니다.
- **죽은 모듈 3,444줄 대량 삭제**: 사용되지 않던 레거시 코드 모듈 정리로 패키지 경량화 및 검증 체커 안정화
- **Dispatch 오케스트레이터 정리**: 불필요해진 죽은 오케스트레이터를 삭제하고, 결정론적 신호(Deterministic Signals) 처리 로직을 순수 코드로 전면 이관

### 3. 디버깅 및 파싱 안정성 개선 (Fix)
현장에서 제보되거나 엣지 케이스에서 발생하던 파싱/상태 관리 버그 3건을 해결했습니다.
- **Codex CLI 연동 fix**: `config.toml` 파싱 시 `notify` 키가 중복으로 들어가 설정 파일 파싱이 깨지던 문제 해결
- **Code-Check 구문 분석 fix**: 문자열 보간(Interpolation) 내부의 중괄호 깊이(`{}`) 추적 로직을 수정하여 검사가 조기 종료되어 미탐이 발생하던 현상 수정
- **State 소유권 통일**: 레거시 경로 상태 소유권을 정리하여 `ANCHOR` 가 조용히 죽어버리던(Silent Death) 고질적 문제 해결

## 💡 작업 하이라이트

### "게이트는 파이프라인 끝에만 존재하는 것이 아니다"

그동안 AI 코딩 하네스를 운용하면서 느낀 점은 **"검증을 뒤로 미룰수록 실패 비용이 기하급수적으로 커진다"**는 것이었습니다.

기존에는 파이프라인의 맨 마지막에 품질 체크를 배치하고, 인간 승인도 시작 시점에만 집중되어 있었습니다. 하지만 이번 개편을 통해 에이전트의 이동 경로 곳곳에 **방어선(Guard)**을 구축했습니다.

```
[ 기존 파이프라인 ]
[시작 (사람 승인)] ──> [SPEC 작성] ──> [코드 생성] ──> [최종 품질 검사 (Gate)]

[ 개선된 vibe 파이프라인 (v3.2.20) ]
[시작] ──> [SPEC 노드 (+Code Guard)] ──> [Loop 실행 (+비용 Gate)] ──> [최종 검사]
                 ▲ 조기 결함 차단              ▲ 과도한 토큰/비용 방지
```

SPEC 노드 자체에 **Code Guard**를 직접 통합함으로써, 명세 작성 단계에서 발생할 수 있는 결함을 사전에 쳐낼 수 있게 되었습니다. 또한 루프 내에 **비용 게이트**를 두어 에이전트가 무한 루프나 불필요한 탐색으로 비용을 탕진하기전에 제어권을 다시 파악할 수 있도록 했습니다.

### 죽은 모듈 3,444줄 삭제 & 조용한 버그 퇴치

AI 에이전트 도구를 개발하다 보면 에이전트가 생성해 둔 임시 모듈이나 과거 구조의 흔적이 레거시로 남기 쉽습니다. 이번에 `code-check` 분석기를 고치면서 프로젝트 내 숨어 있던 **죽은 모듈 3,444줄을 통째로 삭제**했습니다.

더불어 레거시 코드와 얽혀 `ANCHOR` 상태가 에러 로그도 없이 조용히 죽어버리던 버그가 있었는데, 상태 경로 소유권을 명확히 일원화하면서 드디어 원인을 잡았습니다. 묵은 때를 벗겨낸 기분이라 정말 속이 다 시원하네요!
