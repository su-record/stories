# vibe 개발일지 #56 - npm 설치 파이프라인 버그 해결과 Codex 루프 정교화 (10개 커밋)

**작업 기간**: 2026-07-26

안녕하세요, Su입니다! 

AI 코딩 하네스 도구인 `vibe`(@su-record/vibe)를 개발하면서 가장 철저하게 지키려는 원칙 중 하나는 **"유저가 신경 쓸 필요 없는 최소 품질 보장(Minimum quality guaranteed)"**입니다.

하지만 이번 2026년 7월 26일 하루 동안, 배포 파이프라인과 업그레이드 후처리 과정에서 유저 모르게 조용히 버그가 쌓일 뻔한 지점들을 다수 발견했습니다. 연속해서 4개의 패치 버전(v3.2.10 ~ v3.2.13)을 연달아 올리며 진행했던 피땀 어린 수습 및 최적화 과정을 공유합니다.

---

## 📝 이번 기간 작업 내용

이번 10개 커밋은 크게 **`npm postinstall/upgrade 파이프라인 안정화`**, **`루프 Stuck 판정 및 CI 가드`**, **`스킬 SSOT 드리프트 교정`** 3가지 영역으로 나누어 진행했습니다.

- **4개 패치 버전 연속 배포**: v3.2.10 → v3.2.11 → v3.2.12 → v3.2.13
- **3개 주요 스킬 SSOT 불일치 교정 및 중복 제거**
- **4개 문서 간의 루프 정의 모순 단일화 및 CI 자동 검증 가드 추가**

### 1. postinstall 및 업그레이드 파이프라인 버그 수정 (v3.2.11 ~ v3.2.13)
* **배송본 스킬 동기화 잔존 버그 해결**: 패키지 신규 버전에서 특정 스킬 파일을 삭제해도 유저의 로컬 설치본에는 그대로 영구 잔존하던 버그를 해결했습니다.
* **npm 파이프 로그 유실 수정**: `npm install -g` 나 업그레이드 실행 시 파이프라인 처리 도중 `postinstall` 보고 리포트 라인이 삼켜져 눈에 보이지 않던 문제를 바로잡았습니다.
* **유휴 스킬 Prune 보고 및 오삭제 방지**: 삭제 처리(Prune) 리포트 출력을 정상화하고, 하네스가 작업 중 생성한 레지티밋 vibe 생성물까지 실수로 지워버리던 오삭제 로직을 수정했습니다.

### 2. 하네스 루프(Loop) Stuck 감지 정교화 (v3.2.10)
* **Stuck 시맨틱 문서 모순 해소**: AI 에이전트가 갇혔을 때 판정하는 `stuck` 기준이 4개의 문서마다 서로 다르게 작성되어 있던 모순을 해소하고 하나의 정의로 단일화했습니다.
* **Codex 3차 재검증 및 quick 별칭 정합**: Codex CLI와의 연동성을 보장하기 위해 quick 명령어 별칭 정합성을 맞추고 stuck 판정 로직을 3차 재검증했습니다.
* **CI 가드 구축**: 향후 개발 중 루프 정의 문서와 실제 로직 간 드리프트가 발생하지 않도록 CI 자동 검증 단계를 추가했습니다.

### 3. 스킬 시스템 최적화 및 PreCompact 훅 추가
* **SSOT 드리프트 교정**: 단일 진실 출처(SSOT) 규칙에 어긋나 있던 스킬 코드 3건 수정 및 후미에 불필요하게 남아있던 중복 코드를 완전히 제거했습니다.
* **Codex PreCompact 훅 구현**: Codex 모델의 맥락 압축 전에 실행될 `Codex PreCompact` 훅을 새로 추가하여 토큰 사용 및 품질 보장 체계를 강화했습니다.

## 💡 작업 하이라이트

### "배송본엔 없는데 왜 로컬엔 남아있죠?" — postinstall 스킬 정리 잔혹사

이번 작업 중 가장 진땀을 뺐던 버그는 스킬 파일 잔존 및 업그레이드 파이프라인 문제였습니다.

`vibe` 패키지에서 더 이상 필요 없어져 삭제한 스킬 파일이 유저가 `@su-record/vibe`를 업그레이드해도 로컬 환경에는 여전히 섀도우 파일로 남아있는 현상이 발생했습니다. 스킬이 꼬이면서 에이전트가 구버전 스킬을 실행하려는 문제가 생길 수 있는 아찔한 상황이었습니다.

```
[Before]
새 버전 패키지 설치 -> 신규 스킬 추가됨 -> (구 버전 스킬 삭제 안 됨!) -> phantom skill 동작 위험 💣
postinstall 로그 -> npm stdout 파이프에 삼켜져 콘솔 출력 무반응

[After]
새 버전 패키지 설치 -> 신규 스킬 동기화 + 배송본에 없는 구 스킬 Prune 처리 -> vibe 생성물 안전 보호
postinstall 로그 -> 파이프라인 흐름을 저해하지 않고 렌더링 정상 완료 ✨
```

삭제 리포트가 여전히 유저 콘솔에 안 찍히는 원인을 쫓아가 보니, npm 실행 시 내부 파이프스트림 과정에서 출력 로그가 삼켜지고 있었습니다. 파이프 호환성을 완벽히 맞추고, 동시에 `vibe`가 작업 수행 중 생성했던 정당한 결과물이 삭제 대상(Prune)으로 잘못 오판받지 않도록 안전 가드까지 겹겹이 쳤습니다.

### 루프 Stuck 시맨틱 단일화와 CI 가드

AI가 특정 작업에 갇혀 무한 루프를 돌 때 이를 차단하는 `stuck` 감지 로직은 하네스의 핵심 안전장치입니다. 그런데 코드가 발전하면서 정작 **문서 4곳에서 stuck을 정의하는 시맨틱이 서로 모순**되어 있었습니다.

1. 문서 간 모순을 정밀 분석해 정의를 단일화했습니다.
2. Codex CLI와 3차 재검증 테스트를 거쳐 `quick` 별칭과 stuck 판정을 완벽히 합치시켰습니다.
3. 이를 어길 시 빌드가 실패하도록 **CI 가드**를 설치해 사람이 만드는 실수를 시스템으로 막아두었습니다.
