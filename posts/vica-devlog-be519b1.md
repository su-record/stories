# vica 개발일지: 실행부 분리와 파일 탭 사용성 개선

10월 29~30일 vica에서는 화면과 Rust 실행부의 경계를 정리하고, 데스크톱에서 파일 탭을 다루는 방식을 손봤습니다. 탭이 많을 때 선택한 파일을 찾기 쉽도록 탭 줄을 개선했고, 소스 코드에는 문법에 따른 색상을 적용했습니다. 이번 기록은 세 커밋을 구조와 오류 복구, 탭 탐색, 파일 내용 표시로 나눠 정리했습니다.

## 구조와 오류 복구: 화면과 Rust 실행부 분리

먼저 화면과 Rust 실행부를 분리하는 리팩터링을 진행했습니다. 화면을 보여 주는 부분과 실제 실행을 맡는 부분의 경계를 정리한 작업입니다. 겉으로 드러나는 기능 변화와는 성격이 다르지만, 이후 변경 사항을 어느 쪽에서 다뤄야 할지 구분하는 데 필요한 기반이라고 보고 있습니다.

같은 작업에서 오류 복구도 강화했습니다. 실행 과정에서 문제가 생겼을 때의 대응을 함께 다뤘다는 점이 이번 구조 변경의 중요한 부분입니다. 다만 커밋 요약만으로는 어떤 오류를 복구하는지, 복구 뒤 어떤 상태로 돌아가는지까지 설명하기 어렵습니다. 그래서 모든 오류에서 자동으로 정상 상태를 되찾는다고 표현하지는 않겠습니다. 이번에 확인할 수 있는 변경 범위는 화면과 실행부를 분리하고, 오류 상황의 복구 처리를 보강했다는 데까지입니다.

## 탭 탐색: 창 너비를 넘겨도 선택한 탭이 보이도록

데스크톱에서는 열린 탭이 창 너비를 넘어가는 상황을 수정했습니다. 파일을 여러 개 열면 탭 줄에 모든 탭을 한꺼번에 담을 수 없는데요. 이제 이런 경우 탭 줄을 가로로 스크롤할 수 있습니다.

여기에 선택한 탭이 보이도록 하는 처리도 더했습니다. 가로 스크롤만 제공하면 현재 선택한 탭이 화면 밖에 남을 수 있으므로, 선택 상태와 탭 줄의 표시 위치를 함께 다룬 셈입니다. 열린 파일이 많아도 현재 보고 있는 파일의 탭을 확인할 수 있도록 한 변경입니다.

이번 수정의 기준은 탭 개수 자체보다 탭 줄이 창에 들어오는지 여부입니다. 창 너비를 넘어갈 때 스크롤로 접근하고, 선택한 탭은 보이는 위치에 두는 방식으로 탐색 동작을 정리했습니다. 작은 화면이나 여러 파일을 함께 살펴보는 상황에서 의미가 있는 개선이지만, 실제 사용성이 얼마나 나아졌는지는 별도의 사용 확인이 필요합니다.

## 파일 내용 표시: 소스 코드에 문법 색상 적용

파일 탭의 소스 코드에는 문법 색상을 입혔습니다. 코드를 표시할 때 문법에 따라 색을 구분해, 내용을 읽는 데 시각적인 단서를 더한 기능입니다. 파일 탭에서 코드를 살펴볼 때 글자만 이어진 화면보다 구조를 구별하기 쉽도록 하는 데 목적이 있습니다.

일반 텍스트는 기존처럼 그대로 표시합니다. 파일 탭에 열린 내용이라고 해서 모두 코드처럼 색을 적용하지 않고, 소스 코드와 일반 텍스트의 표시 방식을 구분했습니다. 이번 변경을 설명할 때도 이 조건을 빼놓지 않는 것이 중요합니다.

지원 언어의 범위나 색상 테마, 큰 파일에서의 처리 성능은 제공된 커밋 정보에 포함되어 있지 않습니다. 따라서 이번 기록에서는 문법 색상 적용과 일반 텍스트 유지까지만 기능 범위로 잡았습니다.

## 이번 변경을 돌아보며

이번 작업은 내부 실행 구조와 파일을 읽는 화면을 함께 다뤘습니다. 화면과 Rust 실행부의 경계를 정리하면서 오류 복구를 보강했고, 데스크톱에서는 선택한 탭을 찾고 소스 코드를 읽는 동작을 개선했습니다.

기능이 추가됐다는 사실과 실제 사용에서 충분히 검증됐다는 판단은 구분해 두려고 합니다. 이번 세 커밋으로 바뀐 지점은 분명하지만, 오류 복구의 구체적인 범위와 다양한 파일에서의 표시 품질까지 단정할 근거는 아직 없습니다. 개발일지에도 확인된 변경과 남아 있는 확인 범위를 함께 남깁니다.
