# vica 개발일지: 채팅 모델 호출과 연결 설정 정리

2026년 11월 3일, vica에서는 채팅 요청을 맡길 모델을 직접 부르는 기능과 Chat 연결 설정을 손봤습니다. 채팅에서는 `@모델`로 해당 요청을 맡길 모델을 지정하고, 설정에서는 에이전트 탭에서 Chat 연결을 고르도록 했습니다. 기본 연결은 CLI로 정했습니다. 이번 개발일지는 최근 커밋 3개를 바탕으로, 요청 단위의 모델 선택과 연결 설정, 기록 정비로 나눠 정리했습니다.

## 채팅: 요청을 맡길 모델을 직접 부르기

채팅에 추가한 기능은 `@모델` 호출입니다. 사용자가 채팅에서 모델을 직접 불러 그 요청을 맡길 수 있도록 했습니다. 어떤 모델에 요청할지 채팅 안에서 표현할 수 있다는 점이 이번 변경의 핵심입니다.

여기서 구분할 부분은 선택의 범위입니다. 커밋 메시지는 “그 요청을 맡을 모델”을 직접 부른다고 설명합니다. 따라서 이번 기능은 요청 단위의 모델 지정으로 이해할 수 있습니다. 한 번 호출한 모델이 이후 대화에서도 계속 유지되는지, 대화 전체의 기본 모델까지 바꾸는지는 메시지만으로 확인할 수 없습니다.

사용 흐름으로 보면, 요청 내용과 함께 담당 모델을 지정할 수 있는 선택지가 생겼습니다. 다만 지원하는 모델 목록이나 정확한 입력 문법, 모델을 지정하지 않았을 때의 처리 방식까지 이번 기록에서 설명하기는 어렵습니다. `@모델`이라는 호출 방식이 추가됐다는 범위 안에서 변경 내용을 전해드립니다.

## 설정: 에이전트 탭에서 Chat 연결 선택하기

Chat 연결은 설정의 에이전트 탭에서 고르도록 했고, 기본값은 CLI로 정했습니다. 연결을 선택하는 위치와 기본으로 사용하는 연결 방식이 이번 설정 변경에 함께 담겼습니다.

채팅의 모델 호출과 설정의 연결 선택은 구분해서 볼 필요가 있습니다. 앞의 기능은 개별 요청을 맡길 모델을 지정하는 일이고, 이번 설정 변경은 Chat 연결을 어디에서 고르고 무엇을 기본값으로 둘지에 관한 일입니다. 둘 다 채팅 사용에 관련되지만 선택하는 대상과 범위가 다릅니다.

이 구분을 알아두면 변경 내용을 읽을 때도 덜 헷갈립니다. `@모델` 호출이 추가됐다고 해서 연결 설정 자체를 대체한다고 볼 수는 없습니다. 반대로 기본 연결이 CLI라는 사실만으로 모든 요청의 담당 모델까지 고정된다고 해석해서도 안 됩니다. 두 선택이 실제 실행 과정에서 어떻게 맞물리는지는 추가 확인이 필요한 부분입니다.

기존 사용자의 연결 설정이 그대로 유지되는지, CLI 외에 어떤 연결을 선택할 수 있는지도 커밋 메시지에는 나오지 않습니다. 이번 글에서는 에이전트 탭에서 Chat 연결을 선택한다는 점과 기본값이 CLI라는 점까지만 확실히 짚겠습니다.

## 기록: 채팅 연결 이력을 커밋 기준으로 맞추기

기능과 설정을 바꾸는 작업에 더해, 채팅 연결 기록도 커밋 기준으로 고쳤습니다. 이 작업은 새로운 채팅 기능을 더하기보다 변경 이력을 실제 커밋에 맞춰 정리하는 성격입니다.

연결 방식이나 기본값이 바뀌면 나중에 기록을 읽을 때 변경 시점을 구분할 수 있어야 합니다. 이번 정비는 그 이력을 커밋과 대조할 기준을 마련하는 작업으로 볼 수 있습니다. 다만 어떤 기록 항목을 어떻게 수정했는지까지는 제공된 메시지에서 확인되지 않아, 세부 수정 내용은 적지 않았습니다.

이번 작업에서 확인할 수 있는 변화는 요청별 모델 호출, 에이전트 탭의 Chat 연결 선택, 그리고 CLI 기본값입니다. 여기에 채팅 연결 기록을 커밋 기준으로 맞추는 정비가 뒤따랐습니다. 사용성이나 안정성이 얼마나 달라졌는지는 이 세 커밋만으로 판단하기 어렵지만, 모델을 부르는 기능과 연결을 고르는 설정이 각각 어떤 역할을 맡는지는 분명하게 정리할 수 있었습니다.
