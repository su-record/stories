# vica 개발일지: 삭제 전 확인과 컴패니언 알림 보강

2026년 11월 5일의 vica 변경은 에이전트의 자동 실행, 컴패니언의 알림과 실패 요약, 팀 노트 정리로 나뉩니다. 자동 모드에서도 파일 삭제 전에는 사용자에게 묻도록 했고, 컴패니언은 멈춘 에이전트와 오래 기다린 답, 하루 마무리를 알리도록 했습니다. 컴패니언 2단계 구현 내용도 팀 노트에 남겼습니다. 이번 일지는 최근 커밋 세 개의 메시지에서 확인할 수 있는 범위로 정리했습니다.

## 자동 실행 중에도 파일 삭제는 확인받습니다

에이전트의 자동 모드에 파일 삭제 전 확인 절차를 추가했습니다. 자동으로 작업을 진행하는 중이라도 파일을 지우려는 시점에는 사용자에게 묻습니다. 이번 변경으로 확인되는 경계는 명확합니다. 자동 모드를 선택했다는 이유만으로 파일 삭제까지 곧바로 진행하지는 않습니다.

작업을 맡기는 입장에서는 매번 개입하지 않아도 되는 편리함이 중요합니다. 다만 파일을 없애는 결정에는 별도의 확인 기회가 필요하다고 볼 수 있습니다. 이번 변경은 그 판단을 자동 모드의 동작에 반영한 것으로 읽힙니다.

물론 확인 절차가 생겼다고 해서 삭제와 관련된 모든 위험을 해결했다고 말할 수는 없습니다. 어떤 내용을 보여주며 묻는지, 사용자가 거절하면 작업을 어떻게 이어가는지는 커밋 메시지에 나와 있지 않습니다. 여기서 소개할 수 있는 변화는 **자동 모드에서도 삭제 전에 묻는다**는 점까지입니다.

## 컴패니언이 작업 상태와 마무리를 알립니다

컴패니언에는 멈춘 에이전트, 오래 기다린 답, 하루 마무리를 알리는 기능이 들어갔습니다. 작업 도중 살펴봐야 할 상태와 하루를 정리하는 시점이 알림 대상에 함께 포함됐습니다.

에이전트가 멈췄다는 알림은 사용자가 진행 상태를 다시 확인할 계기가 됩니다. 오래 기다린 답에 대한 알림 역시 기다림이 길어진 상황을 알아차리는 데 의미가 있습니다. 하루 마무리 알림은 개별 작업의 진행 상태와는 다른 시점을 다룹니다. 세 알림은 서로 역할이 다르므로, 하나의 알림 기능으로 뭉뚱그리기보다 각각 어떤 상황을 전하는지 구분해서 보는 편이 정확하겠습니다.

실패를 내장 모델로 요약하는 기능도 추가했습니다. 실패가 있었다는 사실과 그 내용을 요약하는 일은 구분할 필요가 있습니다. 이번 변경에는 후자가 포함돼 있습니다. 다만 요약이 원인을 얼마나 정확히 짚는지, 어느 정도의 정보를 담는지는 현재 자료만으로 판단하기 어렵습니다. 실패를 자동으로 복구하거나 해결책까지 제공한다고 확대해서 설명하지는 않겠습니다.

알림의 시간 기준과 전달 방식도 커밋 메시지에는 없습니다. 따라서 이번에는 구체적인 사용 화면이나 동작 순서를 가정하기보다, 컴패니언이 알리는 대상과 실패 요약 방식이 늘었다는 데 초점을 맞췄습니다.

## 컴패니언 2단계 구현을 팀 노트에 남겼습니다

문서 영역에서는 컴패니언 2단계 구현 내용을 팀 노트에 기록했습니다. 기능 변경과 함께 구현 내용을 문서로 남긴 작업입니다. 이후 팀에서 해당 단계를 검토하거나 다음 작업을 논의할 때 참고할 기록이 생겼다는 의미가 있습니다.

다만 노트의 상세 내용은 제공되지 않았으므로 설계 배경이나 검증 결과까지 정리됐다고 단정할 수는 없습니다. 이번 기록에서는 구현 내용을 남겼다는 사실만 다룹니다.

이번 변경을 함께 놓고 보면, 파일 삭제는 실행 전에 확인하고, 컴패니언은 작업 중 주의를 기울일 상황을 알리는 방향입니다. 실제 사용에서 확인 요청과 알림이 얼마나 적절하게 작동하는지는 별도로 살펴봐야 합니다. 현재 커밋에서 확인되는 진전은 사용자가 개입할 지점을 추가하고, 그와 함께 컴패니언 구현 기록을 남겼다는 것입니다.
