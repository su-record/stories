# vica 개발일지: 자동 커밋 설정과 Git 작성자 확인 흐름 다듬기

2026년 11월 10일의 최근 커밋 3개에서는 자동 커밋을 켜고 끄는 기능과 프로젝트의 커밋 작성자를 확인·수정하는 흐름을 손봤습니다. 자동 커밋 스위치를 누른 뒤 화면이 다시 그려지지 않던 문제도 수정했습니다. 이번 작업은 Git 관련 설정, 화면과 업데이트 처리, 테스트 안정성으로 나누어 정리해 보겠습니다.

## Git 설정: 자동 커밋 토글과 작성자 확인

자동 커밋을 켜거나 끌 수 있는 토글을 추가했습니다. 자동 커밋 사용 여부를 사용자가 선택할 수 있도록 만든 작업입니다. 기능을 추가한 뒤에는 스위치를 눌러도 화면이 다시 그려지지 않는 문제를 고쳤습니다.

토글은 조작한 결과를 화면에서 확인할 수 있어야 합니다. 눌렀는데 표시가 그대로라면 설정이 바뀌었는지 판단하기 어렵고, 다시 눌러야 하는지도 헷갈릴 수 있습니다. 이번 수정은 그런 혼란을 줄이는 데 필요한 작업이었습니다. 다만 커밋에 명시된 문제는 화면 재표시였으므로, 이를 설정 저장이나 자동 커밋 실행 자체의 오류로 넓혀 설명하지는 않겠습니다.

커밋 작성자를 다루는 경로도 추가했습니다. 이제 입력창 아래의 Git 버튼에서 프로젝트의 커밋 작성자를 확인하고 수정할 수 있습니다. 작업 중인 프로젝트에서 어떤 작성자로 커밋할지 살펴보고, 필요하면 같은 진입점에서 바꿀 수 있게 됐습니다.

자동 커밋 토글과 작성자 설정은 역할이 다릅니다. 하나는 자동 커밋 사용 여부를 정하고, 다른 하나는 커밋에 기록할 작성자를 다룹니다. 이번 변경에서는 두 설정을 사용자가 직접 확인하고 조정할 수 있는 접점을 마련했습니다. 작성자 설정의 저장 범위나 다른 Git 설정과의 우선순위는 제공된 커밋 정보에 없어, 여기서는 확인·수정 기능과 진입 위치까지만 소개합니다.

## 화면과 업데이트 처리: 충돌 정리와 사용 화면 개선

UI 쪽에서는 CSS 이름 충돌을 정리하고 터미널 화면을 개선했습니다. CSS 이름 충돌 정리는 스타일을 구분하는 과정에서 생긴 충돌을 다룬 작업입니다. 다만 어떤 선택자가 충돌했는지, 특정 화면의 모양이 어떻게 달라졌는지까지는 커밋 요약만으로 확인하기 어렵습니다.

터미널 화면 역시 개선 항목에 포함됐습니다. 세부 변경이 제공되지 않은 만큼 가독성이나 렌더링 성능이 좋아졌다고 단정하기보다는, 이번에 손본 화면 영역으로 남겨 두겠습니다. 자동 커밋 스위치의 재표시 수정과 함께 보면, 새 기능을 추가하는 동안 기존 화면의 문제도 같이 정리한 셈입니다.

업데이트 잠금 처리도 개선했습니다. 화면 작업과 같은 커밋에 담겼지만 별도로 구분할 필요가 있는 변경입니다. 잠금이 적용되는 조건이나 해제 시점에 관한 정보는 없으므로, 중복 업데이트를 완전히 방지했다거나 특정 실패 상황을 해결했다고 설명할 근거는 아직 없습니다.

## 테스트: lsp_rpc 경합 수정

테스트 영역에서는 `lsp_rpc` 테스트의 경합 문제를 수정했습니다. 자동 커밋 스위치 문제와 같은 수정 커밋에 포함돼 있지만, 대상은 서로 다릅니다. 스위치 수정은 사용자가 보는 화면을 다루고, 이 작업은 테스트에서 발생한 경합을 다룹니다.

이번 기록으로 확인할 수 있는 범위는 테스트 경합 수정까지입니다. 이를 실제 LSP 통신 전체의 안정성 개선으로 확대하거나, 테스트의 모든 불안정성이 해소됐다고 말하지는 않겠습니다.

최근 세 커밋에서 가장 구체적으로 달라진 사용 흐름은 자동 커밋을 선택하고, 입력창 아래 Git 버튼에서 프로젝트 작성자를 확인·수정할 수 있게 된 점입니다. 여기에 스위치의 화면 반영 문제를 바로잡고 CSS 충돌, 업데이트 잠금, 터미널 화면, 테스트 경합을 함께 손봤습니다. 기능 추가와 후속 수정을 영역별로 구분해 보니, 무엇이 새로 가능해졌고 무엇을 보완했는지가 조금 더 분명해졌습니다.
