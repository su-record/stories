# vica 개발일지: 대화 실행 분리와 화면·검색 상태 정리

2026년 11월 6일의 최근 커밋 8개에서는 CLI 대화를 앱 밖에서 실행하도록 옮기고, 데스크톱 패널과 웹 검색의 상태 표시를 손봤습니다. 시간에 따라 간헐적으로 실패하던 테스트 두 개도 기다림을 명시하는 방식으로 수정했습니다. 이번 기록은 변경 사항을 대화 실행, 화면과 상태 표시, 테스트와 릴리스로 묶어 정리합니다.

## 앱을 다시 켜도 이어지는 CLI 대화

가장 큰 기능 변경은 CLI 대화의 실행 위치입니다. CLI 대화를 앱 밖에서 실행하도록 옮겨, 앱을 다시 켜도 대화를 이어갈 수 있게 했습니다. 대화를 실행하는 쪽과 그 대화를 보여주는 앱의 관계를 바꾼 작업입니다.

이 변경에서 눈여겨볼 부분은 앱을 다시 여는 상황입니다. 앱의 실행 상태에 대화가 함께 묶이지 않도록 실행을 분리했고, 사용자가 돌아왔을 때 대화를 이어갈 수 있는 흐름을 마련했습니다. 다만 커밋 메시지만으로는 실행을 유지하는 구체적인 구조나 예외 상황까지 확인할 수 없습니다. 이번 일지에서는 앱 재실행 뒤에도 CLI 대화를 이어가도록 바뀌었다는 범위까지만 소개하겠습니다.

같은 작업에서 작업 표시도 다듬었습니다. 실행 구조와 화면 표시를 함께 손봤지만, 표시 방식의 세부 변경은 주어진 기록에 없어 따로 설명하지 않았습니다.

## 오른쪽 패널과 웹 검색의 끝맺음

데스크톱 화면에서는 오른쪽 패널이 열릴 때의 배치를 수정했습니다. 이제 좁은 창에서도 패널이 채팅 영역을 밀도록 했습니다. 창 너비가 좁다는 이유로 패널과 채팅의 배치 규칙이 달라지지 않게 맞춘 셈입니다. 설정 화면에서는 패널을 닫도록 해, 설정으로 이동했을 때의 패널 상태도 명확히 정했습니다.

채팅에서는 모델 회사 쪽에서 대신 수행한 웹 검색의 종료 표시를 고쳤습니다. 다음 내용이 도착하거나 답변이 끝나면 해당 검색도 끝난 것으로 표시합니다. 검색 뒤에 응답이 이어지는 경우와 답변 자체가 완료되는 경우를 모두 종료 판단에 반영한 변경입니다.

패널 수정은 화면 공간을 어떻게 나눌지에 관한 작업이고, 검색 수정은 진행 상태를 언제 끝낼지에 관한 작업입니다. 서로 다른 영역이지만 사용자가 보고 있는 화면을 현재 동작에 맞추려는 수정으로 묶을 수 있습니다. 웹 검색의 범위나 결과 품질을 바꾼 작업으로 확대해서 읽지는 않는 편이 정확합니다.

## 기다려야 하는 테스트를 명시하기

테스트에서는 시간에 따라 가끔 실패하던 두 개를 수정했습니다. 필요한 처리가 진행되기를 기다리도록 바꾼 것이 핵심입니다. 테스트가 확인하려는 결과와 실제 처리 시점 사이의 간격을 다룬 작업으로 볼 수 있습니다.

관련 지식 문서에는 백그라운드 쓰기를 기다리는 테스트 규칙도 남겼습니다. 테스트 코드 수정과 함께 기다림이 필요한 조건을 문서화한 점이 중요합니다. 이후 비슷한 테스트를 작성하거나 고칠 때 참고할 기준이 생겼기 때문입니다. 다만 이번 수정으로 모든 타이밍 문제가 해결됐다고 단정할 근거는 없습니다. 확인할 수 있는 변경 범위는 테스트 두 개와 해당 규칙의 기록입니다.

## 0.1.2 변경 내역과 작업 기록 정리

버전은 0.1.2로 올렸고, 변경 내역을 작성한 뒤 패널과 웹 검색 수정도 추가했습니다. 기능 변경만 반영하고 설명이 뒤처지지 않도록 릴리스 기록을 보완한 흐름입니다. 별도로 작업 기록도 갱신했습니다.

이번 8개 커밋에는 대화 실행 구조를 바꾸는 기능 작업부터 화면 배치, 검색 종료 표시, 테스트의 기다림 조건까지 함께 담겼습니다. 0.1.2 기록에서는 이 변경들을 구분해 읽는 것이 좋겠습니다. 사용자가 체감할 동작 변화와 개발 과정의 검증 규칙을 각각 남긴 작업이었습니다.
