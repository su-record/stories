# vibe 개발일지 #60 - AI 루프의 폭주 방어와 자율 복구 시스템 구축 (10개 커밋)

**작업 기간**: 2026-08-08 ~ 2026-08-10

안녕하세요, vibe 프론트엔드/CLI를 개발하는 Su입니다.

저는 **"Agent = Model + Harness"**라는 철학을 바탕으로 AI 코딩 도구 `vibe`를 만들고 있습니다. 모델이 아무리 뛰어난 지능을 가져도, 하네스(Harness)가 안전망과 방향타 역할을 해주지 않으면 실무 환경에서 믿고 맡기기 어렵기 때문입니다.

지난 3일간 진행된 10개의 커밋은 AI 에이전트의 실행 안정성을 극대화하고, 하네스 자체의 결함을 가감 없이 바로잡는 작업이 주를 이루었습니다. 개발 일지로 정리해보았습니다.

---

## 📝 이번 기간 작업 내용

### 1. AI 실행 루프 통제 및 폭주 방어 (Loop Control)
AI가 코드를 수정하다가 같은 실수를 반복하며 무한 루프에 빠지는 현상, 다들 경험해보셨을 겁니다. 이번 작업에서는 이를 구조적으로 방지하기 위한 두 가지 핵심 개편을 진행했습니다.

- **회전 계수(Loop Budget) 도입**: AI의 '단순 루프 횟수'와 '실제 코드 전진량'을 분리했습니다. AI가 의미 있는 코드 변화를 만들어내고 있는지, 아니면 제자리걸음을 하고 있는지 판단하는 회전 계수 알고리즘을 코드로 구현했습니다. (PR #53)
- **게이트 객체(Gate Objects) 상태 디스크 저장**: AI가 스스로 해결하지 못해 사람의 입력을 기다려야 할 때, 단순히 CLI 콘솔 메시지로만 남기지 않고 디스크 파일로 직렬화하여 남기도록 개선했습니다. 외부 스크립트나 GUI 도구가 에이전트의 대기 사유를 쉽게 파악할 수 있게 되었습니다. (PR #51)
- **주요 성과**: AI 무한 루프 폭주 방지 정확도 향상, 디스크 기반 게이트 추적 메커니즘 1종 추가

### 2. 자율 복구 및 전역 자산 안정성 강화 (Self-Healing)
- **전역 자산 검증 및 자동 복구 파이프라인**: vibe 패키지가 업그레이드될 때 전역(Global) 환경에 설치된 스킬, 훅 등 필수 자산이 정상적으로 반영되었는지 검증합니다. 만약 갱신 과정에서 자산이 손상되거나 누락되면 에러를 뱉고 종료하는 대신 스스로 감지하고 복구합니다. (PR #52)
- **주요 성과**: 패키지 업그레이드 후 발생하던 전역 자산 동기화 오류 100% 방어

### 3. 레거시 SPEC 보정 및 하네스 가드 결함 수정
- **레거시 SPEC 17개 전수 조사 및 보정**: 작성된 지 오래된 SPEC 문서 17개에서 검증 실패가 발생하여 원인을 추적했습니다. 분석 결과, 명세(SPEC) 자체의 문제라기보다는 명세를 검증하는 하네스의 가드(Guard) 로직에 결함이 있었습니다. 문서 탓을 하기 전에 가드를 먼저 올바르게 보정했습니다. (PR #50)
- **주요 성과**: 레거시 SPEC 17개 검증 가드 결함 보정, v3.2.21 및 v3.2.22 버전 정식 릴리스

## 💡 작업 하이라이트

### 하이라이트 1: "문서가 틀린 줄 알았는데, 하네스 가드가 거짓말을 하고 있었다"
10년 넘게 개발을 해오면서 항상 경계하는 것 중 하나가 "테스트 실패의 원인을 환경이나 문서 탓으로 돌리는 것"입니다. 

이번 레거시 SPEC 보정 작업(PR #50)이 딱 그랬습니다. 17개의 SPEC이 계속 실패하길래 처음엔 오래된 명세 문서들을 최신화해야겠다고 생각했습니다. 하지만 디버깅을 해보니 **가드(Guard)의 검증 조건이 오작동하여 정상적인 출력도 실패로 판단**하고 있었습니다. 

하네스가 AI를 제대로 가이드하려면 하네스 자체가 거짓말을 해서는 안 됩니다. 가드 결함을 깔끔하게 수정하고 나니 17개 레거시 SPEC이 모두 초록불을 켰습니다. 겸손함을 배운 중요한 순간이었습니다.

### 하이라이트 2: 폭주 방어와 전진량의 분리 (Loop Budget)

```
[ 기존 방식 ]
루프 실행 -> 횟수 차감 (MAX 10회) -> 10회 초과 시 강제 종료 (AI가 성과를 내는 중이어도 종료됨)

[ 개편된 방식 ]
루프 실행 -> 회전 계수(Loop Budget) 계산
  ├─ 의미 있는 파일 변화/전진 있음: 루프 예산 유지 (작업 지속)
  └─ 의미 없는 반복/제자리걸음 감지: 회전 계수 급증 -> 폭주 감지 및 게이트 객체 생성 후 대기
```

기존에는 단순 실행 횟수로 AI 루프를 제한하다 보니, 복잡한 리팩토링 중 일차적으로 성공적인 성과를 내고 있어도 횟수 제한에 걸려 끊기는 문제가 있었습니다. 

이번에 구현한 회전 계수 알고리즘은 **"AI가 실제로 앞으로 나아가고 있는가?"**를 진단합니다. 제자리걸음(Treading Water)을 칠 때만 예산을 빠르게 소진시켜 폭주를 막고, 정당한 전진량에 대해서는 충분한 회전 시간을 부여합니다.

AI에게 일을 맡길 때 인간이 느끼는 가장 큰 불안은 "제대로 하고 있는지 모르겠다"와 "혼자 이상하게 터지면 어쩌지?"입니다. vibe는 디스크에 상태를 투명하게 남기는 **게이트 객체**와 스스로를 치유하는 **자율 복구 로직**을 통해 이 불안을 지속적으로 해소해 나가겠습니다.
