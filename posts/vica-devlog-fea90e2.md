# vica 개발일지: 채팅 속 화면 부품과 데스크톱 실행 흐름 다듬기

11월 23~24일의 최근 커밋 5개에서는 채팅 AI가 A2UI 1.0 화면 부품으로 답하도록 확장하고, 실제 모델로 시험하며 드러난 표시·도구 판단 문제를 고쳤습니다. 데스크톱 화면 구성과 내장 엔진의 종료 처리도 함께 손봤습니다. 답변을 만드는 기능부터 그 답변을 보여 주고 앱을 닫는 과정까지 이어지는 작업이었습니다.

## 채팅 안에 들어온 화면 부품

채팅의 AI가 A2UI 1.0 화면 부품으로 답할 수 있게 했습니다. 이어 Vica-dev에서 실제 모델로 시험하면서, 답변이 끝나거나 채팅을 다시 그릴 때 부품이 제대로 남는지 확인했습니다.

이 과정에서 보관해 둔 결정 카드가 비는 문제를 찾았습니다. 채팅을 다시 그리는 코드가 카드 내용을 옮겨 담으면서 생긴 문제였고, `dom.js`의 `keepWhole`로 보관 블록을 통째로 받도록 고쳤습니다. 3D 설명 블록에도 같은 처리를 적용했습니다. 화면 부품을 생성하는 것에 더해, 다시 그린 뒤에도 내용을 유지하도록 수정한 셈입니다.

표의 정렬 기준도 좁혔습니다. 기존에는 “극한직업 (2019)”처럼 글 속에 숫자가 들어 있어도 숫자 열로 읽어 오른쪽에 붙이는 경우가 있었습니다. 이제 숫자 앞뒤에는 단위 정도의 짧은 글자만 허용합니다. 제목에 들어간 연도와 수치 데이터를 구분하려는 수정입니다.

## 도구 판단과 자동 승인에 둔 조건

회의 양식을 요청했는데 “계정에 연결되지 않음”이라는 이유로 거절하는 문제도 있었습니다. 해당 요청은 `calendar` 점수 0.55, 확신도 0.48로 분류됐습니다. 이 애매한 결과가 계정 연결이 필요한 요청이라는 판단으로 이어졌습니다.

계정·생성 도구는 점수가 0.7 이상이고 확신도도 낮지 않을 때만 분류 결과를 따르도록 바꿨습니다. Jev 활용 영상에서 정리한 “숫자는 판단, 행동은 규칙”을 적용한 부분입니다. 모델이 낸 점수를 곧바로 거절 사유로 쓰지 않도록 행동 조건을 명시했습니다. “화면으로 물어봐 줘”라는 표현을 컴퓨터 사용 요청으로 읽던 낱말 규칙도 함께 고쳤습니다.

자동 승인에서는 별도의 검토 조건을 추가했습니다. 무언가를 지우거나 비밀을 외부로 내보내는 셸 명령은 판단 모델이 먼저 읽도록 했습니다. 자동 승인 상태에서도 이런 명령에는 검토 단계를 두었습니다. 다만 이 변경만으로 위험한 명령을 모두 차단한다고 볼 수는 없습니다. 이번 커밋에서 추가한 범위는 실행 전 판단 모델의 검토입니다.

## 데스크톱 구성과 실행 과정 정리

데스크톱 화면은 ChatGPT 데스크톱 앱과 비슷한 방향으로 정리했습니다. 창 머리와 왼쪽 패널을 손보고, 루틴·플러그인 페이지도 함께 다듬었습니다. 채팅 화면에 부품이 추가되는 작업과 나란히 앱의 바깥쪽 구성도 정리한 것입니다.

실행 과정에서는 서로 다른 세 가지 문제를 고쳤습니다. 내장 엔진은 앱과 함께 종료되도록 했고, 다음 입력을 추천할 때는 8B 모델을 띄우지 않도록 바꿨습니다. Node 24 환경에서 npm을 읽는 문제도 수정했습니다. 화면에서 바로 보이는 변화는 아니지만, 앱 종료와 추천 기능, 실행 환경에 각각 걸려 있던 문제들입니다. 다만 제공된 커밋 기록에는 성능 측정값이 없어 자원 사용량이나 응답 속도의 개선 폭까지 말하기는 어렵습니다.

## 실제 모델 시험에서 남긴 기록

이번 작업에서는 A2UI 기능 추가 직후 실제 모델로 시험한 내용이 후속 수정으로 이어졌습니다. 카드 내용이 비는 현상, 글 속 숫자의 정렬, 회의 양식 요청의 거절처럼 구체적인 사례를 기준으로 수정했습니다.

Jev 활용 영상 분석과 Vica-dev 실행 방법도 기록했습니다. 코드 변경과 함께 시험 환경을 실행하는 방법과 판단 규칙의 배경을 남겼다는 점에서, 이후 같은 동작을 확인할 때 참고할 자료가 생겼습니다.
