# vica 개발일지: 파일 보기와 대화 처리 구조 정리

10월 29~30일에는 vica 데스크톱의 파일 열기 방식, 대화 처리 구조, 앱 아이콘을 손봤습니다. 사이드바의 파일을 보기 전용 탭으로 열 수 있게 하고, PDF를 그리는 데 pdf.js를 사용했습니다. 내부에서는 대화 실행과 저장을 분리하고 데이터 검증을 강화했습니다. 이번 글에서는 최근 커밋 세 개를 파일 탐색, 대화 처리, 앱 외형으로 나눠 정리해 보겠습니다.

## 파일 탐색: 보기 전용 탭과 PDF 렌더링

사이드바에서 파일을 열면 보기 전용 탭으로 표시하도록 바꿨습니다. 사이드바에서 선택한 파일을 탭으로 확인하는 흐름이 생긴 셈입니다. 여기서 범위는 분명히 짚고 넘어가려고 합니다. 이번에 추가한 것은 파일을 열어 내용을 보는 기능이며, 파일을 수정하는 편집 기능까지 포함한 것은 아닙니다.

PDF는 pdf.js로 렌더링합니다. 파일을 탭으로 여는 동작과, 그 탭 안에서 PDF 내용을 그리는 처리를 함께 다룬 변경입니다. PDF처럼 별도의 렌더링 처리가 필요한 형식에도 표시 방식을 마련했다는 점이 이번 파일 보기 작업의 핵심입니다.

다만 PDF를 그린다는 사실만으로 검색이나 주석, 확대·축소 같은 세부 기능까지 지원한다고 설명할 수는 없습니다. 제공된 커밋 정보에서 확인되는 범위는 보기 전용 탭과 pdf.js 렌더링까지입니다. 사용 가능한 기능을 소개할 때도 이 경계를 지키는 편이 정확하겠습니다.

## 대화 처리: 실행과 저장의 역할 분리

대화 처리 쪽에서는 실행과 저장을 분리했습니다. 대화를 실행하는 일과 데이터를 저장하는 일을 구분하도록 내부 구조를 정리한 작업입니다. 사용자에게 바로 보이는 화면 변경과 달리, 이 부분은 대화를 처리하는 코드의 책임을 나누는 데 초점이 있습니다.

실행과 저장은 서로 이어지는 작업이지만, 코드에서 살펴봐야 할 역할은 다릅니다. 이번 분리는 이후 대화 처리 코드를 수정하거나 문제를 확인할 때 두 역할을 구별하는 기준이 됩니다. 다만 실제로 어떤 함수나 모듈로 나눴는지, 저장 시점이 달라졌는지는 커밋 요약만으로 알 수 없습니다. 구조를 분리했다는 설명을 넘어 동작 변화까지 추정하지는 않겠습니다.

같은 영역에서 데이터 검증도 강화했습니다. 실행과 저장의 경계를 정리하는 작업에 더해, 다루는 데이터를 검사하는 부분도 보강한 것입니다. 검증 대상과 규칙은 제공된 정보에 없으므로 특정 오류를 막았다고 단정하기는 어렵습니다. 이번 기록에서는 책임 분리와 검증 강화가 함께 이뤄졌다는 점을 남겨 둡니다.

## 앱 외형: 얇은 외곽선에 붙인 캐릭터

앱 아이콘은 얇은 외곽선 안에 캐릭터를 붙인 모양으로 바꿨습니다. 파일 보기나 대화 처리처럼 기능을 다루는 변경과는 별개로, 앱을 나타내는 시각 요소를 손본 작업입니다.

아이콘의 인상이 어떻게 달라졌는지는 실제 이미지를 함께 봐야 판단할 수 있습니다. 지금 확인할 수 있는 변화는 얇은 외곽선과 캐릭터를 결합한 구성입니다. 가독성이 좋아졌다거나 더 눈에 잘 띈다는 평가는 덧붙이지 않고, 이번에 적용한 형태를 기준으로 기록합니다.

이번 작업에서 화면에 드러나는 변화는 파일을 여는 탭과 앱 아이콘입니다. 내부에서는 대화 실행·저장의 역할과 데이터 검증을 정리했습니다. 기능 추가와 내부 정리가 함께 들어간 만큼, 파일 보기의 지원 범위와 대화 처리의 실제 동작을 구분해서 설명하는 것이 이번 개발일지의 기준이었습니다.
