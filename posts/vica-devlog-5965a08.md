# vica 개발일지: 디스크에 둔 우편함과 서버 실행 기록, 0.0.2

2026년 10월 30일, vica에 터미널의 우편함과 폴더 식별 방식을 손보는 변경, 서버에서 돌린 vibe의 실행 기록과 캐시를 남기는 변경이 들어갔습니다. 릴리스 버전은 0.0.2로 올렸습니다. 이번 일지는 최근 커밋 세 개를 바탕으로, 터미널에서 다루는 데이터와 서버 실행 자료, 릴리스로 나눠 정리했습니다. 구체적인 구현이나 테스트 결과까지는 커밋 메시지에 드러나지 않아, 확인되는 변경 범위 안에서 소개합니다.

## 터미널: 우편함을 디스크에 두고 폴더를 구분하기

터미널 영역에서는 Vica 우편함을 디스크에 두도록 바꿨습니다. 우편함 데이터를 어디에 둘지에 관한 변경입니다. 다만 커밋 메시지만으로는 기존 저장 방식이나 새 파일 구조를 알 수 없습니다. 저장 경로, 기록 시점, 다시 읽어오는 방식도 이번 기록에서는 설명하기 어렵습니다.

디스크에 둔다는 사실과 복구를 보장한다는 주장은 구분해야 합니다. 프로세스가 끝난 뒤에도 우편함을 그대로 복원하는지, 기록 도중 실행이 끊기면 어떻게 처리하는지는 별도 확인이 필요합니다. 그래서 이번 변경을 소개하면서 “이제 우편함을 잃어버리지 않습니다”라고 약속할 단계는 아닙니다. 확인할 수 있는 내용은 우편함의 저장 위치를 디스크로 잡았다는 점까지입니다.

같은 영역에서 이름이 같은 폴더의 아이디도 나눴습니다. 표시되는 폴더 이름이 같더라도 아이디로 구분하도록 손본 내용입니다. 이름이 겹치는 폴더를 다룰 때 어떤 대상을 가리키는지 구별하는 데 관련된 변경이라고 볼 수 있습니다.

다만 아이디를 경로에서 만드는지, 별도로 발급하는지는 메시지에 없습니다. 폴더를 옮기거나 이름을 바꿨을 때 아이디가 유지되는지도 알 수 없고요. 이번에는 ‘같은 이름의 폴더를 서로 구분한다’는 범위로 이해하는 편이 정확합니다.

## 서버: vibe 실행 기록과 캐시 남기기

서버 쪽에서는 그곳에서 돌린 vibe의 실행 기록과 캐시를 남겼습니다. 실행 기록은 서버에서 수행한 작업의 흔적이라는 점에서, 캐시는 실행 과정에서 생긴 자료라는 점에서 각각 살펴볼 대상입니다.

여기서 캐시를 남겼다는 사실만으로 실행 속도가 빨라졌다고 말할 수는 없습니다. 이후 실행에서 캐시를 재사용하는지, 재사용한다면 어떤 조건을 적용하는지에 관한 정보는 주어지지 않았습니다. 실행 기록 역시 어떤 항목을 담는지, 어디까지 보관하는지는 확인되지 않습니다.

이번 일지에서는 서버에서 돌린 vibe의 기록과 캐시를 남긴 변경으로 정리하겠습니다. 실제 운영 방식을 설명하려면 저장 위치와 보관 범위, 캐시 사용 조건을 함께 확인해야 합니다. 자료를 남기는 변경과 그 자료를 활용하는 동작을 섞어 쓰지 않으려는 이유입니다.

## 릴리스: 버전 0.0.2

같은 날 릴리스 버전을 0.0.2로 올렸습니다. 최근 세 커밋에서 확인되는 작업은 우편함의 디스크 저장, 같은 이름을 가진 폴더의 아이디 구분, 서버의 vibe 실행 기록·캐시 보관입니다.

버전 변경만으로 배포 완료나 테스트 통과 여부까지 판단할 수는 없습니다. 이번 개발일지는 변경 내용을 소개하는 기록으로 남기고, 저장과 복원 동작이나 캐시 재사용 효과는 코드와 실행 결과를 확인한 뒤 다루겠습니다. 특히 우편함을 다시 읽는 과정과 폴더 아이디의 유지 조건은 후속 기록에서 구체적으로 설명할 만한 부분입니다.
