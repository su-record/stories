# vica 개발일지: 이미지 영역 리뷰와 실패 단계 재시도

2026년 11월 9일의 vica 최근 커밋 3개는 리뷰 대상의 위치를 짚는 기능, 실패한 워크플로 단계를 다시 시도하는 기능, 병합과 작업 방식에 관한 기록을 다룹니다. 이번 일지는 커밋 메시지에서 확인할 수 있는 변경 범위를 중심으로 정리했습니다. 실제 코드와 실행 결과는 제공되지 않았으므로, 세부 동작이나 검증 여부까지 확인한 내용은 아닙니다.

## 리뷰: 이미지의 어느 부분인지 함께 표시하기

리뷰 댓글에서 이미지 영역을 주석으로 표시할 수 있도록 변경했습니다. 이미지에 관한 의견을 남길 때, 댓글이 가리키는 위치를 함께 다루는 기능입니다.

이 기능의 활용 지점은 비교적 분명합니다. 이미지 전체에 대한 의견과 특정 부분에 대한 의견은 서로 구분할 필요가 있습니다. 영역을 지정할 수 있으면 리뷰를 읽는 사람이 글로 적힌 위치 설명만 보고 대상을 찾아야 하는 부담을 줄일 수 있습니다. 다만 이는 기능에서 기대할 수 있는 효과이며, 실제로 리뷰 시간이 줄었거나 의사소통 오류가 감소했다고 확인한 것은 아닙니다.

커밋 메시지만으로는 영역을 어떤 방식으로 선택하는지, 주석을 나중에 수정할 수 있는지까지 알 수 없습니다. 이번 변경은 우선 **리뷰 댓글에 이미지의 특정 영역을 연결하는 기능이 추가됐다**는 범위로 정리하는 것이 정확하겠습니다.

## 워크플로: 실패한 단계를 다른 회사로 재시도하기

워크플로 쪽에서는 실패한 단계를 다른 회사로 재시도할 수 있도록 변경했습니다. 메시지에 드러난 재시도 대상은 ‘실패한 단계’이고, 재시도할 때 바꿀 수 있는 대상은 ‘회사’입니다.

여기서 눈여겨볼 점은 재시도 경로에 회사 변경이 포함됐다는 것입니다. 같은 조건으로 한 번 더 실행하는 경우와 달리, 다른 회사를 선택해 실패한 단계를 다시 시도하는 경로를 마련한 셈입니다. 다만 회사라는 구분이 시스템에서 정확히 어떤 실행 주체나 설정을 뜻하는지는 제공된 정보에 나오지 않아, 특정 서비스나 공급자로 바꿔 부르지는 않겠습니다.

재시도 기능은 실패 이후의 처리를 다루는 만큼 실행 범위도 중요합니다. 앞선 단계의 결과를 유지하는지, 실패한 단계 이후에는 어떻게 이어지는지, 회사 변경을 누가 선택하는지는 별도로 확인해야 합니다. 이번 메시지로 확인할 수 있는 내용과 실제 사용 흐름에서 점검할 내용을 나누어 두면, 기능의 완성도를 과장하지 않고 변경 사항을 설명할 수 있습니다.

## 작업 기록: 병합한 레인과 작업 방식의 결정 남기기

기록 영역에서는 병합된 레인과 작업 방식에 관한 결정을 남겼습니다. 기능 변경 두 건과 함께, 병합 및 작업 방식에 관한 내용을 정리한 커밋입니다.

다만 기록에 어떤 레인이 포함됐는지, 작업 방식에 관해 무엇을 결정했는지는 메시지에 담겨 있지 않습니다. 따라서 특정 협업 규칙을 도입했다거나 개발 절차를 바꿨다고까지 설명하기는 어렵습니다. 이번 변경에서 확인되는 것은 **병합한 레인과 작업 방식의 결정을 기록했다는 사실**입니다.

이 기록을 읽을 때는 병합 대상과 결정 내용을 구분해 보는 것이 좋겠습니다. 어떤 작업이 합쳐졌는지와 앞으로 어떤 방식으로 일하기로 했는지는 서로 다른 정보이기 때문입니다. 구체적인 결정 이유까지 남아 있는지는 기록 본문을 확인할 필요가 있습니다.

이번 세 커밋은 리뷰의 위치 정보, 실패 후 재시도 경로, 작업 결정의 기록이라는 영역으로 묶을 수 있습니다. 후속 확인에서는 이미지 영역 표시의 실제 사용 흐름과 재시도 시 실행 범위를 먼저 살펴보면 좋겠습니다. 커밋 메시지에 담긴 기능이 사용자에게 어떤 동작으로 이어지는지 확인해야, 다음 개발일지에서는 구현 결과와 남은 제약도 더 구체적으로 이야기할 수 있겠습니다.
