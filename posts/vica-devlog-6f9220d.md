# vica 개발일지: 컴퓨터 작업의 판단 흐름과 화면 결과 보존

2026년 11월 24일의 최근 커밋 세 개는 컴퓨터 작업의 판단 흐름을 손보고, 큰 화면 결과의 원문과 조사 기록을 남기는 데 집중했습니다. 윈도 창의 요소를 알아보는 판단 단계와 데스크톱 채팅에서 작업을 시작하는 순서를 함께 수정했습니다. 이번 개발일지는 커밋 메시지에서 확인할 수 있는 변경 범위를 기준으로 정리했습니다.

## 윈도 창의 글·입력칸·클릭 요소를 판단 단계에서 인식

컴퓨터 작업의 판단 모델 단계에서 윈도 창의 글, 입력칸, 클릭할 요소를 알아보도록 수정했습니다. 화면에 어떤 내용이 적혀 있는지, 어디에 입력할 수 있는지, 무엇을 누를 수 있는지를 판단 단계에서 다루는 변경입니다.

이 구분은 화면을 보고 다음 동작을 정할 때 필요합니다. 글은 읽어야 할 정보이고, 입력칸과 클릭 요소는 동작의 대상이기 때문입니다. 이번 수정의 초점은 이런 요소를 판단 모델이 알아보게 하는 데 있습니다. 다만 커밋 메시지만으로는 인식 정확도나 지원하는 창의 범위까지 알 수 없습니다. 모든 윈도 앱에서 안정적으로 동작한다고 말하기에는 근거가 부족합니다.

데스크톱 채팅에서 요청한 컴퓨터 작업도 판단 모델을 먼저 거치도록 고쳤습니다. 창의 요소를 인식하는 수정이 판단 단계의 역할을 다룬다면, 이 변경은 채팅에서 시작한 작업의 실행 순서를 다룹니다. 두 수정을 함께 보면 무엇을 판단할지와 언제 판단할지를 각각 손본 셈입니다.

사용자에게 익숙한 채팅 경로에서도 판단 모델이 먼저 돌도록 했다는 점이 이번 변경의 핵심입니다. 다만 이후 동작이 얼마나 나아졌는지, 기존에 어떤 실패가 있었는지는 제공된 기록에 없습니다. 여기서는 판단 단계가 앞서 실행되도록 수정했다는 사실까지 전하겠습니다.

## 30KB를 넘는 화면 결과도 원문 보존

데스크톱에서는 화면 결과가 30KB를 넘을 때 원문을 남기도록 수정했습니다. 이번 기록에서 확인할 수 있는 구체적인 기준은 ‘30KB 초과’입니다.

화면 결과가 길어지면 나중에 판단 과정을 살펴볼 때 원래 어떤 내용이 들어 있었는지 확인할 필요가 있습니다. 원문을 보존하면 큰 결과도 다시 검토할 근거로 삼을 수 있습니다. 판단 모델의 실행 순서를 고치는 일과 별개로, 그 판단에 관련된 화면 결과를 되짚어볼 수 있게 하는 변경입니다.

다만 원문을 어디에 저장하는지, 얼마나 오래 보관하는지, 사용자 화면에는 어떤 형태로 보여주는지는 커밋 메시지에 나오지 않습니다. 원문 보존을 곧바로 표시 방식의 변경이나 결과 처리 성능의 개선으로 해석하지는 않았습니다.

## 재검토·실제 앱 확인·정정 내용을 지식 문서에 기록

지식 문서에는 솔라 컴퓨터 유즈 재검토와 실제 앱 확인, 챗지피티 로그인 조사, 정정 기록을 남겼습니다. 코드 수정과 함께 조사와 확인 내용을 문서로 정리한 작업입니다.

여기서 구분해 읽어야 할 부분은 조사 기록과 기능 구현입니다. 챗지피티 로그인을 조사했다는 사실만으로 로그인 지원을 완료했다고 볼 수는 없습니다. 실제 앱을 확인했다는 기록 역시 모든 사용 경로를 검증했다는 뜻은 아닙니다. 구체적인 조사 결론은 제공되지 않았으므로 이번 일지에서는 기록한 주제까지만 다뤘습니다.

정정 내용을 함께 남긴 점도 짚고 싶습니다. 검토 과정에서 바로잡은 내용을 문서에 두면 이후 작업에서 이전 설명을 그대로 전제하는 일을 줄이는 데 도움이 됩니다. 어떤 내용을 어떻게 정정했는지는 해당 문서에서 확인해야 합니다.

이번 작업은 판단 모델이 창의 요소를 알아보도록 하고, 채팅에서 시작한 컴퓨터 작업에도 판단 단계를 먼저 적용한 변경입니다. 여기에 큰 화면 결과의 원문 보존과 조사·정정 기록을 더했습니다. 실제 앱에서의 성공률이나 로그인 지원 범위까지 확인된 것은 아니므로, 실행 흐름의 수정과 검증 결과는 구분해서 보시면 좋겠습니다.
