# vibe 개발일지 #66 - 안전하고 통제 가능한 에이전트 루프 구축 (11개 커밋)

**작업 기간**: 2026-08-22 ~ 2026-08-23

안녕하세요, Su입니다.

AI 에이전트에게 자율적인 피드백 루프(Loop)를 쥐여줄 때 가장 두려운 순간은 언제일까요? 바로 **"에이전트가 통제를 벗어나 엉뚱한 방향으로 무한 루프를 돌며 토큰을 탕진할 때"**입니다. 

"Agent = Model + Harness"라는 vibe의 철학처럼, 모델이 자유롭게 탐색하되 안전망을 벗어나지 않도록 하네스(Harness)가 브레이크와 가이드라인을 잡아줘야 합니다. 이번 11개의 커밋에서는 **루프 실행의 안전장치(Safety Gate)**와 **프론트엔드 중심의 시각적 검증(Visual Verification)** 체계를 집중적으로 다듬었습니다.

---

## 📝 이번 기간 작업 내용

이번 작업은 주로 에이전트 자동 루프의 신뢰성과 안전성을 높이는 데 초점을 맞췄습니다.

### 1. 루프 안전장치 및 실행 모드 고도화 (Safety & Session)
- **시운전 게이트(Trial Gate) 도입**: 새로 등록되거나 처음 실행되는 루프는 무조건 **최대 2바퀴(2 iterations)**만 돌고 안전하게 멈추도록 강제했습니다. 검증되지 않은 루프가 백그라운드에서 폭주하는 사고를 원천 차단합니다.
- **세션 축 per-iteration 모드 추가**: 한 번의 세션 호출당 딱 한 바퀴만 돌고 컨텍스트를 정리하는 모드를 구현했습니다. 외부 스케줄러나 cron 환경에서 단계별 상태를 통제하기 훨씬 수월해졌습니다.

### 2. 검증 체계 및 환경 버그 수정 (Verification & Infra)
- **`verify=visual` 렌더 검증 추가**: 프론트엔드 코드의 진짜 완료 기준은 '빌드 에러 없음(exit code 0)'이 아니라 '화면에 제대로 그려졌는가'입니다. 렌더링 결과를 평가 기준으로 삼고, 프로세스 게이트는 정상 exit code로 닫는 구조를 잡았습니다.
- **Cron PATH 및 통합 배럴 참조 수정**: cron 백그라운드 실행 시 PATH 환경변수가 누락되어 커맨드를 찾지 못하던 문제와, 루프 게이트 모듈이 통합 배럴 파일을 거치며 발생하던 불필요한 의존성 문제를 해결했습니다.

### 3. 안정화 릴리즈
- **v3.2.47, v3.2.48 배포**: 게이트 픽스 및 시각 검증 로직 반영.

## 💡 작업 하이라이트

### 1. "처음엔 딱 두 바퀴만" — 시운전 게이트(Trial Gate)
에이전트에게 자율성을 부여할 때 가장 위험한 구간은 루프를 **'처음 걸었을 때'**입니다. 프롬프트나 탈출 조건에 사소한 오류만 있어도 에이전트는 밤새 같은 작업을 맴돌 수 있습니다.

```
[ 루프 트리거 ] 
       │
       ▼
[ Trial Gate 검사 ] ─── (첫 실행인가?) ──► YES ──► 최대 2바퀴 제한 후 대기 (사용자 피드백 대기)
       │
       ▼ NO (검증 완료된 루프)
[ 일반 루프 실행 ] ──► 목표 달성 or 설정된 max-iterations까지 순항
```

이제 vibe는 루프가 처음 등록되면 2회 시운전 후 강제로 멈춰 결과를 보고합니다. 사용자가 "의도대로 잘 도네"를 확인한 뒤에야 전폭적인 루프를 허용하는 안전 장치입니다.

### 2. 프론트엔드를 위한 `verify=visual`
기존 CI나 하네스는 보통 `npm test`나 `tsc`의 exit code 0을 통과 기준으로 삼습니다. 하지만 프론트엔드에서는 **런타임 에러 없이 빈 화면(White Screen)이 떠도 exit code는 0**입니다.

이번에 추가된 `verify=visual`은 실제 렌더링 결과물(스크린샷, DOM 트리 구조)을 캡처하여 모델이 시각적으로 목표 명세와 일치하는지 확인한 후 Done을 선언하도록 개선했습니다. 프론트엔드 전문 하네스로서 vibe의 색깔이 돋보이는 지점입니다.
