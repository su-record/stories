# vibe 개발일지 #67 - 스킬 무결성 검증과 파이프라인 견고화 (10개 커밋)

**작업 기간**: 2026-08-23 ~ 2026-08-26

안녕하세요! AI 코딩 하네스 도구 `vibe`를 만들고 있는 Su입니다.

"Easy vibe coding + Minimum quality guaranteed"라는 철학 아래, 이번 며칠 동안은 사용자가 체감하는 안정성과 내부 파이프라인의 견고함을 다지는 작업에 집중했습니다. 에이전트가 제 역할을 하려면 하네스가 흔들리지 않아야 하니까요.

이번 개발일지에서는 스킬 무결성 검증 도입 배경과 CI 게이트 정상화 등 10개 커밋의 여정을 공유합니다.

## 📝 이번 기간 작업 내용

이번 작업은 크게 **스킬 무결성 및 최적화**, **스펙 검증 UX 개선**, **파이프라인 & 코어 버그 수정** 3개 영역으로 묶을 수 있습니다.

### 1. 스킬 시스템 & 무결성 관리
- **설치된 스킬 무결성 검증 (`feat/skill-integrity`)**: 사용자 환경에 설치된 스킬 파일이 배송본(npm 패키지 기본 제공본)과 일치하는지 해시 기반으로 검증하는 기능을 추가했습니다. 무거운 `SKILLS.lock` 파일을 새로 도입하는 대신 가벼운 검증 방식을 채택했습니다.
- **RTM 등 경량 함수 6종의 좁은 배럴화 (`fix/rtm-barrel`)**: 통합 배럴(`index.ts`)을 경유하면서 불필요한 의존성까지 끌고 오던 가벼운 유틸리티 6종을 별도의 좁은 배럴 엔트리로 분리해 임포트 오버헤드를 줄였습니다.

### 2. 스펙 파이프라인 시각화
- **SPEC 승인 전 구조 다이어그램 자동 삽입 (`feat/spec-structure-diagram`)**: 모듈이나 도메인 경계가 바뀌는 아키텍처 변경 SPEC의 경우, 승인 단계 이전에 구조 다이어그램을 자동으로 생성·부착하도록 개선했습니다. 사람과 에이전트 모두 변경 범위를 직관적으로 파악할 수 있게 되었습니다.

### 3. 파이프라인 안정화 & 버그 수정
- **CI 릴리즈 게이트 4종 누락 수정 (`ci/run-declared-gates`)**: 문서상 선언되어 있던 릴리즈 품질 게이트 4종이 실제 CI 워크플로우에서 누락되어 돌지 않던 심각한 설정을 바로잡았습니다.
- **Frontmatter 따옴표 파싱 버그 수정 (`fix/frontmatter-quote-stripping`)**: 루프 설정의 frontmatter에서 따옴표를 제대로 벗겨내지 않아 `schedule`이나 `test_command` 설정이 깨지던 엣지 케이스를 해결했습니다.

## 💡 작업 하이라이트

### 1. 스킬 무결성 검증: 왜 `SKILLS.lock`을 만들지 않았는가?

사용자 프로젝트에서 vibe 스킬 파일이 임의로 수정되었거나 구버전 상태로 남아 있어 에이전트가 예기치 않게 오동작하는 케이스가 종종 있었습니다.

처음에는 `package-lock.json`처럼 스킬의 메타데이터와 해시를 기록하는 `SKILLS.lock` 도입을 검토했습니다. 하지만 하네스가 지나치게 무거워지면 vibe 코딩 본연의 "경쾌함"을 해치게 됩니다.

```text
[기존 검토안]
SKILLS.lock 생성 및 관리 -> 파일 생성 오버헤드 + 충돌 해결 피로도 증가

[최종 채택안]
배송본 매니페스트 해시와 런타임 diff 비교 -> 별도 락파일 없이 상태 즉시 진단
```

결과적으로 lock 파일 없이도 배송본의 기준 해시와 로컬 파일을 대조해 변경 여부만 깔끔하게 감지하도록 구현했습니다. 하네스는 단순할수록 강력하다는 원칙을 다시 한번 되새긴 작업이었습니다.

### 2. "선언만 되어 있던" 릴리즈 게이트 4종 정상화

솔직하게 털어놓는 부끄러운 배움입니다. 코드 리뷰와 릴리즈 가이드에는 4가지 품질 게이트가 정의되어 있었지만, 정작 GitHub Actions 워크플로우 재작성 과정에서 조건문 누락으로 해당 잡들이 스킵되고 있었습니다.

- 스펙 포맷팅 게이트
- 린트/타입 엄격 게이트
- 스킬 인터페이스 호환성 게이트
- 최소 번들 사이즈 게이트

다행히 이슈를 발견하고 즉시 CI 파이프라인을 복구했습니다. "문서에 적힌 규칙은 반드시 CI 코드로 강제되어야 한다"는 기본을 다시금 점검한 계기였습니다.
