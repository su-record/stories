# vica 개발일지: 실행 상태를 기록하고 화면에 드러내기

10월 27일부터 29일까지의 최근 커밋 10개에서는 터미널에서 실행 중인 작업을 기록하고, 그 상태를 CLI와 데스크톱 화면에 보여 주는 작업을 진행했습니다. 실행이 끝난 Claude 작업을 이어 가는 동작도 추가했습니다. 이번에는 상태를 수집하는 기반, 사용자에게 보여 주는 화면, 조작 방식의 근거를 나누어 정리해 보겠습니다.

## 실행 여부와 에이전트 활동을 따로 기록했습니다

상태 관리 쪽에서는 `vicad`에 실행 기록을 저장하고, Claude hook을 통해 에이전트의 활동 상태를 매기도록 했습니다. 여기에 zsh 셸 통합을 더해 명령 실행의 시작과 끝을 보고하게 했습니다. 셸에서 명령이 실행되는 구간과 에이전트의 활동 상태를 각각 다룰 수 있도록 기반을 마련한 셈입니다.

에이전트 활동이 바뀐 시각도 저장합니다. 현재 상태와 함께 그 상태로 전환된 시점을 남기는 변경입니다. 다만 이번 커밋 목록만으로는 이 시각을 모든 화면에서 어떻게 활용하는지까지 확인할 수 없어서, 여기서는 저장 기반을 추가했다는 범위로 소개하겠습니다.

상태 판정과 함께 실제 Claude Code에서 확인한 활동 상태 전이도 문서에 기록했습니다. 구현한 판정 방식과 실제 실행 중 관찰한 변화를 대조할 때 참고할 자료입니다. 이번 기록의 확인 대상은 Claude Code이며, 다른 에이전트까지 같은 방식으로 검증했다고 보기는 어렵습니다.

## CLI에서는 상태와 근거를, 데스크톱에서는 작업 화면을 갖췄습니다

`vica ls`는 칸마다 실행 상태와 활동 상태를 표로 보여 주도록 바뀌었습니다. 상태를 판단한 근거도 함께 표시합니다. 목록에서 현재 상황을 살펴볼 때, 표시된 상태뿐 아니라 그 판단의 바탕도 확인할 수 있게 한 변경입니다.

데스크톱에는 터미널 화면과 상태·탐색기·git 사이드바를 만들었습니다. CLI의 표와 데스크톱의 사이드바는 표현 방식이 다르지만, 이번 작업에서는 둘 다 터미널 작업의 상태와 주변 정보를 드러내는 영역을 넓혔습니다.

다만 화면을 만들었다는 사실과 각 영역의 세부 동작이 모두 완성됐다는 평가는 구분하려고 합니다. 이번 기록에서 확실히 말할 수 있는 진척은 터미널 화면과 해당 사이드바를 구성했다는 점입니다.

## 끝난 Claude 실행을 이어 가는 준비 동작을 추가했습니다

holder에는 종료된 Claude 실행의 이어 하기 명령을 빈 프롬프트에 채우는 기능을 넣었습니다. 자동으로 실행을 재개하는 기능은 아니며, 사용자가 이어 하기 명령을 입력할 수 있도록 프롬프트를 준비하는 동작입니다.

특히 대상이 **빈 프롬프트**라는 조건을 함께 짚어 두고 싶습니다. 기능을 설명할 때 “Claude 작업을 이어 준다”라고만 쓰면 자동 재개처럼 읽힐 수 있어서요. 이번 변경은 종료된 실행과 다음 입력 사이를 잇는 구체적인 입력 보조 기능으로 정리하는 편이 정확합니다.

## 디자인 결정과 키 선택의 근거를 남겼습니다

설계 문서에는 디자인 시안 확정 결정을 17절에 기록했고, 한 줄 사이드바와 다른 에이전트에게 넘기기 동작도 정리했습니다. 이는 설계 기록입니다. 다른 에이전트에게 넘기는 기능까지 이번에 구현했다고 설명하지는 않겠습니다.

키 설정에서는 에이전트 CLI의 Ctrl 키 사용을 직접 측정하고, 리더 키로 `Ctrl-q`를 선택한 근거를 남겼습니다. 이후 키 구성을 다시 검토할 때 당시 확인한 내용을 찾아볼 수 있도록 한 작업입니다.

이번 변경으로 실행과 활동 상태를 기록하는 기반, 이를 확인하는 CLI와 데스크톱 화면, 종료된 Claude 실행을 이어 갈 입력 동작이 갖춰졌습니다. 설계로 남긴 부분과 구현한 부분을 구분하면서, 실제로 확인한 동작의 범위도 개발 기록에 함께 남겼습니다.
