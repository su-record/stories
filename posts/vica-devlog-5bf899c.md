# vica 개발일지: 날짜별 사용량과 채팅 흐름 정리

2026년 11월 9일, vica에 사용량 확인과 채팅 관련 기능을 추가하고 업데이트 알림 표시를 다듬었습니다. 최근 커밋 3개를 기능별로 묶어 보면, 사용량을 날짜 단위로 살펴보는 기능, 채팅 명령과 봇 선택 처리, 터미널과 알림의 표시 방식으로 나눌 수 있습니다. 이번 글에서는 확인할 수 있는 변경 사항을 중심으로 정리하겠습니다.

## 사용량: 날짜별 조회와 채팅 팝업

Grok·Antigravity·Muse의 사용량을 날짜별로 확인할 수 있도록 했습니다. 사용량을 살펴볼 때 어느 날짜에 해당하는 값인지 구분할 수 있게 된 점이 이번 변경의 핵심입니다. 세 서비스가 이번 날짜별 사용량 기능의 대상에 포함됐습니다.

채팅 쪽에는 사용량 팝업을 추가했습니다. 날짜별 사용량이 기록을 나누어 보는 기능이라면, 팝업은 채팅 영역에서 사용량을 확인하는 접점에 해당합니다. 두 변경 모두 사용량과 관련돼 있어 한 영역으로 묶었지만, 조회 단위와 표시 방식이라는 서로 다른 부분을 다룹니다.

다만 커밋 요약만으로는 날짜를 나누는 시간대나 팝업에 표시되는 세부 항목까지 알 수 없습니다. 비용, 토큰 수, 요청 수 가운데 무엇을 보여 주는지 임의로 덧붙이지는 않겠습니다. 이번 기록에서는 세 서비스의 날짜별 사용량과 채팅의 사용량 팝업이 추가됐다는 범위까지 전합니다.

## 채팅: `/goal` 추가와 봇 선택 처리 정리

채팅에는 `/goal` 명령을 추가했습니다. 새로운 명령이 생겼다는 점은 확인할 수 있지만, 입력 형식이나 실행 뒤의 동작은 제공된 변경 요약에 담겨 있지 않습니다. 따라서 구체적인 사용 예시보다는 명령 추가 자체를 이번 작업 내용으로 남깁니다.

봇 선택은 판단 모델만 맡도록 변경했습니다. 이 부분은 역할을 누가 담당하는지 명시한 변경입니다. 적용 범위는 ‘봇 선택’이며, 채팅의 모든 처리를 판단 모델 하나로 통합했다는 뜻으로 넓혀 읽어서는 안 됩니다. 기능 이름이 짧게 적힌 변경일수록 실제로 바뀐 경계를 구분해서 기록하려고 합니다.

캐시도 개선했습니다. 다만 어떤 데이터를 캐시하는지, 저장이나 재사용 조건이 어떻게 달라졌는지는 요약만으로 확인하기 어렵습니다. 응답 속도가 얼마나 빨라졌는지, 중복 요청이 얼마나 줄었는지 말할 측정값도 없습니다. 캐시 처리에 개선이 들어갔다는 사실과 성능 효과에 대한 평가는 구분해 두겠습니다.

## 표시 방식: 터미널 크기 상한과 업데이트 알림

터미널에는 크기 상한을 적용했습니다. 크기에 제한을 두는 변경이지만, 상한값과 적용 조건은 이번 자료에 포함돼 있지 않습니다. 특정 화면 크기나 출력 상황에서의 동작을 설명하려면 추가 확인이 필요합니다. 여기서는 터미널 크기를 다루는 제약이 추가됐다는 점을 기록합니다.

업데이트 알림에서는 노트에 포함된 마크다운 기호를 제거하도록 수정했습니다. 알림에 노트를 보여 줄 때 마크다운 기호가 그대로 남는 부분을 손본 작업입니다. 변경 대상은 업데이트 알림에 표시되는 노트이므로, 릴리스 노트 원문이나 다른 화면의 마크다운 처리까지 바뀌었다고 확대해서 설명하지는 않겠습니다.

## 이번 작업을 마치며

이번 변경에는 새 기능과 표시 방식 수정이 함께 들어갔습니다. 사용량은 날짜별 조회와 팝업으로 확인 경로를 더했고, 채팅은 `/goal` 명령과 봇 선택 담당을 정리했습니다. 터미널 크기 상한과 알림 노트의 마크다운 기호 제거도 같은 날 반영했습니다.

아직 세부 동작이나 성능 수치를 설명할 자료는 부족합니다. 그래서 이번 개발일지는 무엇이 추가되고 어느 영역이 바뀌었는지에 초점을 맞췄습니다. 실제 사용법을 안내할 때는 `/goal`의 입력 형식, 사용량 집계 기준, 터미널 상한값을 확인한 뒤 구체적으로 설명하는 편이 정확하겠습니다.
