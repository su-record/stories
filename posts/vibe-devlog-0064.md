# vibe 개발일지 #64 - 스킬 생태계 경계와 컨텍스트 비용 가시화 (12개 커밋)

**작업 기간**: 2026-08-17 ~ 2026-08-20

안녕하세요, Su입니다.

AI 코딩 하네스를 만들다 보면 언제나 "에이전트에게 어디까지 자동으로 쥐어줄 것인가?"라는 고민에 부딪힙니다. 스킬이 많아지면 기능은 풍부해지지만, 상시 컨텍스트(Context Window)를 갉아먹고 예기치 않은 부작용을 낳기도 하죠. 

이번 기간에는 스킬 시스템의 경계를 명확히 하고, 컨텍스트 비용을 투명하게 리포트하도록 개선했습니다. 동시에 배럴 파일 참조로 인한 런타임 크래시와 설치 호환성 문제도 함께 손봤습니다.

---

## 📝 이번 기간 작업 내용

이번 12개 커밋은 크게 3가지 영역으로 나누어 진행했습니다.

### 1. 스킬 시스템 경계 정의 & 컨텍스트 비용 가시화
- **상시 컨텍스트 비용 보고 (`feat(status)`)**: 에이전트가 활성화한 스킬들이 차지하는 상시 토큰/컨텍스트 비용을 `/vibe status` 등에서 직관적으로 확인할 수 있도록 추가했습니다.
- **생태계 스킬 경계 정리 (`feat(skills)`)**: 모든 스킬을 무조건 자동 주입하지 않고, 권유(P3) 수준과 사용자 명시적 opt-in(P4) 매핑으로 경계를 나누어 컨텍스트 낭비를 막았습니다.
- **skills.sh 호환성 및 비대화 방지 (`fix(skills)`)**: `skills.sh` 설치 표기 3종 중 1종만 지원하던 파싱 버그를 수정하고, 비대화형 플래그 누락 건을 바로잡았습니다.

### 2. 게이트 디스패치 런타임 안정화
- **배럴 임포트 의존성 크래시 수정 (`fix(dispatch)`)**: 게이트 검사 로직이 통합 배럴(index) 파일을 거쳐가며 불필요한 무거운 모듈 의존성을 끌고 와 런타임에서 죽던 문제를 해결했습니다. 직접 경로 임포트로 격리했습니다.

### 3. 하네스 헌법(Constitution) 및 E2E 문서화
- **수치 출처 규율 정립 (`docs(constitution)`)**: "근거 없는 숫자는 쓰지 않는다"는 원칙을 세우고, 출처가 불분명했던 가이드라인 내 수치 3건을 제거했습니다.
- **E2E 1순위 브라우저 도구 설치 명시 (`docs(e2e)`)**: 에이전트 브라우저 기반 E2E 테스트 도구의 설치 경로와 우선순위를 명확히 문서화했습니다.

## 💡 작업 하이라이트

### 1. "스킬이 늘어날수록 에이전트가 둔해진다" — 컨텍스트 비용 보고 & Opt-in

vibe의 핵심 철학은 **"Agent = Model + Harness"**입니다. 하네스가 좋은 도구를 쥐어주는 건 좋지만, 과도한 시스템 프롬프트 주입은 모델의 추론 성능을 저하시킵니다.

```
[ Before ]
모든 생태계 스킬 자동 로드 → 상시 컨텍스트 점유율 증가 → 모델 집중도 저하

[ After ]
P1/P2 (핵심 도구)    : 상시 가용 + status 명령어로 상시 토큰 비용 가시화
P3 (생태계 권유)    : 필요 시점에만 에이전트에 제안
P4 (Opt-in 매핑)    : 사용자가 명시적으로 활성화할 때만 로드
```

이제 개발자는 현재 활성화된 스킬들이 내 컨텍스트 윈도우를 얼마나 쓰고 있는지 즉시 확인하고 최적화할 수 있습니다.

### 2. 통합 배럴(Barrel) 파일의 배신과 런타임 격리

가벼워야 할 게이트 디스패치 단계가 특정 환경에서 모듈 로딩 실패로 크래시되는 문제가 있었습니다. 

원인은 편의상 사용하던 `index.ts` 배럴 파일이었습니다. 게이트 단계를 통과할 때 쓰지도 않는 무거운 서브시스템 모듈까지 한꺼번에 평가(evaluate)되면서, 해당 환경에 없는 선택적 의존성을 요구했던 것이죠. 

단순하지만 중요한 교훈이었습니다. **하네스의 게이트웨이나 경량 훅에서는 절대 통합 배럴을 거치지 않고, 세부 엔트리포인트를 직접 임포트**하도록 구조를 격리했습니다.
