# vica 개발일지: 코드 지도 생성과 작은 수정의 실행 경로 정리

2026년 11월 12일의 최근 커밋 네 개는 chat의 코드 지도 생성과 작은 수정 실행, 그리고 이를 뒷받침하는 기록 정리에 관한 작업입니다. 코드 지도는 외부의 vibe 프로그램 없이 앱 안에서 만들도록 옮겼고, 수정할 자리를 이미 찾은 경우에는 실행 모델을 한 번 호출해 작은 수정을 마치도록 바꿨습니다. 관련 이전 기록과 지도 캐시, 호출 경로 측정 및 판단 엔진 비교 기록도 함께 갱신했습니다.

이번 글은 제공된 커밋 메시지를 바탕으로 정리했습니다. 구체적인 구현 방식이나 측정 수치는 확인할 수 없어, 변경된 범위와 아직 판단하기 어려운 부분을 나눠 적었습니다.

## 코드 지도 생성 책임을 앱 안으로 옮겼습니다

chat 영역에서는 코드 지도를 만드는 경로를 리팩터링했습니다. 커밋 메시지에서 확인되는 핵심은 **vibe 프로그램 없이 앱 안에서 코드 지도를 생성한다**는 점입니다. 코드 지도 생성이라는 작업을 앱 내부에서 맡도록 경계를 바꾼 셈입니다.

여기서 범위를 넓혀 해석하지는 않으려고 합니다. 이번 변경만으로 vibe와 관련된 모든 의존성을 없앴다고 말할 수는 없습니다. 확인되는 대상은 코드 지도 생성 경로이며, 다른 기능까지 같은 방식으로 옮겼는지는 별도 확인이 필요합니다.

이 작업과 함께 코드 지도 이전 기록과 지도 캐시도 갱신했습니다. 생성 경로를 옮기는 코드 변경에 관련 기록과 캐시 정리를 묶어서 볼 수 있습니다. 다만 캐시의 구조를 바꿨는지, 저장된 내용을 새로 갱신했는지까지는 메시지에 드러나지 않습니다. 따라서 이번 일지에서는 캐시 정책 개선이나 적중률 향상 같은 효과를 덧붙이지 않았습니다.

## 찾은 자리의 작은 수정은 한 번의 실행 호출로 마칩니다

수정 실행 쪽에서는 적용 조건이 분명한 기능을 추가했습니다. **수정할 자리를 이미 찾았고, 변경 규모가 작은 경우** 실행 모델 한 번의 호출로 수정을 끝내도록 했습니다.

이 조건이 중요합니다. 모든 코드 수정이 한 번에 끝난다는 뜻도, 위치를 찾는 과정까지 포함해 모델을 딱 한 번만 호출한다는 뜻도 아닙니다. 이번 변경이 다루는 범위는 찾은 자리에서 작은 수정을 실행하는 단계입니다. 탐색과 실행을 구분해 읽어야 기능의 범위를 과장하지 않을 수 있습니다.

커밋 메시지에는 ‘작은 수정’을 나누는 구체적인 기준이나 실패했을 때의 처리 방식은 담겨 있지 않습니다. 여러 파일에 걸친 수정에도 적용되는지 역시 확인할 수 없습니다. 현재 확인할 수 있는 성과는 특정 조건의 수정 작업을 실행 모델 한 번 호출로 마치는 경로를 마련했다는 데 있습니다.

## 실행 경로 측정과 판단 엔진 비교 기록도 갱신했습니다

기능 변경과 맞물려, 한 번 호출하는 경로의 측정 기록과 판단 엔진 비교 기록을 갱신했습니다. 실행 방식을 바꾼 작업과 그 경로를 측정한 기록을 같은 작업 묶음으로 살펴볼 수 있게 됐습니다.

다만 기록을 갱신했다는 사실만으로 속도나 비용이 개선됐다고 결론 내릴 수는 없습니다. 비교 대상, 측정 조건, 결과 수치가 제공되지 않았기 때문입니다. 판단 엔진 사이에 어떤 차이가 있었는지, 특정 엔진을 선택했는지도 이번 메시지만으로는 알 수 없습니다.

이번 변경은 앱 내부의 코드 지도 생성과, 이미 찾은 위치에서의 작은 수정 실행에 초점이 맞춰져 있습니다. 관련 기록과 캐시까지 함께 정리했다는 점도 포함됩니다. 실제 사용에서 얼마나 빨라졌는지, 한 번 호출하는 경로가 어디까지 안정적으로 적용되는지는 구현과 측정 결과를 확인한 뒤에 이야기할 부분으로 남겨두겠습니다.
