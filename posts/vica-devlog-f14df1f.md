# vica 개발일지: 왼쪽 탐색 영역과 루틴 화면 정리

2026년 11월 24일의 최근 커밋 3개에서는 vica 데스크톱의 왼쪽 탐색 영역과 루틴 화면을 손봤습니다. 루틴·플러그인 화면을 열 때 접힌 목록이 펼쳐지도록 바꾸고, 왼쪽 아이콘 줄은 ByMin의 아이콘·색·정렬에 맞췄습니다. 루틴 화면에서는 프로젝트 표시와 상태 이름, 삭제 단추를 바로잡았습니다. 바로 쓰는 루틴의 내용도 비카 혼자 할 수 있는 일로 바꿨습니다.

이번 기록은 커밋 순서 대신 화면을 오가는 흐름과 루틴을 확인하는 흐름으로 묶었습니다. 같은 왼쪽 영역의 변경이라도 목록이 펼쳐지는 동작과 아이콘의 표현은 구분해서 살펴보겠습니다.

## 화면 이동: 루틴·플러그인을 열면 왼쪽 목록 펼치기

왼쪽 목록이 접혀 있는 상태에서 루틴이나 플러그인 화면을 열면, 이제 해당 목록을 펼칩니다. 화면을 여는 동작에 목록을 펼치는 동작을 연결한 변경입니다. 접힌 목록을 따로 여는 조작 없이 화면과 목록을 함께 볼 수 있도록 했습니다.

적용 범위는 루틴·플러그인 화면에 들어가는 상황입니다. 왼쪽 목록을 항상 펼쳐 두도록 바꾼 것은 아닙니다. 사용자가 목록을 접을 수 있는 기존 흐름과, 특정 화면을 열었을 때 목록을 보여 주는 동작을 구분해서 봐야 합니다.

왼쪽 아이콘 줄의 모습도 함께 정리했습니다. 아이콘 종류와 색, 정렬을 ByMin과 같은 기준으로 맞췄습니다. 목록 펼치기가 화면 이동에 따른 동작을 다룬다면, 이 작업은 이동할 곳을 고르는 아이콘 줄의 표현을 다룹니다.

두 변경은 모두 왼쪽 탐색 영역에 속하지만 역할은 다릅니다. 한쪽은 화면을 열었을 때 무엇을 보여 줄지 정하고, 다른 쪽은 아이콘을 어떤 모습으로 배치할지 맞춥니다. 이번에는 이 두 부분을 함께 다뤘으며, 탐색이 실제로 얼마나 편해졌는지는 커밋 기록만으로 단정하지 않겠습니다.

## 루틴 화면: 표시와 조작 요소 바로잡기

루틴 화면에서는 프로젝트 표시, 상태 이름, 삭제 단추를 수정했습니다. 프로젝트와 상태는 화면의 내용을 읽을 때 확인하는 정보이고, 삭제 단추는 루틴을 관리할 때 사용하는 조작 요소입니다. 같은 화면 안에 있지만, 정보를 보여 주는 부분과 사용자의 동작을 받는 부분을 나눠 손본 셈입니다.

다만 제공된 커밋 메시지에는 프로젝트 표시가 어떤 조건에서 잘못됐는지, 상태 이름을 무엇에서 무엇으로 바꿨는지까지 담겨 있지는 않습니다. 삭제 단추의 구체적인 수정 방식도 확인할 수 없습니다. 따라서 이번 일지에서는 세 항목을 바로잡았다는 범위까지만 기록합니다. 삭제 확인 절차나 루틴의 상태 처리 방식까지 달라졌다고 확대해서 설명하지는 않겠습니다.

## 바로 쓰는 루틴: 비카 혼자 할 수 있는 일로 변경

루틴 화면의 수정과 함께, 바로 쓰는 루틴의 내용도 바꿨습니다. 이번에 잡은 기준은 **비카 혼자 할 수 있는 일**입니다. 화면의 표시를 고치는 작업과 별개로, 바로 사용할 수 있도록 내놓는 루틴의 내용 자체를 조정했습니다.

여기서 구분할 점은 루틴의 내용을 바꾼 것과 비카의 실행 능력을 새로 추가한 것은 다르다는 점입니다. 이번 커밋 기록이 알려 주는 것은 전자입니다. 어떤 루틴이 추가되거나 빠졌는지, 실행 과정이 어떻게 달라졌는지는 메시지에 없어 개별 사례를 덧붙이지 않았습니다.

이번 변경을 확인할 때도 범위를 나눠 보면 좋겠습니다. 화면 이동에서는 접힌 목록이 펼쳐지는지, 아이콘 줄에서는 ByMin과 표현이 맞는지, 루틴 화면에서는 표시와 삭제 단추가 바로잡혔는지가 각각의 확인 지점입니다. 바로 쓰는 루틴은 그 내용이 비카 혼자 할 수 있는 일이라는 기준에 맞는지를 살펴볼 부분으로 남깁니다.
