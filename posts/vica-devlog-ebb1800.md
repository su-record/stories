# vica 개발일지: Windows 연동과 설계 초안 보존, 파일 삭제 흐름 정리

2026년 11월 8일의 최근 커밋 9개는 Windows 실행 환경, 설계 초안과 리뷰 의견, 파일 삭제, 업데이트 처리에 걸쳐 있습니다. 이번 변경에서는 운영체제별로 구분해야 할 부분을 나누고, 이전 작업을 검토하거나 정리할 때 필요한 동작을 다뤘습니다. 커밋 메시지에서 확인할 수 있는 범위를 바탕으로 영역별로 정리해 보겠습니다.

## Windows 터미널 연동과 배포 파일 분리

Windows에서는 named pipe를 통해 터미널의 결정 응답을 전달할 수 있도록 지원했습니다. 터미널에서 내린 결정을 주고받는 경로에 Windows named pipe가 추가된 셈입니다. 다만 메시지만으로는 어떤 결정 항목까지 지원하는지 알 수 없어, 세부 동작은 여기서 단정하지 않겠습니다.

셸의 완료 표시 줄을 확인하는 테스트도 Windows에서 실행하도록 바꿨습니다. 통신 경로 지원과 함께 셸 동작을 검사하는 범위도 Windows로 넓혔습니다. 테스트를 실행하도록 한 변경과 실제 테스트 결과는 구분해야 하므로, 이번 기록에서는 실행 대상이 확대됐다는 점까지 담습니다.

배포 쪽에서는 macOS와 Windows 릴리스 파일을 서로 분리했습니다. 운영체제별 산출물을 구분해 다루도록 정리한 변경입니다. 구체적인 파일명이나 배포 경로는 제공된 메시지에 없지만, 두 환경의 릴리스 파일을 별도로 유지하려는 방향은 분명합니다.

## 이전 설계 초안은 남기고, 의견은 삭제할 수 있게

설계 리뷰에서는 이전 초안에 달린 의견을 살펴볼 수 있도록 과거 설계 초안을 보존했습니다. 초안이 바뀐 뒤에도 리뷰 의견이 어떤 설계를 대상으로 했는지 확인하려면 당시 내용이 필요합니다. 이번 변경은 그 검토 맥락을 유지하는 데 초점을 맞췄습니다.

동시에 이전 초안의 의견도 계속 삭제할 수 있게 했습니다. 초안을 보존하는 동작과 의견을 삭제하는 동작을 함께 챙긴 점이 중요합니다. 과거 내용을 검토할 수 있게 남겨 두면서도, 해당 초안에 속한 의견을 정리하는 기능은 유지했습니다. 보존 범위를 넓히는 과정에서 기존 삭제 동작을 놓치지 않도록 다룬 변경으로 읽힙니다.

## 탐색기 삭제와 미추적 파일 처리

파일 관리에서는 탐색기에서 삭제하는 항목과 미추적 파일을 안전하게 휴지통으로 보내는 처리를 다뤘습니다. 삭제를 요청한 파일을 어떻게 처리할지에 관한 변경으로, 탐색기 삭제뿐 아니라 미추적 파일도 대상에 포함했습니다.

다만 커밋 메시지만으로 모든 삭제 상황에서 복구가 보장된다고 말할 수는 없습니다. 이번 작업은 해당 파일들을 휴지통으로 보내는 흐름의 안전성을 다듬은 것으로 정리하는 편이 정확하겠습니다.

## 실행 중인 버전을 기준으로 업데이트 결과 판단

업데이트 결과는 현재 실행 중인 버전을 기준으로 판단하도록 바꿨습니다. 업데이트 과정에서 얻은 정보와 실제 실행 상태를 연결하는 기준을 명확히 한 변경입니다.

이전 버전의 `vicad`가 유지된 경우에는 그 상태도 알리도록 했습니다. 업데이트 결과를 이해할 때 무엇이 실제로 실행되고 있고, 어떤 구성 요소가 이전 버전으로 남았는지는 서로 구분할 필요가 있습니다. 이번 변경은 그 차이를 결과에 드러내도록 다뤘습니다.

## 병렬 작업의 진행 상황과 결정 기록

문서에는 병렬 lane의 진행 상황과 11월 8일의 라우팅 결정을 기록했습니다. 이어 병합된 lane과 Windows decision pipe도 문서에 반영했습니다. 작업 중의 판단뿐 아니라 병합 이후 상태까지 기록 범위에 포함한 것입니다.

이번 9개 커밋은 구현 변경과 그 판단을 남기는 문서 작업이 함께 묶여 있습니다. 다만 실제 사용 중의 안정성이나 테스트 통과 여부까지 확인할 자료는 없습니다. 이번 개발일지는 Windows 지원 범위가 넓어지고, 리뷰·삭제·업데이트에서 상태를 보존하거나 구분하는 동작이 정리됐다는 데까지 기록해 둡니다.
