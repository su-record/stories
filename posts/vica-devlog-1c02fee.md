# vica 개발일지: 설정과 모델 실행 흐름을 정리했습니다

2026년 11월 9일의 최근 커밋 6개에서는 설정, 모델 선택과 배포, 코워크와 알림을 함께 손봤습니다. 채팅 쪽에는 OpenRouter와 Kimi의 캐시 정보를 다루는 변경이 들어갔고, 0.1.8 릴리스 노트도 현재 변경 사항에 맞췄습니다. 이번 글에서는 커밋 순서 대신 실제로 손댄 영역을 따라 정리해 보겠습니다.

## 설정 규칙과 모델 선택

설정 영역에서는 항목들을 한 규칙으로 정리하면서 내장 모델, 단축키, 외부 연결 없이 쓰는 기능을 더했습니다. 설정의 기준을 맞추는 작업과 선택지를 추가하는 작업이 함께 들어간 셈입니다. 다만 커밋 메시지만으로는 외부 연결 없이 사용할 수 있는 기능의 범위까지 알 수 없어, 모든 기능이 오프라인에서 동작한다고 소개하지는 않겠습니다.

작업 방식인 `work-styles`에서는 판단 모델이 맡는 역할을 넓혔습니다. 회사를 지정하고 구체적인 모델은 정하지 않은 단계에서, 판단 모델이 모델 선택을 맡도록 했습니다. `vica-laya`의 방식 선택도 판단 모델의 역할에 포함했습니다.

여기서 중요한 조건은 ‘회사만 지정한 단계’라는 점입니다. 모든 단계의 모델 선택을 바꾼 것으로 읽기보다는, 구체적인 모델을 지정하지 않은 경우에 누가 선택할지를 정한 변경으로 이해하시면 됩니다. 설정 항목을 정리한 작업과 함께 보면, 사용자가 지정하는 부분과 판단 모델에 맡기는 부분을 다듬은 흐름입니다.

## vica-laya 실행 파일과 모델을 한 묶음으로

`vica-laya`에서는 실행 파일과 모델을 묶음 하나로 받도록 바꿨습니다. 실행에 쓰는 파일과 모델을 같은 배포 단위로 다루게 된 것이 이번 변경의 핵심입니다.

이 변경은 앞서 소개한 방식 선택과는 구분할 필요가 있습니다. 판단 모델 관련 작업이 어떤 방식을 선택할지에 관한 내용이라면, 묶음 다운로드는 실행 파일과 모델을 어떻게 받을지에 관한 내용입니다. 같은 `vica-laya` 영역이지만 선택과 배포라는 서로 다른 지점을 손봤습니다. 다운로드 크기나 속도에 관한 수치는 제공된 기록에 없으므로, 성능 개선까지 이야기하기는 어렵습니다.

## 코워크를 만들고 스킬을 등록하는 흐름

사용 흐름 쪽에는 새 코워크 만들기와 스킬 등록 기능이 들어갔습니다. 코워크 생성과 스킬 등록은 각각 별도로 짚을 만한 추가 사항입니다. 다만 생성 화면의 구성이나 스킬 등록 절차까지는 커밋 메시지에 드러나지 않아, 이번 일지에서는 기능이 추가됐다는 범위로 소개합니다.

같은 작업에서 토스트를 개편하고 종료·업데이트 관련 처리도 정리했습니다. 새 기능을 시작하는 지점뿐 아니라 알림을 확인하거나 앱을 종료하고 업데이트하는 지점까지 손본 셈입니다. 구체적인 알림 문구나 종료 조건은 기록만으로 확인하기 어려워, 사용 경험이 얼마나 달라졌는지는 단정하지 않겠습니다.

## 채팅 캐시 정보와 0.1.8 문서

채팅에서는 OpenRouter에 캐시 표시를 붙이고, Kimi의 캐시 수치를 읽도록 수정했습니다. 두 변경은 캐시 정보를 다룬다는 공통점이 있지만, 하나는 표시를 추가한 것이고 다른 하나는 수치를 읽는 처리라는 차이가 있습니다. 이를 곧바로 캐시 적중률이나 비용 절감 효과로 설명할 근거는 없습니다.

마지막으로 0.1.8 릴리스 노트를 현재 바뀐 내용에 맞게 수정했습니다. 기능을 추가한 기록과 사용자가 읽는 배포 문서가 어긋나지 않도록 문서도 함께 갱신한 것입니다.

이번 일지는 제공된 커밋 메시지에서 확인할 수 있는 범위로 작성했습니다. 구현 세부나 테스트 결과는 담지 않았지만, 설정과 모델 선택, 실행 묶음 배포, 코워크와 알림, 채팅 캐시 정보까지 이번 변경이 닿은 영역은 나누어 살펴볼 수 있었습니다.
