# vibe 개발일지 #68 - 컨텍스트 다이어트와 윈도우 줄바꿈의 저주 (12개 커밋)

**작업 기간**: 2026-08-25 ~ 2026-08-29

안녕하세요, Su입니다. 

"Agent = Model + Harness"라는 철학으로 vibe를 개발하면서 매주 느끼는 점은, **하네스의 역할은 AI에게 잔소리를 늘어놓는 것이 아니라 명확한 경계(Guardrail)와 신뢰할 수 있는 도구를 쥐어주는 것**이라는 사실입니다.

이번 며칠간은 AI에게 주입하던 불필요한 컨텍스트를 과감히 덜어내고, 스펙 작성의 사실 근거 체계를 정비하며, Windows 환경에서 발생하던 기괴한 줄바꿈 버그를 잡는 데 집중했습니다. 12개의 커밋에 담긴 기술적 고민과 배움을 공유합니다.

## 📝 이번 기간 작업 내용

### 1. 컨텍스트 엔지니어링: 규칙과 판단의 분리
- **상시 지침 다이어트 (PR #90)**: 시스템 프롬프트에 들어있던 "일반적인 코딩 조언(클린 코드 원칙, 주석 스타일 등)"을 대거 걷어냈습니다. 모델이 자체적으로 판단해야 할 영역과 하네스가 강제해야 할 '절대 규칙'을 명확히 분리했습니다.
- **불필요한 토큰 소비 감소**: 상시 주입 토큰을 줄여 모델의 지시 추종력(Instruction Following)과 응답 속도를 개선했습니다.

### 2. 스펙 신뢰도 & 품질 게이트 강화
- **Spec Grounding 태그 도입 (PR #88)**: 스펙 작성 단계에서 컨텍스트 소스마다 `[확인]`, `[해석]`, `[모름]` 3단계 근거 등급을 명시하도록 했습니다. 모호한 가정을 사실인 양 코딩하는 환각(Hallucination)을 원천 차단합니다.
- **Mermaid 렌더 검증 게이트 (PR #89)**: "마크다운 네이티브 렌더니까 검증할 필요 없다"는 안일한 판단을 반성하고 검증 게이트를 추가했습니다.
- **Node 20 호환성 패치**: CI 환경에서 jsdom v30이 Node 20과 충돌하던 이슈를 jsdom 25 버전으로 핀(pin)하여 해결했습니다.

### 3. CLI 훅 & Windows 환경 안정성
- **agy 프롬프트 stdin 전환 (PR #91)**: Windows `cmd.exe`에서 멀티라인 프롬프트 전달 시 `\n`(LF)에서 명령어가 절단되던 치명적 버그를 `argv` 대신 `stdin` 스트림 파이프로 전환하여 수정했습니다.
- **Codex Notify 설치기 리팩터링**: 블록 분할 로직을 별도 헬퍼 함수로 추출하고 단위 회귀 테스트를 보강했습니다.

## 💡 작업 하이라이트

### 1. "규칙이 아니라 판단이다" — 상시 지침 다이어트

AI 코딩 도구를 만들다 보면 욕심이 생겨 상시 프롬프트에 온갖 훈수를 두게 됩니다. *"가독성 좋은 코드를 작성해라"*, *"변수명은 명확하게 지어라"* 같은 것들이죠.

하지만 최신 프론티어 모델들은 이미 뛰어난 코딩 판단력을 가지고 있습니다. 이런 뻔한 조언들은 토큰만 낭비할 뿐 아니라, 정작 중요한 하네스 규칙(스펙 준수, 게이트 통과 조건 등)에 대한 집중도를 떨어뜨립니다.

```markdown
<!-- Before: 모델에게 코딩 훈수 두기 -->
- 코드는 항상 모듈화하고 가독성을 신경 쓰세요.
- 함수는 단일 책임 원칙을 준수해야 합니다.
- 필요 없는 주석은 달지 마세요.

<!-- After: 판단은 모델에게 맡기고, 하네스는 실행 제약만 전달 -->
- /vibe.spec의 Context Sources 등급([확인]/[해석]/[모름])을 준수할 것.
- 빌드/테스트 실패 시 게이트를 통과할 수 없음.
```

과감하게 일반 조언을 덜어내니, 모델이 하네스의 워크플로우를 훨씬 더 정교하게 따르기 시작했습니다.

### 2. Windows cmd.exe의 LF 절단 버그 해결

이번 기간 가장 골치 아팠던 버그였습니다. CLI 훅에서 AI 에이전트(agy)에게 프롬프트를 넘길 때 `argv` 인자로 전달하고 있었는데, Windows 환경의 `cmd.exe`가 줄바꿈(`\n`) 문자를 만나면 그 뒤의 인자를 통째로 날려버리는 현상이 발생했습니다.

```
[cmd.exe] agy.exe "첫 번째 줄\n두 번째 줄" 
          ──> agy에는 "첫 번째 줄"만 전달되고 나머지 증발!
```

인자 이스케이프 지옥에 빠지는 대신, 표준 입력(`stdin`) 스트림으로 프롬프트를 흘려보내는 방식으로 아키텍처를 변경했습니다.

```typescript
// Before (위험: OS 셸 파서에 의존)
execFile('agy', [promptText], ...);

// After (안전: 스트림 파이프로 직접 주입)
const child = spawn('agy', ['--stdin'], { stdio: ['pipe', 'inherit', 'inherit'] });
child.stdin.write(promptText);
child.stdin.end();
```

OS 플랫폼 차이에 영향을 받지 않는 훨씬 견고한 파이프라인을 구축할 수 있었습니다.
