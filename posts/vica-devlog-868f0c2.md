# Vica 개발일지: 작업 영역을 좌우로 나누고, macOS 앱 이름을 다듬었습니다

2026년 10월 30일 Vica에서는 데스크톱 작업 영역을 좌우 그룹으로 나누고, 각 그룹에 탭 줄을 두었습니다. macOS가 앱을 Vica로 부르도록 앱 묶음의 실행 파일 구성도 수정했습니다. 이번 작업은 화면 구조와 앱 패키징 두 영역으로 나뉩니다. 여기에 작업 영역 구조와 브라우저 검증 방법을 문서로 남기고, 서버에서 실행한 vibe의 기록과 캐시를 보관하는 정리 작업을 더했습니다.

## 작업 영역: 좌우 그룹마다 탭 줄을 둡니다

이번 화면 변경의 중심은 작업 영역을 좌우 그룹으로 나눈 것입니다. 각 그룹에 탭 줄을 두면서 탭을 다루는 화면 구조에도 그룹 단위가 생겼습니다. 이제 작업 영역 구조를 설명할 때는 좌우 어느 그룹인지, 그 그룹에 어떤 탭 줄이 있는지를 함께 짚을 수 있습니다.

이 변경을 단순히 화면을 둘로 나누는 작업으로만 소개하면 그룹별 탭 줄이라는 핵심이 빠집니다. 좌우 배치와 각 그룹의 탭 줄을 함께 구현했다는 점이 이번 기능의 범위입니다. 작업 영역을 이해하는 기준이 달라진 만큼, 이후 화면 동작을 확인할 때도 이 구조를 기준으로 살펴볼 필요가 있습니다.

다만 제공된 커밋 정보만으로 탭을 그룹 사이에서 이동할 수 있는지, 그룹 크기를 조절할 수 있는지까지는 알 수 없습니다. 이번 일지에서는 확인된 범위인 **좌우 그룹 구성과 그룹별 탭 줄 추가**까지만 다루겠습니다. 화면 구조가 생겼다는 사실과 세부 상호작용이 어디까지 지원되는지는 구분해 두는 편이 정확하겠습니다.

## 구조 설명과 브라우저 검증 방법을 문서로 남겼습니다

작업 영역 변경과 함께 그룹 구조와 브라우저 검증 방법을 기록했습니다. 기능을 구현한 코드에 더해, 구조를 이해하고 브라우저에서 확인하는 방법을 찾아볼 수 있는 문서를 남긴 셈입니다.

구조 설명과 검증 방법은 쓰임이 조금 다릅니다. 전자는 작업 영역이 어떻게 나뉘는지 이해할 때 참고하고, 후자는 실제 화면을 확인하는 절차를 찾을 때 참고할 수 있습니다. 이번에는 두 내용을 함께 기록해 구현과 확인 방법을 연결했습니다.

여기서 검증 방법을 문서화했다는 사실을 검증 완료로 읽지는 않으려고 합니다. 제공된 기록에는 구체적인 검증 결과가 없으므로, 모든 동작을 확인했다거나 문제가 없었다고 말할 근거는 없습니다. 이번 문서 작업에서 확실히 남은 것은 구조 설명과 확인 방법입니다.

## macOS: 앱 묶음 안에 실행 파일을 넣었습니다

데스크톱 패키징에서는 앱 묶음에 실행 파일을 복사해 넣도록 수정했습니다. 목적은 macOS가 앱을 Vica로 부르게 하는 것입니다.

사용자가 보는 앱 이름과 관련된 수정이지만, 손댄 부분은 앱 묶음 안의 실행 파일 구성입니다. 화면의 문구를 고친 작업으로 소개하기보다 macOS용 앱 패키징을 조정한 작업으로 묶는 것이 맞겠습니다. 이름이 표시되는 모든 위치나 다른 운영체제의 동작까지 바뀌었다는 정보는 없어, 이번 변경의 범위는 macOS에 한정해 기록합니다.

## 서버에서 돌린 vibe의 기록과 캐시도 보관했습니다

개발 환경 쪽에서는 서버에서 실행한 vibe의 실행 기록과 캐시를 남겼습니다. 이는 데스크톱 화면에 추가된 기능과 구분되는 정리 작업입니다. 실행 과정에서 생긴 기록과 캐시를 보관했다는 데 의미가 있으며, 캐시로 속도가 개선됐다고 해석할 성능 수치는 제공되지 않았습니다.

이번 네 건의 커밋은 작업 영역의 구조 변경, macOS 패키징 수정, 그리고 문서와 실행 자료 보관으로 묶을 수 있습니다. 기능 설명에서는 새로 생긴 그룹과 탭 줄을 중심에 두고, 검증이나 성능에 대해서는 기록으로 확인할 수 있는 범위까지만 남겼습니다. 다음 작업을 돌아볼 때도 구현한 내용과 확인한 결과를 구분할 수 있도록, 이번 일지는 여기까지 정리합니다.
