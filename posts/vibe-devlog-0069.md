# vibe 개발일지 #69 - 결정론적 CI 게이트와 Windows 격리 안정화 (13개 커밋)

**작업 기간**: 2026-08-29 ~ 2026-09-02

안녕하세요, vibe를 만들고 있는 Su입니다. 

"Agent = Model + Harness"라는 철학 아래 vibe를 개발하면서 늘 신경 쓰는 부분은 **재현 가능성과 하네스의 단단함**입니다. 아무리 똑똑한 AI 모델이라도 이를 감싸는 하네스가 흔들리면 결과물의 품질을 보장할 수 없기 때문입니다.

이번 며칠간은 문서나 구두로만 존재하던 규약들을 CI 파이프라인에 완전히 배선하고, Windows 환경에서의 테스트 격리와 EOL 이슈 등 하네스 밑바닥의 거친 모서리들을 깔끔하게 다듬는 작업을 진행했습니다.

## 📝 이번 기간 작업 내용

이번 기간의 13개 커밋은 크게 세 가지 영역으로 나누어 진행되었습니다.

### 1. 결정론적 품질 게이트 배선 & EOL 정상화
- **선언된 규약 3종의 CI 게이트 자동화**: 이전에는 '문서상 지켜야 할 규칙'으로 선언되어 있던 3가지 품질 규약을 실행 가능한 결정론적 CI 게이트로 직접 배선했습니다.
- **작업 트리 LF 고정**: OS별 개행 문자(CRLF/LF) 차이로 인해 상시 실패하던 CI 게이트 3종을 `.gitattributes` 및 빌드 설정을 통해 LF로 완전 고정하여 해소했습니다.
- **Agent Drift 추적 강화**: `agents-md` 드리프트 발생 시 원인이 된 fix-commit 해시를 기록하도록 보강했습니다.

### 2. 크로스 플랫폼 테스트 격리 (Windows 환경)
- **Windows HOME 격리 개선**: 테스트 실행 시 사용자 홈 디렉토리 환경 오염으로 발생하던 Windows 전용 실패 19건을 환경 변수 격리 레이어를 추가해 완벽히 해결했습니다. 이제 macOS/Linux뿐만 아니라 Windows에서도 동일한 하네스 테스트 결과를 보장합니다.

### 3. 하네스 기능 고도화 및 SPEC 확정
- **되돌림 비용(Reversibility) 기반 승인 축 추가**: 커버리지 스윕 시 되돌리기 어려운(High Reversibility Cost) 결정만 최종 승인 직전에 노출하도록 UX를 개선하고, `spec-reversibility-surface` SPEC을 `VERIFIED`로 확정했습니다.
- **Codex 훅 동기화 및 비대칭 해소**: Claude Code 중심이던 훅 동기화 로직을 Codex CLI 훅에도 동일하게 적용하여 내용 불일치를 자동으로 감지하고 복구하도록 수정했습니다.
- **Harness Discipline Import 확정**: 하네스 규율 주입 체계를 정리한 PR #97을 머지하고 SPEC을 `VERIFIED`로 확정했습니다.

## 💡 작업 하이라이트

### 1. "문서상의 룰"에서 "통과하지 못하면 머지 불가능한 게이트"로

그동안 하네스 내부에는 "이런 구조를 유지해야 한다"는 설계 원칙들이 존재했습니다. 하지만 팀이 커지거나 작업 속도가 빨라지면 이런 규칙은 자연스레 깨지기 마련입니다.

이번 작업에서는 느슨하게 관리되던 규약 3가지를 스크립트화하여 CI 게이트로 강제했습니다.

```
[AS-IS: 규칙 기반]
PR 작성 ──> 리뷰어의 눈에 의존 ──> 누락 시 런타임/드리프트 에러 발생

[TO-BE: 결정론적 CI 게이트]
PR 작성 ──> CI Rule Runner ──> [Gate 1: Drift Check] 
                              [Gate 2: Spec Verification] 
                              [Gate 3: Cross-Hook Symmetry] ──> 통과 시에만 머지
```

규약이 코드로 강제되자마자 숨어 있던 작은 불일치들이 수면 위로 드러났고, 이를 모두 수정한 뒤에야 안심하고 릴리즈할 수 있었습니다.

### 2. Windows HOME 격리와 19개의 빨간 불 해결

테스트 러너가 글로벌 설정을 읽는 바람에 Windows 환경에서만 유독 19개의 테스트가 상시 깨지는 문제가 있었습니다. 

`process.env.USERPROFILE`과 `process.env.HOME`의 경로 차이, 그리고 파일 시스템 Mocking 타이밍 문제를 정교하게 격리하는 픽스 커밋을 적용했습니다. OS 환경과 무관하게 하네스가 일관되게 동작하도록 보장하는 것은 CLI 도구에서 타협할 수 없는 기본기라는 점을 다시 한번 배웠습니다.
