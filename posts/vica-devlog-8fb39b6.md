# vica 개발일지: 연결 도구와 컴퓨터 유즈의 실행 흐름 다듬기

10월 31일부터 11월 1일까지의 최근 커밋 21개에서는 Chat이 일을 넘기는 방식과 컴퓨터 유즈의 읽기·실행·승인 흐름을 손봤습니다. 데스크톱의 설정과 상태 표시도 함께 정리했습니다. 기능을 넓히는 작업과, 실제 사용 중 막히던 지점을 고치는 작업이 맞물린 이틀이었습니다.

## Chat에서 도구를 고르고 실행을 이어가기

Chat은 회사마다 연결된 도구를 읽고, 해당 도구로 일을 보낼 수 있게 했습니다. Chat 일꾼이 이미 주어진 도구 정보를 두고 다시 판단하는 일을 줄이는 방향입니다. 입력창에서는 모델을 고를 수 있도록 했습니다.

컴퓨터 유즈 요청이 Chat에서 끝까지 이어지도록 연결 흐름도 수정했습니다. 요청을 넘기는 것만으로는 작업이 끝나지 않으니, 이후 실행까지 이어지는 경로를 함께 다뤘습니다. 데스크톱에서는 요청을 네 갈래로 나누고 스킬·루틴·설정을 다시 구성했습니다. 다만 커밋 메시지만으로는 네 갈래의 세부 기준까지 설명하기 어려워, 이번 기록에서는 구조를 나눴다는 범위까지만 짚겠습니다.

## 앱을 읽고 답장을 보내기까지

컴퓨터 유즈에서는 앱 읽기와 실행 전 안전 검사를 추가한 뒤, 화면에서 놓치던 정보를 보완했습니다. 날짜와 사진, 행 메뉴를 읽는 범위를 넓혔고, 날짜 구분선을 빠뜨리거나 겹친 창을 혼동하던 부분도 고쳤습니다. 처음 보는 앱에서 읽기·저장·승인이 막히던 문제 역시 이번 수정에 포함했습니다.

메신저 작업은 대화를 찾는 단계부터 전송 결과를 확인하는 단계까지 손봤습니다. 웹 기반 메신저에서 대화를 고르고 답장을 보낼 수 있게 했으며, 카카오톡에서는 채팅 탭에서도 본인 대화를 찾도록 수정했습니다. 메뉴 막대를 건드리지 않게 하고, 전송 여부는 입력창을 기준으로 판정하도록 바꿨습니다. 화면을 조작한 뒤 무엇을 보고 성공으로 판단할지도 함께 정리한 셈입니다.

실제 에이전트로 진행한 ‘나와의 채팅’ 시험 결과는 문서로 남겼습니다. 시험 기록이 추가됐다는 사실과 모든 메신저에서 안정적으로 동작한다는 주장은 구분해야 합니다. 이번 커밋 목록만으로 전체 지원 범위나 성공률까지 말할 수는 없습니다.

## 로그인과 승인 경계 정리

저장한 로그인 정보를 에이전트 모르게 입력하는 방식을 추가했습니다. 사이트에서는 브라우저 로그인을 사용하고, Ego를 먼저 찾도록 흐름을 바꿨습니다. 로그인 정보를 다루는 경로와 에이전트가 작업하는 경로를 구분하는 데 초점을 둔 변경입니다.

실행 권한도 함께 다뤘습니다. 데스크톱의 컴퓨터 유즈는 보호막과 자체 권한으로 실행하도록 했고, 브라우저의 위험한 클릭은 사용자에게 먼저 묻게 했습니다. 답장은 사용자 승인을 받아 보내도록 하면서 업무 기준을 전달하는 기능도 추가했습니다. 자동으로 진행할 수 있는 작업이 늘어나는 만큼, 사용자가 확인해야 하는 행동도 실행 흐름 안에 넣었습니다.

## 데스크톱에서 상태를 보고 작업 정리하기

비카 모션은 상태별로 나눈 뒤 원본 얼굴을 바탕으로 다시 만들었고, 클릭 모션도 바로잡았습니다. 채팅에는 시각을 표시하고 드래그 복사를 수정했습니다. 대화를 읽고 필요한 내용을 옮기는 기본 동작까지 챙긴 변경입니다.

활성화 판정과 회의 평가, 실패 표시도 고쳤습니다. 특히 실패 표시는 실행 기능과 별개로 놓치기 쉬운 부분이라 이번 작업에서 함께 다뤘습니다. 변경 파일을 커밋에서 제외하거나 다시 포함하고, 제거하는 기능도 데스크톱에 추가했습니다.

이번 작업의 중심은 도구 연결부터 화면 읽기, 사용자 승인, 결과 판정까지 이어지는 경로였습니다. 기능 추가와 오류 수정, 실제 시험 기록을 함께 남겼다는 점에서, 무엇을 구현했고 어디를 확인했는지 구분해 돌아볼 수 있는 개발 기록이 됐습니다.
