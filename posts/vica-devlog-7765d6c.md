# vica 개발일지: 화면을 보고 판단하는 경로와 글자를 읽는 경로

2026년 11월 18일의 최근 세 커밋에서는 폰과 윈도우 화면을 다루는 방식을 손봤습니다. 폰에서는 판단 모델이 화면 사진을 보고 조작하고, 글자 인식으로 읽은 내용을 모으도록 했습니다. 컴퓨터에서는 그림뿐인 창도 폰과 같은 판단 경로를 거치게 고쳤고, 윈도우 화면의 글자와 목록을 읽고 가려진 창을 다루는 기능을 추가했습니다.

이번 변경은 화면을 보고 판단하는 영역과 화면에서 글자를 읽는 영역으로 묶어 정리하겠습니다. 두 영역이 함께 바뀌었지만, 커밋에 담긴 내용만으로 읽은 글자가 판단에 어떻게 전달되는지까지 설명할 수는 없습니다. 여기서는 추가하거나 수정한 동작을 중심으로 살펴보겠습니다.

## 화면을 보고 조작하기: 폰과 컴퓨터의 판단 경로

폰 쪽에는 판단 모델이 화면 사진을 보고 폰을 조작하는 기능을 넣었습니다. 화면에 무엇이 보이는지 살펴보고 조작하는 역할을 판단 모델이 맡는 구성입니다. 화면에서 글자를 읽는 작업도 함께 추가했지만, 사진을 바탕으로 판단하는 동작과 인식한 글자를 모으는 동작은 구분해서 볼 필요가 있습니다.

컴퓨터 쪽에서는 그림뿐인 창을 처리하는 경로를 수정했습니다. 이런 창도 폰과 같은 경로로 판단 모델이 고르도록 바꿨습니다. 글자로 읽을 내용이 없는 창 역시 화면을 보고 판단해야 하는 대상으로 다룬다는 점에서 폰 작업과 맞닿아 있습니다.

이 수정의 범위는 그림뿐인 창의 판단 경로입니다. 폰과 컴퓨터의 모든 조작 방식이 같아졌다고 볼 수는 없습니다. 다만 두 환경에서 시각적인 내용을 판단하는 경로를 일부 맞췄다는 변화는 분명합니다. 앞으로 이 부분을 확인할 때도 단순히 창에 글자가 있는지만 볼 것이 아니라, 그림으로만 구성된 창이 해당 경로에서 제대로 선택되는지 살펴볼 필요가 있습니다.

## 글자를 읽고 모으기: 폰의 인식 결과와 윈도우의 목록

폰에서는 글자 인식이 읽은 내용을 모으는 기능을 추가했습니다. 판단 모델이 화면 사진을 보는 동안, 화면에서 읽어 낸 글자도 수집하는 구성입니다. 다만 어떤 단위로 모으는지, 중복된 내용을 어떻게 처리하는지, 어디에 보관하는지는 이번 커밋 설명에 드러나지 않습니다. 따라서 여기서 말할 수 있는 범위는 인식 결과를 모으는 기능이 생겼다는 데까지입니다.

윈도우에는 화면 글자를 읽는 기능과 목록을 글로 읽는 기능을 추가했습니다. 화면 속 글자를 읽는 것과 목록을 텍스트로 읽는 것을 각각 작업 범위에 포함했습니다. 목록을 어떤 형식으로 표현하는지까지는 확인할 수 없지만, 이번 변경에서 목록을 읽는 동작을 별도로 다뤘다는 점은 짚어 둘 만합니다.

폰과 윈도우 모두 글자를 읽는 기능이 늘었지만, 두 환경이 같은 인식 방식이나 결과 형식을 쓴다고 단정하지는 않겠습니다. 공통으로 확인되는 변화는 화면 사진을 판단하는 작업과 더불어, 화면의 글자를 읽는 작업도 추가했다는 점입니다.

## 가려진 창 다루기와 남은 확인

윈도우 작업에는 가려진 창을 다루는 기능도 포함됐습니다. 글자와 목록을 읽는 기능이 화면의 내용을 대상으로 한다면, 이 기능은 창이 놓인 상태를 다룹니다. 다만 가려진 창을 어떤 방식으로 처리하는지, 어느 정도 가려진 상태까지 지원하는지는 커밋 설명만으로 알 수 없습니다.

이번 세 커밋으로 폰의 화면 기반 조작과 글자 수집, 컴퓨터의 시각 판단 경로, 윈도우의 읽기 및 창 처리 기능이 바뀌었습니다. 기능 추가와 경로 수정은 확인할 수 있지만, 인식 정확도나 조작 성공률이 얼마나 달라졌는지는 별도의 검증이 필요합니다. 특히 그림뿐인 창, 목록이 있는 화면, 가려진 창은 서로 다른 조건인 만큼 나눠 확인해야 할 대상입니다. 이번 기록에서는 구현한 범위와 아직 확인할 수 없는 범위를 구분해 남겨 둡니다.
