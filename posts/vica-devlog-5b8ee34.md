# vica 개발일지: 확장팩 계획 정리와 Windows 0.1.10 배포 기록

2026년 11월 10일, vica에서는 확장팩 계획을 문서에 남기고 Windows 0.1.10 배포와 확인 결과를 기록했습니다. 최근 세 커밋은 모두 문서 작업입니다. 이번 일지는 커밋 순서 대신 확장팩 기획과 Windows 릴리스라는 두 영역으로 나눠 정리하겠습니다. 구현 내용보다는 무엇을 계획에 반영했고, 어떤 배포 기록을 남겼는지에 초점을 맞췄습니다.

## 확장팩: 계획 기록에서 팩 구성 반영까지

확장팩 영역에서는 계획 자체를 기록하는 작업과, 그 계획에 글쓰기 팩과 스튜디오팩 구성을 반영하는 작업이 있었습니다. 두 커밋을 묶어 보면 이번에 문서로 다룬 범위가 드러납니다. 확장팩 계획을 남기는 데서 그치지 않고, 이름이 명시된 두 팩의 구성까지 계획에 포함했습니다.

글쓰기 팩과 스튜디오팩은 이번 변경에서 구체적으로 확인할 수 있는 기획 대상입니다. 다만 커밋 메시지만으로는 각 팩에 어떤 기능이 들어가는지, 두 팩의 역할을 어떻게 나눴는지까지 알 수 없습니다. 이름에서 용도를 짐작할 수는 있어도, 그 짐작을 실제 기능 목록처럼 소개하지는 않겠습니다.

여기서는 ‘계획에 반영했다’는 표현의 범위를 지키는 것이 중요합니다. 이번 기록은 두 팩의 구성을 확장팩 계획에 담았다는 뜻이지, 기능 구현이나 배포를 마쳤다는 뜻은 아닙니다. 사용자에게 바로 제공되는 기능으로 소개하면 현재 확인된 작업보다 앞서 나가게 됩니다.

개발일지에 담을 수 있는 변화는 확장팩 기획의 문서화 범위가 두 팩의 구성까지 구체화됐다는 점입니다. 세부 사양이나 출시 일정은 제공된 기록에 없으므로 이번 글에서는 다루지 않습니다. 계획과 구현 상태를 구분해 두어야 이후 개발 기록과 비교할 때도 무엇이 달라졌는지 정확히 설명할 수 있겠습니다.

## Windows: 0.1.10 배포와 확인 결과 기록

릴리스 영역에서는 Windows 0.1.10 배포와 확인 결과를 문서에 남겼습니다. 확장팩 문서가 앞으로 만들 내용을 다뤘다면, 이 기록은 특정 플랫폼과 버전의 배포를 다룹니다. 같은 문서 작업이어도 기획 문서와 릴리스 기록은 읽어야 할 맥락이 다릅니다.

이번 커밋에서 확인할 수 있는 대상은 Windows용 0.1.10입니다. 배포뿐 아니라 확인 결과도 기록했다는 점이 포함돼 있습니다. 다만 어떤 항목을 확인했는지, 어떤 환경에서 확인했는지, 결과에 제한 사항이 있었는지는 커밋 메시지에 나오지 않습니다.

그래서 이번 배포를 두고 ‘모든 테스트를 통과했다’거나 ‘안정성 검증을 마쳤다’고 표현하기는 어렵습니다. 확인 결과를 기록했다는 사실과 그 결과가 무엇인지는 구분해서 읽어야 합니다. 마찬가지로 0.1.10에 포함된 기능이나 수정 사항도 주어진 자료만으로는 설명할 수 없습니다. 이번 일지에서는 버전과 플랫폼, 배포 및 확인 결과의 기록 여부까지만 전하겠습니다.

## 이번 작업의 범위

이번 세 커밋은 확장팩의 계획과 Windows 릴리스 이력을 각각 문서에 남긴 작업으로 묶을 수 있습니다. 확장팩 쪽에는 글쓰기 팩과 스튜디오팩 구성을 반영했고, 릴리스 쪽에는 Windows 0.1.10 배포와 확인 결과를 기록했습니다.

눈에 보이는 기능 변화를 소개하는 일지는 아니지만, 그렇다고 구현 성과를 덧붙여 설명할 필요는 없겠습니다. 이번에는 계획으로 남긴 내용과 배포 기록으로 남긴 내용을 나눠 전합니다. 각 팩의 세부 기능과 0.1.10의 확인 항목은 문서 본문이 있어야 더 자세히 이야기할 수 있는 부분으로 남겨두겠습니다.
