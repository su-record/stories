# vica 개발일지: vica-laya로 이름을 바꾸고 입력창과 검증 흐름을 다듬었습니다

2026년 11월 5일의 최근 커밋 6개에는 이름 변경부터 입력창 배치, 컴퓨터 화면의 글자 표시, 에이전트 시험 보완까지 담겼습니다. 이번 기록은 커밋 순서 대신 사용자가 만나는 화면, 동작을 확인하는 시험, 팀에 남긴 문서로 묶어 정리했습니다. 이름은 **vica-laya**로 바꿨고, 화면을 손보는 과정에서도 표시 위치와 실제 동작 좌표는 구분해 다뤘습니다.

## 입력창 주변의 선택지를 정리했습니다

이름 변경과 함께 요청 분석 모델, 입력창 위치 칩, 브랜치 전환을 추가했습니다. 요청을 분석할 모델과 입력창 위치를 다루는 요소, 브랜치를 전환하는 기능이 이번 변경 범위에 들어갔습니다. 다만 커밋 정보만으로는 각 기능의 세부 사용 방식이나 지원 범위까지 설명하기 어려워, 여기서는 추가된 항목을 중심으로 남깁니다.

채팅 입력창에서는 도구줄 배치를 바꿨습니다. **권한은 왼쪽에, 모델과 추론 강도는 오른쪽에** 두고, 위쪽 영역은 투명하게 처리했습니다. 입력창 주변에서 무엇을 어느 쪽에 놓을지 정리한 작업입니다. 권한과 모델 설정의 위치를 나눴다는 점은 분명하지만, 이 배치가 실제로 더 편한지는 사용 과정에서 따로 확인할 부분입니다.

이번 화면 변경은 새 선택지를 더하는 일과 기존 설정의 자리를 조정하는 일이 함께 진행됐다는 점에서 묶어 볼 수 있습니다. 기능이 생겼다는 사실과 그 기능을 화면에서 어떻게 찾게 할지는 서로 다른 문제라, 개발일지에도 두 내용을 구분해 기록해 둡니다.

## 글자 표시를 맞추되 동작 좌표는 유지했습니다

컴퓨터 관련 기능에서는 글자 표시를 실제 글자 위치에 맞췄습니다. 여기서 중요한 조건은 **동작 좌표를 그대로 뒀다**는 점입니다. 화면에 글자를 표시하는 위치를 조정하면서, 동작에 쓰는 좌표까지 함께 바꾸지는 않았습니다.

따라서 이번 작업을 컴퓨터 동작 전반의 좌표 수정으로 설명하면 범위가 넓어집니다. 바뀐 것은 글자의 표시 위치이고, 유지한 것은 동작 좌표입니다. 화면 표시를 손본 변경인 만큼, 이후 이 부분을 살펴볼 때도 표시가 맞는지와 동작 좌표가 유지되는지를 나눠 확인할 필요가 있습니다.

## Node 26 시험 출력과 시험 간 간섭을 다뤘습니다

에이전트 쪽에서는 Node 26의 시험 출력을 읽도록 수정했습니다. 시험 결과를 판단하려면 해당 환경에서 나오는 출력을 읽을 수 있어야 하므로, 이번 보완은 검증에 쓰이는 출력 처리와 관련된 작업입니다. 다만 이를 Node 26 전반에 대한 호환성 검증 완료로 넓혀 말하지는 않겠습니다.

환경 변수를 바꾸는 시험과 검증 시험이 겹치지 않도록 한 수정도 포함됐습니다. 한쪽 시험이 환경 변수를 변경하는 동안 다른 시험이 검증을 수행하는 상황을 피하도록 조정한 것입니다. 출력 형식을 읽는 문제와 시험 실행이 서로 간섭하는 문제를 각각 다뤘다는 점을 함께 남깁니다.
