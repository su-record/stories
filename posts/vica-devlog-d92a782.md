# vica 개발일지: 뒤에 있는 앱 입력과 아이폰 조작, 판단 작업 연결

2026년 11월 13일의 vica 커밋 5개는 컴퓨터 입력, 아이폰 조작, 판단 작업 연결에 걸쳐 있습니다. 컴퓨터 쪽에서는 뒤에 있는 앱으로 입력을 보내는 기능과 입력이 적용되지 않을 때의 처리를 함께 손봤습니다. 아이폰은 잠금 해제와 패널 조작을 추가했고, 인증된 판단 작업은 설치된 `vica-laya`가 답하도록 연결했습니다.

## 컴퓨터 입력: 앱을 앞으로 가져오지 않고 보내기

뒤에 있는 앱에 글자와 키를 보낼 때, 그 앱을 앞으로 가져오지 않고 입력할 수 있도록 했습니다. 입력 대상을 매번 전면으로 옮기지 않는 방식입니다. 다른 앱이 앞에 있는 상태에서도 대상 앱으로 입력을 보낼 수 있다는 점이 이번 변경의 핵심입니다.

다만 입력을 보내는 것과 앱이 실제로 받아들이는 것은 구분해야 합니다. 이번 커밋에서도 백그라운드 입력 기능을 추가한 뒤, 전체 선택과 키 입력이 기대대로 적용되지 않는 경우를 다뤘습니다.

먼저 뒤에 있는 앱에 `⌘A`를 보냈을 때는 선택 범위를 되읽어 확인하도록 했습니다. 전체 선택 명령을 보냈다는 사실만으로 처리를 끝내지 않고, 앱의 선택 상태를 다시 확인하는 절차를 넣은 것입니다. 글자를 입력하기 전에 기존 내용을 선택해야 하는 작업에서는 이 확인이 중요합니다.

들어가지 않는 키는 대상 앱을 앞으로 가져온 뒤 보내도록 했습니다. 따라서 이번 입력 방식을 “언제나 앱을 뒤에 둔 채 처리한다”고 설명할 수는 없습니다. 기본적으로는 전면 전환 없이 입력하되, 키가 적용되지 않는 경우에는 앱을 앞으로 가져오는 경로를 둔 구조입니다.

## 실행 구분: 자체 에이전트마다 별도 세션 이름 사용

컴퓨터 유즈에서는 자체 에이전트를 실행할 때마다 세션 이름을 따로 쓰도록 수정했습니다. 입력 기능과는 다른 층위의 변경이지만, 컴퓨터 조작을 어느 실행에 연결할지 구분하는 데 필요한 부분입니다.

이번 커밋에서 확인할 수 있는 범위는 실행별 세션 이름 분리까지입니다. 세션 이름을 나눴다는 사실만으로 실행 간 간섭이 모두 사라졌다고 말하기는 어렵습니다. 여기서는 자체 에이전트의 실행을 세션 이름으로 구별하도록 바뀌었다는 점을 기록해 둡니다.

## 아이폰: 금고의 암호로 잠금 해제하고 패널에서 조작하기

아이폰 쪽에는 잠긴 기기를 금고에 저장된 암호로 푸는 기능을 추가했습니다. 기기를 조작하려면 먼저 잠금 상태를 처리해야 하는데, 이제 금고의 암호를 사용하는 경로가 생겼습니다.

패널에서는 아이폰으로 누르기·끌기·쓸기 동작을 보낼 수 있도록 했습니다. 잠금 해제와 화면 조작을 함께 다뤘지만, 두 기능의 역할은 다릅니다. 전자는 잠긴 기기에 접근하는 단계이고, 후자는 패널에서 실제 조작을 전달하는 단계입니다. 이번 변경으로 추가된 조작 범위는 이 세 가지 동작입니다.

## 판단 작업: 인증된 요청을 설치된 vica-laya에 연결

판단 영역에서는 인증된 판단 작업에 설치된 `vica-laya`가 답하도록 했습니다. 판단 요청을 실제로 답하는 구성 요소에 연결하는 변경입니다.

여기서 조건은 “인증된 작업”과 “설치된 `vica-laya`”입니다. 모든 판단 요청의 처리 방식이 바뀌었다거나, 별도의 설치 없이 사용할 수 있게 됐다는 뜻으로 넓혀 설명하지는 않겠습니다. 이번 기록은 해당 조건에서 답변을 맡는 주체가 연결됐다는 범위로 남깁니다.

이번 다섯 커밋에서는 새 조작 경로를 여는 작업과, 컴퓨터 입력 결과를 확인하는 작업이 함께 진행됐습니다. 특히 백그라운드 입력은 기능 추가에 그치지 않고 선택 상태 확인과 전면 전환 경로까지 이어졌습니다. 지원하는 기능뿐 아니라, 어떤 조건에서 다른 처리 경로를 쓰는지도 함께 남겨둘 만한 변경이었습니다.
