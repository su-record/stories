# vica 개발일지: Aside 중심의 컴퓨터 사용과 채팅 준비 개선

2026년 11월 21일의 vica 작업은 컴퓨터 사용 환경과 데스크톱 채팅 흐름에 집중됐습니다. Aside를 메인 브라우저로 쓰도록 바꾸고 CLI 설치·업데이트를 관리하는 한편, 채팅의 첫 요청 준비 부담과 토큰 낭비를 줄였습니다. 컴퓨터 사용 여부를 판단하는 모델의 범위와 메뉴 막대 멈춤 문제도 함께 손봤습니다.

이번 글은 최근 커밋 3개의 메시지를 바탕으로 정리했습니다. 코드 변경이나 측정 결과는 제공되지 않았으므로, 구체적인 구현 방식과 성능 개선 폭은 단정하지 않겠습니다. 커밋 순서보다는 서로 맞닿은 기능과 영역을 기준으로 살펴보겠습니다.

## 컴퓨터 사용: Aside를 메인 브라우저로

컴퓨터 영역에서는 Aside를 메인 브라우저로 사용하도록 바꿨습니다. 브라우저를 중심으로 수행하는 작업에서 어떤 환경을 기본으로 삼을지 정한 변경입니다. 다만 기존 브라우저와의 전환 방식이나 지원 범위까지는 커밋 메시지에서 확인할 수 없습니다. 이번 기록에서는 Aside의 역할이 메인 브라우저로 바뀌었다는 점에 초점을 맞추겠습니다.

같은 영역에 CLI 설치·업데이트 관리도 들어갔습니다. 브라우저 선택과 함께 CLI를 설치하고 갱신하는 과정까지 관리 대상으로 포함한 셈입니다. CLI가 필요할 때 사용자가 직접 처리해야 하는 단계가 얼마나 남아 있는지, 업데이트를 어떤 조건에서 실행하는지는 별도 확인이 필요합니다. ‘관리한다’는 설명만으로 자동 설치나 자동 업데이트까지 지원한다고 말하기는 어렵습니다.

컴퓨터 사용 판단에 활용하는 모델도 늘렸습니다. Aside를 기본 환경으로 삼는 변경이 실행 환경에 관한 일이라면, 이쪽은 컴퓨터를 사용할지 판단하는 단계의 변경입니다. 판단에 쓸 수 있는 모델의 범위가 넓어진 점은 확인되지만, 모델 이름이나 선택 기준은 주어진 정보에 없습니다. 모델 확대가 곧 판단 정확도 향상을 뜻하는 것은 아니므로, 품질 평가는 구분해 두겠습니다.

## 데스크톱 채팅: 첫 요청 준비와 토큰 낭비 줄이기

채팅에서는 첫 요청을 준비하는 부분을 개선했습니다. 대화가 시작되는 구간을 성능 개선 대상으로 잡았다는 점이 이번 작업의 특징입니다. 다만 준비 단계에서 무엇을 바꿨는지는 메시지만으로 알 수 없습니다. 초기화 시점을 옮겼거나 특정 처리를 재사용했다고 설명하면 구현을 추측하게 되므로, 여기서는 첫 요청 준비 부담을 줄이는 작업으로 정리하겠습니다.

토큰 낭비를 줄이는 변경도 함께 진행했습니다. 첫 요청 준비와 토큰 사용은 같은 채팅 흐름에 속하지만, 확인해야 할 결과는 다릅니다. 전자는 요청 준비에 드는 시간이나 작업량을, 후자는 불필요하게 쓰는 토큰을 살펴봐야 합니다. 현재는 수치가 없어 응답이 얼마나 빨라졌는지, 토큰이 얼마나 줄었는지까지 소개할 수는 없습니다.

그래도 이번 성능 작업의 방향은 분명합니다. 채팅의 첫 요청 준비와 토큰 사용을 함께 손봤습니다. 실제 사용에서 어느 정도 차이가 나는지는 측정 결과가 있어야 더 구체적으로 이야기할 수 있겠습니다.

메뉴 막대가 멈추는 문제도 수정했습니다. 기능을 추가하거나 처리 부담을 줄이는 작업과 달리, 이 변경은 데스크톱 인터페이스의 동작 문제를 고친 작업입니다. 발생 조건과 원인은 제공되지 않았으므로 특정 운영체제나 사용자 동작에 연결해 설명하지는 않겠습니다.

이번 세 커밋에서는 컴퓨터 사용 환경을 정비하는 일과 채팅의 부담을 줄이는 일, 메뉴 막대의 멈춤을 고치는 일이 나란히 진행됐습니다. 변경 방향은 기록할 수 있지만, 세부 동작과 개선 효과까지 설명하기에는 근거가 부족합니다. 다음 기록에 실행 결과나 측정값을 함께 담을 수 있다면, 이번에 바꾼 부분이 실제 사용에서 어떻게 드러나는지도 더 정확히 짚어볼 수 있겠습니다.
