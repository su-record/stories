# vica 개발일지: 데스크톱 아이콘과 채팅 실행 모드 수정

2026년 11월 6일의 vica 최근 커밋 3개는 데스크톱 앱의 아이콘 표시와 채팅 모델의 명령 실행 설정을 다룹니다. 데스크톱에서는 앱을 처음 켜기 전에도 아이콘이 회색 판 없이 보이도록 묶는 형식을 바꿨고, 관련 빌드 변경 이력도 갱신했습니다. 채팅에서는 Grok이 Claude 설정의 자동 모드를 물려받아 사용자 허락 없이 명령을 실행하던 문제를 수정했습니다.

## 데스크톱: 처음 실행하기 전의 아이콘 표시 수정

이번 아이콘 수정이 다루는 시점은 **앱을 처음 켜기 전**입니다. 앱을 실행한 뒤 화면 안에서 보이는 요소뿐 아니라, 실행하기 전에 보이는 앱 아이콘도 확인해야 할 대상이라는 점이 드러난 변경입니다. 수정 내용은 아이콘을 Icon Composer 형식으로 묶어, 이 시점에도 회색 판 없이 표시되도록 하는 것입니다.

아이콘 문제라고 하면 그림 자체를 바꾸는 작업을 떠올릴 수 있지만, 이번 커밋에서 확인되는 변경은 패키징 형식에 있습니다. 따라서 새로운 아이콘 디자인을 적용했다고 소개하기보다는, 기존에 문제가 있던 표시 상태를 아이콘을 묶는 방식으로 바로잡았다고 설명하는 편이 정확합니다. 어떤 환경에서 얼마나 자주 나타났는지까지는 제공된 커밋 정보만으로 알 수 없습니다.

관련 문서도 함께 손봤습니다. 데스크톱 아이콘의 빌드 방식이 바뀐 이력을 갱신해, 구현 변경을 문서에도 반영했습니다. 아이콘 표시 수정과 변경 이력 정리를 같은 영역으로 묶은 이유입니다. 하나는 앱에서 보이는 결과를 고치는 작업이고, 다른 하나는 빌드 방식이 달라졌다는 사실을 기록으로 남기는 작업입니다.

나중에 아이콘 빌드를 다시 다룰 때는 현재 형식뿐 아니라 변경 이력도 살펴볼 필요가 있습니다. 다만 이번 문서 커밋이 구체적으로 어떤 설명이나 절차를 추가했는지는 확인할 수 없어, 문서에 담긴 세부 내용까지 확대해 소개하지는 않겠습니다.

## 채팅: Grok에 Claude의 자동 모드가 이어지지 않도록 수정

채팅 쪽에서는 **모델 사이에 실행 설정이 잘못 이어지는 문제**를 다뤘습니다. Grok이 Claude 설정의 자동 모드를 물려받으면서, 사용자 허락 없이 명령을 실행할 수 있었던 동작을 수정했습니다. 여기서 중요한 부분은 자동 모드 자체의 존재보다, Claude에 속한 설정이 Grok의 명령 실행에 영향을 줬다는 점입니다.

명령 실행 설정은 실제 동작을 허용하는 범위와 연결됩니다. 특정 모델에서 자동 모드를 사용했다고 해서 다른 모델에도 같은 허용이 적용된다고 볼 수는 없습니다. 이번 수정은 바로 그 구분을 지키기 위한 변경으로 읽을 수 있습니다. 사용자 입장에서도 모델을 바꿨을 때 이전 모델의 설정 때문에 예상하지 못한 명령이 실행되는 상황은 피해야 하니까요.

수정 범위는 조심해서 설명하려고 합니다. 커밋 정보로 확인되는 것은 Grok이 Claude의 자동 모드를 물려받아 허락 없이 명령을 실행하는 문제를 막았다는 사실입니다. 모든 모델의 권한 체계를 개편했다거나, 명령 실행 전에 언제나 같은 확인 절차가 나타나도록 바꿨다는 내용까지는 확인되지 않습니다.

## 이번 변경에서 남겨둘 점

데스크톱 수정은 첫 실행 전의 아이콘 표시를, 채팅 수정은 모델별 실행 설정의 경계를 다뤘습니다. 함께 갱신한 문서는 아이콘 빌드 방식의 변경을 기록하는 역할을 합니다.

이번 기록은 커밋 메시지에서 확인할 수 있는 변경에 한정했습니다. 실제 기기별 아이콘 표시 결과나 채팅 설정 조합별 검증 결과는 제공되지 않았습니다. 그래서 수정 의도와 범위는 정리하되, 모든 환경에서 검증을 마쳤다는 식의 완료 판단은 덧붙이지 않았습니다.
