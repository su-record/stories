# vibe 개발일지 #65 - 자가 업그레이드 신뢰성과 테스트 불변식 다지기 (10개 커밋)

**작업 기간**: 2026-08-20 ~ 2026-08-22

안녕하세요, AI 코딩 하네스 도구 **vibe**를 만들고 있는 Su입니다.

AI 하네스 도구의 본질은 **"개발자가 신경 쓰지 않아도 최소 품질과 일관성을 자동으로 보장하는 것"**입니다. 하지만 하네스 자체가 흔들리거나, CLI의 기본 동작(자가 업그레이드 등)이 엉뚱한 결과를 낸다면 신뢰는 무너지기 마련이죠.

이번 3일간은 화려한 새 기능 추가보다는, 오랫동안 발목을 잡을 뻔했던 **자가 업그레이드 신뢰성 버그 2건**을 뿌리 뽑고, **테스트 단언을 불변식(Invariant) 기반으로 전환**하는 내실 다지기에 집중했습니다.

---

## 📝 이번 기간 작업 내용

이번 10개 커밋은 크게 3가지 영역으로 나누어 진행했습니다.

### 1. `upgrade` 명령어 신뢰성 강화 (2건 해결)
- **미러 레지스트리 동기화 지연 대응**: 지역 npm 미러나 캐시된 레지스트리에 최신 버전을 조회하다가, 이미 발행된 최신 버전 대신 뒤처진 버전을 받아오는 문제를 수정했습니다. 원본 레지스트리 우선 확인 및 타임스탬프 검증을 강화했습니다.
- **실제 도달 버전 검증(Version Parity)**: 패키지 매니저의 `npm update` / `yarn upgrade` 실행 후, 프로세스가 성공 종료(exit 0)했다고 해서 무조건 성공으로 보고하던 안일한 로직을 뜯어고쳤습니다. 업데이트 후 실제 설치된 바이너리/패키지 버전을 재조회하여 의도한 타깃 버전에 도달했는지 확인하도록 변경했습니다.

### 2. 테스트 스위트 및 E2E 사다리(Ladder) 정비 (2건 개선)
- **선택을 하드코딩한 단언 → 불변식(Invariant) 단언으로 교체**: 특정 모델이나 환경의 세부 구현 선택값(특정 파일명, 특정 순서 등)을 그대로 `expect(x).toBe(val)`로 박아두었던 취약한 테스트들을 "반드시 만족해야 하는 상태 불변식" 중심으로 리팩터링했습니다.
- **E2E 실행 체인에서 Agent Browser 제거**: 과도하게 복잡도를 올리고 플레이키(flaky) 테스트의 주원인이 되던 무거운 브라우저 에이전트 레이어를 코어 E2E 사다리에서 깔끔하게 덜어냈습니다.

### 3. 스킬 시스템 문서 및 도구 체인 명세 보강 (1건 문서화)
- **`video-production` 스킬의 전제 도구 획득 경로 정리**: AI 에이전트가 영상 제작 스킬을 실행하기 전, 시스템에 ffmpeg 등 필요한 바이너리가 없을 때 이를 획득하는 명확한 가이드라인과 훅을 문서화했습니다.

## 💡 작업 하이라이트

### "성공했다고 말하기 전에, 정말 최신인지 확인했는가?"

CLI 도구에서 `vibe upgrade`를 실행했을 때 일어나는 흔한 착각이 있습니다.

```
[Before]
$ vibe upgrade
→ npm install -g @su-record/vibe@latest 실행
→ exit code 0 확인
→ "✨ 최신 버전으로 업그레이드되었습니다!" (실제로는 미러 캐시 때문에 제자리걸음)
```

미러 레지스트리가 수 분 동안 뒤처져 있으면, 사용자는 분명 업그레이드 완료 메시지를 봤는데 여전히 구버전에 머무는 기묘한 상황을 겪게 됩니다.

```
[After]
$ vibe upgrade
1. 메인 npm 레지스트리에서 진짜 최신 버전(vTarget) 조회
2. 패키지 매니저 업데이트 실행
3. 실행 후 `vibe --version`(vInstalled)을 직접 실행해 확인
4. vInstalled === vTarget 검증 완료 후에만 성공 리포트
   (불일치 시 캐시 경고 및 수동 플래그 안내)
```

"하네스 도구라면 본인의 버전 상태조차 스스로 검증할 수 있어야 한다"는 원칙을 다시 세웠습니다.

### 취약한 테스트 단언을 불변식으로

AI 에이전트 연동 테스트를 작성하다 보면, 모델의 비결정성이나 프롬프트 미세 조정에 따라 출력 형태가 살짝 바뀔 수 있습니다. 

- **Before**: `expect(result.files).toEqual(['spec.md', 'run.sh'])` (순서나 부가 파일 하나만 바뀌어도 깨짐)
- **After**: `expect(result.files).toSatisfy(hasRequiredArtifacts)` (필수 산출물 충족 여부, 스펙 준수 불변식만 단언)

세부 구현에 결합된 테스트를 걷어내고 **"결과물이 하네스 계약(Contract)을 지키고 있는가?"**에 집중하도록 단언 방식을 재구성했습니다.
