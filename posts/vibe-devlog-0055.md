# vibe 개발일지 #55 - Claude를 넘어 Codex까지, 진정한 하네스 중립화 (10개 커밋)

안녕하세요, Su입니다! 

저는 **"Agent = Model + Harness"**라는 철학을 바탕으로 AI 코딩 하네스 도구인 `vibe`(`@su-record/vibe`)를 만들어가고 있습니다. AI 에이전트의 성패는 모델 자체의 성능도 중요하지만, 그 에이전트가 오작동하지 않도록 제약하고 가이드해 주는 **하네스(Harness)** 시스템에 달려있다고 믿기 때문인데요.

오늘은 `vibe`가 특정 AI CLI(Claude Code)에 치우쳐 있던 레거시 때를 벗겨내고, **Codex CLI, Gemini CLI 등 어떤 환경에서도 동일한 품질을 보장하는 '하네스 중립화(Harness Neutralization)'**를 진척시킨 10개의 커밋 이야기를 공유해보려고 합니다.

---

## 📝 이번 기간 작업 내용

이번 10개의 커밋은 크게 **하네스 중립화**, **에이전트/구조 개선**, 그리고 **CLI 가드 및 Hook 안정화**라는 3가지 영역으로 나누어 정리할 수 있습니다.

### 1. 멀티 AI 하네스 중립화 (Harness Neutralization)
* **스킬 내 Claude Code(CC) 전용 문법 제거**: Codex CLI 실검증 과정에서 발견된 CC 독점 프롬프트 파싱 요소를 모두 제거하고 내부 프롬프트 모순을 해소했습니다.
* **잔여 중립화 이슈 6건 수정**: Codex 재검증을 돌리며 교차 검증 중 발견된 잔여 하네스 비중립 구문 6건을 추가 정교화했습니다.

### 2. 에이전트 시스템 및 레거시 디렉토리 이전
* **서브에이전트 모델 상속 독트린 구현**: 메인 에이전트의 모델 설정 및 규칙이 서브에이전트 호출 시 손실되지 않고 명확히 상속되도록 독트린 로직을 구체화했습니다.
* **레거시 디렉토리 이동 (`.claude/vibe` ➔ `.vibe`)**: 특정 플랫폼 이름이 포함되어 있던 레거시 경로 `.claude/vibe`를 완전히 독립된 `.vibe`로 공식 이전했습니다.

### 3. CLI 및 Hook 오탐/복구 안정화
* **`vibe upgrade` & `status` 기능 강화**: CLI 업그레이드 시 프로젝트 Hook이 유실되는 현상을 막는 자동 복구 로직을 추가하고, `status` 명령어에서 가드(Guard)의 생사 상태를 정확히 보고하도록 고쳤습니다.
* **`code-check` 훅 오탐 수정**: Markdown 문서 내부의 예제 `console.log` 코드를 P1 위험 요소로 잘못 감지하던 이슈를 정규식/AST 파싱 범위 보정으로 해결했습니다.
* **Release Note 하이라이트 오류 수정**: 파일 위치만 단순 이동된 SPEC 문서가 신규 기능 하이라이트로 잘못 분류되는 현상을 바로잡았습니다.

## 💡 작업 하이라이트

### 1. Claude 전용 하네스에서 '진정한 중립 하네스'로

`vibe`는 초기에 Claude Code(CC) 환경에서 주로 검증되었습니다. 하지만 `vibe`가 지향하는 가치는 **"어떤 LLM 모델이나 CLI 도구를 가져와도 최상의 코드 품질을 보장한다"**입니다. 

실제로 OpenAI Codex CLI 환경에서 `vibe` 스킬들을 동작시켜보니, CC 전용으로 작성되어 있던 프롬프트 힌트나 내부 모순 때문에 Codex가 가이드라인을 탈출하거나 엉뚱하게 오작동하는 현상을 발견했습니다.

```
[Before]
Claude Code 전용 프롬프트 구문 포함 ──> Codex CLI 사용 시 파싱 실패 / 스킬 무시 발생

[After]
중립화된 스킬 프롬프트 ──> Claude Code, Codex CLI, Gemini CLI 모두 동일하게 하네스 작동
```

이번 작업을 통해 CC 전용 문법을 전면 제거하고, Codex CLI 환경에서 직접 실검증을 수행하며 남은 6건의 하네스 비중립 요소까지 완전히 털어냈습니다. 이제 어떤 에이전트 CLI를 사용하든 `vibe`는 동일하게 든든한 울타리가 되어 줍니다.

### 2. 문서 내 `console.log` 오탐 문제와 실수에서 배운 점

개발자를 돕기 위해 만든 `code-check` 훅이 정작 개발자의 발목을 잡는 일이 있었습니다. 기술 문서(`.md`) 작성 중에 포함된 예시 코드의 `console.log`까지 P1 심각도로 감지해서 커밋/실행을 막아버리는 현상이 발생한 것이죠.

```markdown
<!-- README.md 예시 -->
```typescript
// 사용법 예시
console.log(vibe.run());
```
--> code-check Hook: "P1 경고! console.log가 남아있습니다!" (오탐)
```

"AI 오작동을 막으려면 훅 자체가 견고해야 한다"는 원칙을 다시 한번 새기며, 코드 체크 훅이 문서 영역과 실제 소스 코드를 엄격히 분리하여 평가하도록 로직을 정교화했습니다. 하네스 도구가 개발 경험(DX)을 해치지 않게 가듬는 것은 늘 정교한 균형이 필요한 작업 같습니다.
