# vibe 개발일지 #58 - AI SPEC 흐름 고도화와 설치 하네스 안정화 (10개 커밋)

**작업 기간**: 2026-07-29 ~ 2026-08-04

안녕하세요, Su입니다.  
"Agent = Model + Harness"라는 철학 아래, 개발자가 최소한의 품질을 보장받으며 편하게 vibe 코딩을 할 수 있도록 도구를 깎아나가고 있습니다.

지난 일주일 동안은 AI가 명세를 잡는 `/vibe.spec` 단계의 사용자 경험을 대폭 개선하고, 설치 환경에서 발생하는 치명적인 권한 엣지 케이스들을 뿌리 뽑는 작업을 진행했습니다.

## 📝 이번 기간 작업 내용

### 1. SPEC 워크플로우 UX 개선 (AI 명세화 고도화)
* **커버리지 스윕 역질문 2단 분리**: AI가 부족한 요구사항을 채우기 위해 질문할 때, 한꺼번에 몰아쳐서 묻지 않고 핵심 정책과 예외 케이스로 2단계 분리하도록 개편했습니다.
* **SPEC 승인 시점 세션 경계 도입**: 명세 확정 후 `/vibe.run`으로 넘어갈 때 이전 대화 맥락이 불필요하게 코드 생성에 영향을 주지 않도록 세션 경계를 명확히 그었습니다.
* **작업 효과**: AI 역질문 가독성 향상, 승인 단계 전환 간 프롬프트 오염률 **0%** 달성.

### 2. 설치 및 타겟 하네스 개편 (Install & Support)
* **sudo 전역 설치 자산 경로 버그 수정**: `sudo npm i -g` 사용 시 템플릿 자산이 `root` 홈 디렉터리로 들어가 일반 사용자가 접근하지 못하던 문제를 해결했습니다. (루트 해석 폴백 로직 구축)
* **Cursor 지원 제거 및 Codex 훅 기준 통일**: 하네스 집중도를 높이기 위해 Cursor 지원을 정돈하고, Codex CLI 연동 훅 판정 로직을 하네스 표준 기준으로 일원화했습니다.
* **작업 효과**: 전역 설치 환경 디버깅 로직 **3개 에지 케이스 방어**, 하네스 코드베이스 간결화.

### 3. CI/CD 및 테스트 인프라 견고화
* **pnpm SSOT 적용**: `packageManager` 필드를 단일 진실 출처(SSOT)로 삼아 CI와 로컬의 pnpm 버전 이중 선언 버그를 제거했습니다.
* **테스트 환경 격리 및 릴리스 파이프라인 단속**: npm 폴백 테스트를 실행 환경에서 독립시키고, CI 릴리스 빌드 시 main 브랜치 보호 규칙을 우회하던 잠재적 구멍과 타이틀 누락 문제를 해결했습니다.
* **작업 효과**: CI 재시도 횟수 감소, 릴리스 파이프라인 안전성 확보.

## 💡 작업 하이라이트

### 1. SPEC 역질문 2단 분리 & 세션 경계 (Session Boundary)
기존 `/vibe.spec` 단계에서는 AI 모델이 스펙의 모호한 점을 파악할 때 5~6개의 질문을 한 번에 던지곤 했습니다. 이로 인해 개발자가 답변을 작성하다 맥락을 놓치거나 AI가 답변을 오해하는 현상이 있었습니다.

이를 **[1차: 핵심 비즈니스 로직] → [2차: 예외 및 엣지 케이스]**의 2단계 스윕 구조로 변경했습니다.

```
[Before]
/vibe.spec 요청 ──> AI의 6개 질문 폭탄 ──> 맥락 혼선 및 코드 생성 품질 저하

[After]
/vibe.spec 요청 ──> 1차 질문(핵심 정책) ──> 2차 질문(예외 처리) ──> [SPEC 승인 / 세션 경계 형성] ──> /vibe.run
```

또한 SPEC이 승인되는 즉시 **세션 경계(Session Boundary)**를 형성하여, 실제 코드를 구현하는 `/vibe.run` 시점에는 정제된 `.spec` 문서만을 참조하게 만들어 AI 환각(Hallucination)을 대폭 줄였습니다.

### 2. `sudo npm i -g` 전역 설치 시 자산 미싱 문제 해결
개발자 환경은 생각보다 다양합니다. 일부 사용자분들이 `sudo npm i -g @su-record/vibe`로 설치할 경우, `process.env.HOME`이 `/root`로 평가되어 정작 실행은 일반 사용자 권한으로 할 때 설정 자산을 찾지 못하는 문제가 발생했습니다.

`SUDO_USER` 환경변수 분석 및 사용자 홈 디렉터리 탐색 폴백 메커니즘을 추가하여, 어떤 권한 명령어로 설치하더라도 원래 사용자의 환경에 안전하게 하네스 자산이 배치되도록 보완했습니다.
