# vica 개발일지: 터미널 검증에서 세션 유지 기반까지

10월 21일부터 23일까지의 최근 커밋 21개에서는 터미널 텍스트를 어떻게 해석하고 표시할지 검증하는 작업과, 세션을 유지하고 다시 연결하는 기반 작업을 함께 진행했습니다. Rust 기반 실험 환경을 마련하고 VT 엔진을 결정했으며, 이모지와 커서 위치처럼 출력에서 드러나는 문제를 다뤘습니다. 이번 기록은 커밋에 남은 구현과 검증 범위를 중심으로 정리했습니다. 측정값이 제공되지 않은 성능 항목은 개선 폭을 단정하지 않겠습니다.

## Rust 기반으로 터미널 검증 환경 정리

먼저 VT 개념 검증(PoC)의 범위와 설계 기준선을 문서에 남기고, 설계를 Rust 중심으로 전환했습니다. Rust VT 어댑터와 재현 가능한 PTY 실험 하네스를 추가해 터미널 동작을 반복해서 확인할 수 있는 기반도 마련했습니다.

검증 자료로는 실제 에이전트 실행 픽스처와 VT 측정 기록을 남겼습니다. 기록된 터미널 화면을 독립적인 엔진들과 비교하는 기능도 추가했습니다. 하나의 구현에서 화면이 그럴듯하게 보이는지만 확인하지 않고, 다른 엔진의 결과와 대조할 수 있게 한 작업입니다.

PoC 1~5차 기록을 문서에 통합하는 과정에서는 `alacritty_terminal`을 VT 엔진으로 확정했습니다. 원시 증거 자료의 형식을 보존하고 프로세스 정리 과정도 기록했습니다. 결론뿐 아니라 그 결론을 확인할 자료를 함께 남기는 데 신경 썼습니다.

## 문자 폭, 줄바꿈, 커서 위치 다듬기

화면 출력에서는 패널 너비 모드와 커서 위치를 보정한 텍스트 렌더링을 추가했습니다. 애플리케이션별 문자 폭도 측정해 기록했습니다. 같은 텍스트를 다루더라도 폭 계산과 커서 이동을 함께 확인해야 하는 영역이라, 렌더링 기능과 검증 작업을 나란히 진행했습니다.

리사이즈 처리에서는 어댑터를 거쳐 크기를 바꿨다가 되돌리는 과정에서 줄바꿈 대기 상태의 끝부분이 보존되도록 수정했습니다. 화면 크기 변경 전후에 텍스트 상태가 유지되는지 확인하는 데 초점을 맞춘 수정입니다.

이모지는 투영된 터미널 좌표를 사용해 텍스트를 보존하도록 손봤습니다. 이후 Orca에서 커서 보정과 투영된 이모지 출력을 확인한 기록을 남겼습니다. 다만 이모지 보존의 한계도 함께 문서화했습니다. Apple Terminal에서도 커서 동작을 확인하고 표시상의 제약을 기록했으므로, 모든 터미널에서 같은 결과를 보장한다고 말할 단계는 아닙니다.

## 빠른 출력은 선택적으로 도입

그래핌 단위 텍스트의 지연을 측정하고, 일반적인 그래핌 텍스트를 즉시 렌더링하는 옵션을 추가했습니다. 이 기능은 사용자가 선택해서 켜는 방식으로 도입했습니다.

선택적 텍스트 처리의 지연과 유니코드 경계에서의 한계도 별도로 기록했습니다. 즉시 렌더링 경로를 마련한 것과 모든 유니코드 입력을 문제없이 처리하는 것은 구분해야 합니다. 이번 커밋 목록만으로 구체적인 지연 감소 수치를 제시할 수는 없지만, 어떤 경로를 빠르게 처리할지와 어디까지 검증했는지를 나눠 살펴보는 작업은 진행했습니다.

## 세션 재연결과 데스크톱 기반 마련

세션 쪽에서는 독립적인 holder를 추가하고 재연결 기능과 경계가 정해진 프로토콜을 구현했습니다. 이어 `vicad` 릴레이에 레이아웃 영속 저장과 저널 복구를 추가했습니다. 화면을 그리는 부분에서 나아가 연결이 끊긴 뒤의 재접속, 레이아웃 보존, 기록을 통한 복구를 다루기 시작한 셈입니다.

23일에는 세션 단축키와 데스크톱 기반을 추가했습니다. 데스크톱 사용 경험을 완성했다기보다는, 세션 기능을 사용자가 조작할 수 있도록 연결하는 토대를 마련한 단계입니다. 원본 저장소 이력을 병합하는 정리 작업도 함께 진행했습니다.

이번 작업으로 VT 엔진 선택과 실험 기반은 구체화됐고, 세션 유지에 필요한 구성도 늘었습니다. 동시에 이모지 표시와 유니코드 경계의 제약은 검증 기록에 남아 있습니다. 구현된 기능과 확인된 한계를 함께 적어 두는 것이 이번 개발일지의 중요한 기준이었습니다.
